# Uninstall

> **Files:** `backend/internal/uninstall/`, `backend/internal/cli/uninstall.go`, `backend/internal/daemon/uninstall.go`, `backend/internal/compositor/manager/offline.go`, `backend/internal/secrets/secrets.go`, `backend/internal/fsx/lock.go`, `install.sh`, `packaging/aur/`, `qml/services/system/UninstallManager.qml`, `qml/components/methods/UninstallPlan.qml`, `qml/components/views/Settings/RemoveAxiomPanel.qml`, `qml/components/views/Settings/OutsideChangesCard.qml`
> **Related:** [Footprint ledger](footprint.md), [Session teardown](session-teardown.md), [Installation](../../installation.md), [Greeter install](../features/greeter-install.md), [Testing](../testing.md)

`axiom uninstall` takes axiom's footprint out of the user's home and session. It keeps what the user chooses to keep, never deletes a file that is the user's (a compositor config, a backup), lists what it leaves, and never runs anything as root.

### Steps (`uninstall.Run`, in order)
`uninstall.Build` says what it would do and changes nothing (`--dry-run`, the Settings dialog); each step of `Run` goes on when an item fails, the item landing in `Report.left`.
0. **Running.** A display whose `daemon.lock` is held (`fsx.Held`: a shared flock that creates and changes nothing) is in `Plan.Running`, and `Run` refuses with `axerr.Running`. `uninstall.Stop` (`--stop`) asks each daemon to quit (`Options.Shutdown`: `daemon.shutdown` on the display's socket) and waits up to 15 s for its `daemon.lock` and `guard.lock`.
1. **Greeter.** `<Root>/usr/share/axiom-greeter` or an `/etc/greetd/config.toml` naming it gives a `GreeterNote`: the login screen is system-wide and is removed first (Settings → Login screen, or the greeter-install command's uninstall as root).
2. **Managed release.** Per compositor whose config `takeover.Check` calls `ours`: `takeover.Release` with a fallback that has no start line (`manager.Offline.Takeover`: the writers' released text with empty autostart). `user/` stays.
3. **Ledger.** The backfill runs offline once (hookups and files apart, `Ledger.Backfill` and `BackfillFiles`; `daemon.OfflineInferred` finds the candidates from the built schema's `x-hookup`, the three writers' include and autostart targets, and the screen-share picker's shapes), then `Ledger.Undo` of every row (`Force` for `UndoInferred`, `IncludeSystem` for `RestoreSystem`). A row that ends `changed`, `failed` or `needsRunning`, or that wasn't picked, stays in the ledger and in the report.
4. **Remaining lines** (install.sh's, and any from before the ledger), in each compositor's main config and the portals' configs. Only a line equal to a canonical shape goes (`Canonical(kind, line)`, table-tested), alone or as a pair; any other line that starts axiom or names axiom's module is listed in `Manual` and never removed. The file is edited in place through its link, every other byte kept; one with nothing to remove isn't written.
5. **Session leftovers.** `session.Teardown` (no compositor steps, not the same instance, so no agent is started again) for each display with an unclean record or units and portal lines in the state record.
6. **Installed files.** `axiom-*.desktop` whose `Exec=` names a binary called `axiom`, `axiom.portal`, the portal's D-Bus service, and the folders they leave empty.
7. **Portal restart.** Only if step 3, 5 or 6 changed a portal file or line and the user said yes (`--no-portal-restart` says no): `session.RestartPortal` on the CLI's bus. Otherwise a note says to restart the session.
8. **Secrets.** `secrets.Count` (the Secret Service's `SearchItems`, object paths only: no value is ever read) and, unless kept, `secret-tool clear service axiom` (only through the bus the environment names).
9. **Folders.** Cache and runtime folder always; data and config unless kept; state: with the settings kept only `ui/takeover.json`, `session.json`, `session.lock`, `log/`, `dev/` and, once the ledger is empty, `footprint.json`, `footprint.lock` and `footprint/`; otherwise all of it but the ledger and `footprint/prior/` while rows remain. `secrets.json` goes unless secrets are kept. Every removal is `removeAxiomDir`: the path must be a folder called `axiom` directly under its XDG base, never `$HOME` or `/`.
10. **Backups** are listed with their size and never touched: `*.axiom-bak-*` (also the ledger rows'), `<config>.bak-<date>`, `*.axiom-backup-*` in the compositor dirs and `user/`, `user/.backups/`, a leftover `.axiom-claimed`.

### Canonical lines
`<B>` is any path or name whose basename is `axiom`, quoted (`'…'`) or not; whitespace around the line and a CRLF are allowed.
- Hyprland: `hl.on("hyprland.start", function() hl.exec_cmd("<B> run") end)` with or without ` -- axiom` (the AUR notes tell users to add it without), `local ok, axiom = pcall(dofile, "…/axiom/hyprland.lua")` and the `if ok then axiom.setup() end` right after it (never alone).
- sway: `exec <B> run`, `include …/axiom/sway.conf` (quoted or not). niri: `spawn-sh-at-startup "<B> run"`, `include "…/axiom/niri.kdl"`.
- xdph: `screencopy:custom_picker_binary = <B>`. xdpw: `chooser_type = dmenu` directly followed by `chooser_cmd = <B> screenshare-pick --for xdpw`, the pair only.

Near misses (`exec_always`, an extra argument, a comment, `axiom-foo`) stay and are listed.

### Answers
`uninstall.Answer(flags, counts, tty, ask)` is the whole decision table (`TestAnswerTable`). The questions, in order, each with its default: keep settings (yes), keep downloaded content (yes), keep saved passwords (yes; only with some), undo changes found without a record (yes; only with some), put back the default apps and input-method engines (no; only with some), restart the portal (yes; only when a portal file changed). `--yes` takes the defaults; `--purge-all` sets the first three to no and the fourth to yes and still asks about the system rows; `--restore-system` answers that one yes. No terminal and no `--yes`: refused (`run with --yes to take the defaults, or --dry-run to see the plan`). A hidden `--answers <file>` (the Settings button's) reads the answers as JSON instead.

### CLI, daemon and Settings
- `axiom uninstall [--dry-run] [--json] [--yes] [--purge-all] [--restore-system] [--stop] [--no-portal-restart]`. A partial run exits 0 with `left` in the report; a package gets "Remove the package too: sudo pacman -R axiom-shell".
- RPCs (shell only): `uninstall.plan {}` → `{plan, log, packaged}` (the plan leaves out the daemon's own display), `uninstall.start {answers}`. Start writes the answers to a 0600 file in `$XDG_RUNTIME_DIR` and spawns, detached (the session seams' `Spawn`), `bash <installTree>/install.sh --uninstall --yes --answers <file>` for a script install, else `<bin> uninstall --stop --yes --answers <file>`, its output in `$XDG_RUNTIME_DIR/axiom-uninstall.log` (a `sh -c 'exec >>"$0" 2>&1; exec "$@"'` with the arguments passed, never put in the script).
- Settings › General › Changes outside axiom: "Remove axiom from this system…" opens `RemoveAxiomPanel` in the card: the plan by step (`UninstallPlan.groups`), the switches (`UninstallPlan.questions`, the defaults above), a first step "Uninstall the login screen first" while the plan has a greeter note, and the line that axiom closes when it starts.
- `install.sh --uninstall` runs `axiom uninstall --stop` with `--yes`, `--dry-run`, `--purge-all`, `--restore-system` and `--answers` passed on, then (not for a package) removes the binary under `~/.local/bin` when `axiom version` names axiom and the install folder when it holds a tree, unless that is the clone the script runs from (a folder of its own choosing: the default install folder is always removed).
