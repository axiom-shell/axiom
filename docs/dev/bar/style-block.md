# Bar style block

> **Files:** `qml/components/views/Settings/BarStyleBlock.qml`, `qml/components/views/Settings/BarLookSample.qml`, `qml/components/reusable/ChoiceTiles.qml`, `qml/config/schema/definitions/widgets/BarStyle.yaml`, `qml/components/views/BarEditor/BarsPanel.qml`, `backend/internal/schema/yamlsrc/check.go`
> **Config:** `Bars.style` (a `BarStyle`), and each bar's own `style` (`Bars.items[].style`)
> **Related:** [Settings page](../core/settings-page.md), [Schema annotations](../core/schema-annotations.md), [Bar editor](bar-editor.md), [Shared UI pieces](../core/shared-ui-pieces.md)

Every BarStyle setting in one block: the settings page's wide Bar style card, and the bar editor's Style tab for the selected bar's style.

### Where it's used
- **Settings page:** `Bars.style` has `x-row: BarStyleBlock`, so the whole object is one row on a card of its own, in the page's columns like any other ([schema annotations](../core/schema-annotations.md) › `x-row`). Edits go through the page's form (`SettingsManager`), as the page's own rows' do.
- **Bar editor:** `BarsPanel` puts the block on the Style tab (the tab's `styles` in `BarsConfig.editorTabs` are the sections it shows), over the selected bar's look, each section shared or the bar's own ([bar editor](bar-editor.md)). A shared section collapses to its heading and a link to the settings page's card. An owned section where some keys are still null (a bar saved when the sections were grouped otherwise, `BarManager.ownsAllStyle` false) says "Some of these follow the shared style." beside a "Make all this bar's own" button: `setStyleOwned(keys, true)`, one undo step, keys already set keeping their values.

### What it holds
- **Sections** by BarStyle's `x-group`s, one under another: Look, the style's options, then Colors, Accents, Size and Shadow. Each is a `SchemaPropertiesForm` with `keepsPlace` that doesn't pair `x-beside` fields, so the tiles keep their room.
- **Folds (settings page):** Colors, Accents, Size and Shadow are folds (a `FoldHeader` over a `FoldingColumn`, their forms built only while open), shut until opened and kept as `<row path>:<section>` (`SettingsManager.isFoldOpen` / `setFoldOpen`). Shut, a fold shows the unsaved-edits dot while any of its settings has one. They're open in search results and the changed list (`form.listing`), and a jump to a setting in one (a link, `openSetting`) opens it: the block reads `pendingJump.setting`, as it's made and on `jumpRequested`. In the bar editor the sections don't fold (the Style tab narrows to its sections already).
- **A section not built** (shared in the editor, or a shut fold) hides its form's Loader too: an unloaded Loader keeps its last height, which left a gap where the form had been.
- **Look:** the rows marked `x-keepsPlace` (style, shape, grouping) stay where they are, greyed with why while they don't apply. Under them are the rows placed there (`x-placeUnder`: tab sides and ends under the shape, `SchemaLayout.placedUnder`), then the chosen style's own options in one panel ("Tinted options"). Which rows show is the schema's `x-showIf` alone; the block holds no style rules.
- **Tiles:** an enum with `x-control: tiles` draws as `ChoiceTiles`. An option whose `x-enumShowIf` fails is greyed, with its `x-tileHint` as the reason. Each tile's preview is a `BarLookSample` over the bar whose spacing it takes (on the settings page the first bar; in the editor the selected one).
- **No live widgets:** the block draws no bar widgets of its own (an edit would rebuild every one on every tile). The bar editor's board already shows the bar's widgets live.

### Drawing bars: one file
`BarLookSample.qml` is the only file of the block that imports bar drawing code. It draws each tile's sample: three boxes on a strip of bar (an icon, an icon with "42%", "12:30"), with one key set to the tile's value, so grouping, merged runs, powerline, tabs, split parts, separators and the gradient all read.
- **What it draws with:** the style with the tile's key set goes through `BarsConfig.enrichBarConfig`, so the sample bar's `barConfig.look` is `BarLook.resolve`'s: its shape and grouping as drawn, its traits, separators and gradient. The samples' caps and room are `BarRuns.segmentAt` on `BarRuns.context` (as `WidgetDecorations` places a section's), a tab's content shift is `BarTabs.tabShift`, and backgrounds are the drawing kit's `WidgetBackground` (`qs.components.bar.look`: a merged run's one, each box's with its split parts and gradient slice), its colors `WidgetLook`'s (Auto, so the gradient takes their place), with `SeparatorMark` between. On a box sit only a `StyledIcon` and a `StyledText`: no bar widget (nothing from `bar/widgets/`, no `BarWidgetHost`). Like every file outside `BarLook`, it reads the look's traits and resolved fields, never a `widgetStyle` name.
- **Cheap to build:** `ChoiceTiles` makes a tile's sample once, from the build queue (a frame's worth at a time), not in the frame the card appears.
- **Cheap on an edit:** `ChoiceTiles` sets `previewProperties` (`values`, `bar`) on a sample in place, only those that differ; everything in it is fixed (three samples, three backgrounds, two separator marks shown or hidden), so an edit only re-evaluates bindings.
  - The block hands the samples a copy of its values (`_sampleValues`): the settings draft changes its own object in place, so the same object would never compare different.
  - A sample works out its bar (`enrichBarConfig`) only when its style, bar or thickness changes, and keeps it only if it differs. As a binding it read the config readers, which every settings edit replaces, so every tile redrew on any edit on the page.
- **Changing the bar's drawing** changes only this file of the block: `BarStyleBlock`, `ChoiceTiles` and the forms draw nothing of bars.
- **The editor's tabs:** the block owns the Style tab's `styles` entries in `BarsConfig.editorTabs` (`[Look, Size, Colors, Accents, Shadow]`; Surface has none).
