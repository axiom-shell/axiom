> **Files:** `services/compositor/NiriManager.qml`, `backend/internal/daemon/compositorsocket.go`, `backend/internal/compositor/ipc/niri.go`, `backend/internal/compositor/ipc/niristreams.go`, `backend/internal/compositor/manager/niri.go`, `components/methods/NiriState.qml`, `tests/tst_NiriState.qml`, `backend/internal/compositor/kdl/`, `backend/internal/compositor/userconf/niri.go`, `backend/internal/compositor/binds/niri.go`, `backend/internal/compositor/actions/`, `services/compositor/CompositorManager.qml`, `scripts/dev/nested.sh`
> **Config:** `WindowLook.*`, `Input.*`, `Keybinds.binds`, `Monitors.items`, `Compositor.mode`, `WindowBehaviour.*`, `Compositor.niri.*`, `Session.*`, `Workspaces.*`
> **Related:** [The compositor](README.md), [Backend contract](contract.md), [Config modes](config-modes.md), [Sway backend](sway-backend.md), [Workspace strips](../hyprland/workspace-strips.md), [Recipe: compositor backend](../../recipes/compositor-backend.md)

`NiriManager` is `CompositorManager.backend` under niri (checked against niri 26.04): its state, workspaces, windows, outputs and keyboard, and, through the daemon's niri writer (`manager/niri.go`), all three config modes.

### Running it
- `scripts/dev/nested.sh niri` opens niri in a window with a second axiom in it, on scratch folders and its own D-Bus (as for sway: [sway backend](sway-backend.md) › Running it). `--managed` runs niri on the scratch config folder's niri config, the one managed mode takes over.
- Nested, niri's `Mod` is Alt (`mod-key-nested`); axiom writes `Super`, never `Mod`.
- Keep the nested window visible: while it isn't shown on the host (another workspace), niri's winit backend stops its event loop, its IPC times out and the axiom in it hangs on it, so an `axiom ipc` call into it never returns. It carries on once shown again. That's niri's behaviour, not axiom's; `nested.sh` says so as it starts niri.
- axiom's Restart shell and its one-per-display check end only the axioms on their own display: the nested and the live one never end each other ([services pattern](../core/services-pattern.md) › One axiom per display).
- Commands to the nested niri take its socket: `NIRI_SOCKET=$XDG_RUNTIME_DIR/niri.wayland-N.PID.sock niri msg …`. The guard refuses `output`, `quit` and `load-config-file` on the session's own niri (AGENTS.md › Never).

### IPC (through axiom)
- Quickshell has no niri module: the daemon talks to `$NIRI_SOCKET` for `NiriManager` (`daemon/compositorsocket.go`, shell only), never a process.
- niri answers one request per connection: `niri.request` (`{ request }` → the reply's `Ok`; an `Err` is a `refused` error, logged) opens one per call. `NiriManager._request(r, cb)` sends state requests at once; `_command(r, cb)` / `_action(a, cb)` queue, one at a time in order, so a chain split over several calls can't overtake itself. Requests are JSON objects (`{"Action":{"FocusWorkspace":{"reference":{"Index":3}}}}`), so names and indexes can't be confused.
- The event stream: `niri.watch` gives the asking connection a stream of its own (`ipc.NiriStreams`), pushed as `niri.started` when it (re)connects, then one `niri.event` per event as niri wrote it (one message each, not latest-wins: they're deltas). It opens with the full state, a `ConfigLoaded` included, which isn't a reload. A dropped or failed connect is tried again a second later, until the connection closes (there is no unwatch). `NiriManager` watches after every hello (a new connection to axiom has no stream); a second watch keeps the stream it has.

### State (`NiriState`, `tst_NiriState` on replies and an event stream captured in nested niri, `tests/fixtures/niri/`)
- niri's own objects are kept as they come (`NiriState.reduce`, event by event, immutable) and turned into the [shapes](contract.md#shapes) from there.
- **Outputs** aren't in the event stream: `Outputs` is requested at start, after workspace changes (debounced) and when Quickshell's screens change; a changed set of names is `outputsHotplugged`. `description` is make, model and serial. niri says nothing of layer surfaces' geometry, so `reserved` is what axiom's own layers reserve, from `LayerManager`'s arrangement (`LayerArrange.arrange`'s `reserved`, replaced in `NiriManager._reserved` only when it changes); another app's layers aren't counted.
- **Workspaces** belong to an output and are numbered there from 1 (`idx`), dynamically (the occupied ones and one empty after them). axiom's id for one is its output's block base + idx − 1 (`supports.outputWorkspaces`: every layout gets blocks, `standard` too, and nothing is remapped; [workspaces](../hyprland/workspaces.md)). Blocks are `blockSize` (100) long, not the Workspaces section's size: with `dynamicWorkspaces` the section's layout doesn't apply, and `CompositorManager.workspaceIds` are the ones niri has (a column per output). Workspaces past the block have no id (-1). A user's name for a workspace is its `name`.
- **Windows**: `id` is niri's, `focusRank` follows its focus timestamps (nothing persisted), `column`/`tile` its place in the strip (`WorkspaceGeometry.stripOrder` orders by them). niri 26.04 gives no position for a tiled window, only its size: a strip is laid out from its columns at the output's edge, without niri's scroll (`windowGeometry` off). Its `cover` (`windowCover`, for the dock's intellihide) is its column at the output's height while the strip fits on the output (niri doesn't scroll it then), else the whole output (the strip fills the view). A floating window is where niri says. A tiled window as big as its output is fullscreen.
- **Keyboard**: niri's full layout names, short codes from `Input.keyboard.layout` when axiom sets the keyboard, else the config's xkb layout, else the name (`KeyboardLayouts`).
- **Gaps** (`gapsOut`, a strip's layout): the gaps and struts of the config niri runs (`axiom compositor niri info --config <running config>`: axiom's module or the detached wrapper in it), read on `niri.started` and after every reload. The same read gives what `Mod` stands for (`modKey`, nested niri's `mod-key-nested`), for `builtInBinds`.
- `configReloaded` is a `ConfigLoaded` that didn't fail; `lastLoadFailed` says when one did (niri keeps the config before).

### Primitives
- `activateWindow` / `closeWindow`: `FocusWindow` / `CloseWindow` by id.
- `travel`: niri slides by itself, so only the last leg: `FocusMonitor` when given, then `FocusWorkspace`, `MoveWindowToWorkspace` (focus on) or `FocusWindow`. A workspace niri has is referred to by its id, else by its place on the output (niri goes to its last, empty one for a place past it).
- `focusOutput` / `moveWindowToOutput` (left and right steps): `FocusMonitor` / `MoveWindowToMonitor`, then `FocusMonitor` on the output focus should end on (the new one, or the old one for a silent move).
- `sendWindowToWorkspace`: `MoveWindowToWorkspace` with focus off. `scrollStrip`: `FocusColumnLeft`/`Right`. `applyRemap`: nothing.
- `placeWindow` (the overview's drop): onto the workspace, then beside the target's column (`MoveColumnToIndex`, the window focused first: niri moves the focused column), or into it (`ConsumeOrExpelWindowLeft`, at the column's end), or a floating window to its place (`MoveFloatingWindow`).
- `resizeWindow`: `SetWindowWidth`/`SetWindowHeight` by a fixed step; a floating window also moves.
- `withOutputDetails`: `Outputs` (`NiriState.outputDetails`). `applyOutputs`: axiom sends one `Output` request per change of each rule (`outputs.apply`, `render.NiriOutputRequests`: on/off, mode, scale, transform, position, VRR), disabled outputs last. A config reload keeps them unless the config's own `output` for that output changed (checked in niri 26.04), so the writer writes the matching profile into its files (as sway's does).
- `cycleKeyboardLayout`: `SwitchLayout`. `exitSession`: `Quit` without asking.
- The switcher: niri's binds can't tell axiom anything but through its IPC, so a switcher bind spawns `axiom ipc windowSwitcher next|previous`, and `SwitcherKeys` sees the modifier's release (`switcherRelease` off).
- X11 apps need `xwayland-satellite` on the PATH: niri starts it on demand and sets `DISPLAY` for what it spawns (axiom included, so apps axiom launches get it). Without it every X11 app (Steam) fails to open its display. It's a dependency of its own (`DependencyManager.tools`, install.sh's niri feature); the `Niri.xwayland` setting only turns it off.
- No `modifierTap`: niri has no release binds, so a bind on a modifier alone would fire on press, starting every combo. `render.NiriKey` leaves it out. Tapping Super can still reach niri as a spare key remapped outside it (keyd's `leftmeta = overload(meta, f13)`, then bind F13).
- `captureKeys` (`keyCapture`): nothing, niri having no empty mode: the key recorder's window inhibits niri's shortcuts while it records (`KeyRecorder`'s `ShortcutInhibitor`, keyboard-shortcuts-inhibit), so a combo niri binds reaches it and doesn't fire. Binds the user marked `allow-inhibiting=false` still fire.
- `toplevelFor`, `withCursorPos`, `withLayerRects`: null; `warpCursorToLayer`: nothing.

### The config writer (the daemon's `manager/niri.go`)
The [config modes](config-modes.md) on niri. niri takes nothing of axiom's layer at runtime (no runtime binds, rules or look), so everything is a file (`liveByFile`), and niri reloads a file it loads when it changes. The text comes from `render` (`niri.go`: its frozen cases, and `TestCompositorsReadTheFiles` has niri validate the files).
- **KDL** is written as nodes and serialized last (`render.KdlSerialize`, `merged`): niri refuses a file with two `layout` or `binds` nodes, or one key bound twice (compared without case). A float is written with a point (`render.real`: niri refuses `opacity 1`). Across includes the later definition wins, per field.
- **Validation**: every file is checked with `niri validate -c /dev/stdin` before it's written (`validate`, its `include`s left out); one niri refuses is left as it was and `problem` gives niri's error (`problems().Invalid`; the detached module's, also the file modes' fallback, as `problems().Runtime`, until niri takes it). A raw bind (`compositor: "niri"`) is the likely cause. With no `niri` on the daemon's `$PATH` the check is skipped (logged): niri checks the file itself when it loads it.
- **The user's binds** are read from their config (`axiom compositor niri binds`: the config niri started with, its includes followed, axiom's files left out, `Mod` as niri resolves it), again after every reload. Binds on keys the user binds are left out of the modules (`skippedKeys`, `render.RuntimeBinds`), so the user's win; the writer reads them before its first apply.
- **detached**: `$XDG_STATE_HOME/axiom/niri-detached-module.kdl` (the module) and `niri-detached.kdl`, a wrapper including the user's config and then the module, which axiom has niri load in place of the user's config (`LoadConfigFile`). niri watches the wrapper and what it includes, the user's files too, until it loads another config. Taking it out (`runtimeClear`) loads the user's config again. Whether the wrapper is loaded is kept in state (`niriDetached`, keyed by niri's socket: a new niri starts with its own config). It's also the fallback of the file modes while their file isn't loaded.
- **included**: `$XDG_STATE_HOME/axiom/niri.kdl`, included at the **end** of the user's config (`includeTarget` place `end`), so axiom's look wins; the user's binds still win, being left out of it. `checkLoaded`: the config niri started with reaches the module (`axiom compositor niri includes`). After writing, the writer has niri reload (`LoadConfigFile` without a path): niri only notices a file it loads.
- **managed**: `~/.config/niri/config.kdl` (`Paths.niriPath`): axiom's binds, then one `include optional=true` per `.kdl` file in `user/`, in name order (niri takes no globs; listed by the writer, again when the folder changes), then the rest of axiom's layer and the session (`environment`, `spawn-sh-at-startup`). The user's binds win over axiom's, axiom's look and settings over the user's.
  - The takeover (the binary's takeover, kind niri): stock is niri's default config (`/usr/share/doc/niri/default-config.kdl`, what niri writes when there's none), only backed up; a config of the user's is adopted as `user/00-previous.kdl` (dated backup beside the original), its nodes starting axiom or including its module commented out (`/* (axiom starts and loads itself now) */ /-`), relative includes made absolute. Like every managed takeover, it waits for the user's approval when the config is theirs ([config modes](config-modes.md) › Approving a takeover).
  - The adopted file's binds move into axiom (the binary's merge, kind niri): niri's actions where axiom has one (directions, workspaces by number or step, close, fullscreen, floating, center, tabbed columns as groups, column width ±10 %, quit), axiom's IPC calls, volume, brightness and media commands (`compositor/actions`, shared with sway's and Hyprland's merges), other spawns as `exec`, the rest `raw`. Moved binds are commented out with `/* (moved into axiom) */ /-`; a bind with options axiom's lack (`allow-inhibiting`) stays.
- **The look** (`render.NiriLookNodes`): borders as the border's and focus ring's colors; shape as a border of its width instead of the focus ring, every window's corners rounded and clipped; gaps as niri's gaps plus struts for the outer part; window blur as a window rule's `background-effect` and the global `blur`; the blur behind axiom's surfaces as layer rules setting only their `xray` (`render.NiriSurfaceBlurNodes`, from `render.SurfaceBlur`): what blurs is each window's own region ([translucency](../theming/translucency-blur.md) › niri: blur regions); the shadow as niri's (`render.GaussianShadow` matching axiom's); focused and unfocused opacity rules. No dim, no fullscreen opacity.
- **Input and options** by `x-niri` annotations ([schema annotations](../core/schema-annotations.md)): the Input fields while their part is on, `WindowBehaviour` and the `Niri` section (niri's own options: layout, the hot corner and overview, animations, CSD, the primary clipboard, xwayland-satellite) in managed mode, and the strip width (`Workspaces.stripColumnWidth` as `default-column-width`) in every mode. A flag can only be turned on (`issues.md`); a setting niri turns off with a flag (`animations { off }`) is an `offFlag`.
- **Outputs**: the matching monitor profile as `output` nodes, named by connector or by "Make Model Serial".

### `supports` for niri
`configModes`, `keybinds`, `monitors`, `switcher`, `strips`, `stripsAlways` (every output is a strip: the bar's strip, the overview's strip layout), `outputWorkspaces`, `dynamicWorkspaces`, `windowBorders`, `windowShape`, `windowRounding`, `windowGaps`, `windowBlur`, `windowShadow`, `windowOpacity`, `windowGroups` (tabbed columns), `windowCover`, `inputConfig`, `keyCapture`, `bindMerge`, `blur` and `blurRegion` (ext-background-effect: no alpha threshold, so each window sends what blurs). Not: `windowDim`, `blurThreshold`, `layerOrder`, `layerRestack` (a window moved to another layer keeps its place), `focusGrab`, `switcherRelease`, `cursorPos`, `cursorWarp`, `workspaceSlide`, `windowGeometry`, `outputCapture` (niri has only wlr-screencopy, so the screenshot picker's frame is grim's: [screenshots](../features/screenshots-recording.md)), `mouseBinds` (niri's own Mod + drag moves and resizes: `builtInBinds`, Mod as `niri info`'s `modKey` reads it), `namedSpecial`, `scratchpad`, `pseudoTile`, `splitToggle`, `pin`, `outputProfiles`, `monitorMirror`, `monitorColor`.
