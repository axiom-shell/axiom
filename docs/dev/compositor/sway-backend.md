# Sway backend

> **Files:** `services/compositor/SwayManager.qml`, `services/compositor/SwayIpcManager.qml`, `backend/internal/compositor/manager/sway.go`, `backend/internal/compositor/takeover/`, `backend/internal/compositor/binds/`, `backend/internal/compositor/userconf/sway.go`, `backend/internal/compositor/binds/sway.go`, `components/surfaces/switcher/SwitcherKeys.qml`, `components/methods/SwayState.qml`, `components/methods/SwayConf.qml`, `tests/tst_SwayState.qml`, `tests/tst_SwayConf.qml`, `services/compositor/CompositorManager.qml`, `scripts/dev/nested.sh`
> **Config:** `WindowLook.*`, `Input.*`, `Keybinds.binds`, `Monitors.items`, `Compositor.mode`, `WindowBehaviour.*`, `Compositor.sway.*`, `Session.*`
> **Related:** [The compositor](README.md), [Backend contract](contract.md), [Recipe: compositor backend](../../recipes/compositor-backend.md)

`SwayManager` is `CompositorManager.backend` under sway: the state, workspaces, windows, outputs, keyboard and special groups, and, through the daemon's sway writer (`manager/sway.go`), all three config modes (binds, the window look, input; managed also the shared `WindowBehaviour` options, the `Sway` section and the session).

### Running it
- `scripts/dev/nested.sh sway` (needs `sway`; `foot` for a terminal inside) opens sway in a window, with a second axiom in it:
  - on scratch folders
  - on its own D-Bus session
  - with idle and polkit off.
- `--copy-config` starts from your own config.
- `scripts/dev/nested.sh niri` does the same for niri ([niri backend](niri-backend.md)), `scripts/dev/nested.sh hyprland` for Hyprland (a second Hyprland in a window; commands to it take its signature: `hyprctl -i <n>` or `HYPRLAND_INSTANCE_SIGNATURE=…`, `hyprctl instances` lists them; not under sway, whose `xdg_wm_base` 5 is too old for Hyprland's Wayland backend, so run it from Hyprland or niri). `--managed` runs any of them on the scratch config folder's own config, the one managed mode takes over (axiom finds every compositor's config folder through `XDG_CONFIG_HOME`). `AXIOM_COMPOSITOR=none` in the nested launch runs axiom on no backend at all (the bar, the launcher and notifications; empty workspaces): the "unknown compositor" case to keep working.
- Logs: the newest `/run/user/$UID/quickshell/by-pid/<pid>/log.log` (`pgrep -af "qs -p"`: the one without `-d`).
- IPC: `axiom ipc …` (a nested one: its own binary with `--socket`, `scripts/dev/nested.sh`).
- Closing the window, or killing that compositor, ends both.

### X11 apps
- They need Xwayland, which Arch's sway only lists as optional (`xorg-xwayland`): it's a dependency of its own (`DependencyManager.tools`, install.sh's sway feature). `Sway.xwayland` says when sway starts it.

### SwayFX
- `SwayManager.fx`: SwayFX's `get_version` reply adds `sway_original_version` (its `variant` still says "sway"). Read at start, kept in the `PersistentProperties` across reloads of the shell; `ready` until then false; a sway that doesn't answer is asked again after 2 s, doubling up to a minute. `displayName` is "SwayFX", and greyed-out settings on plain sway say "SwayFX can." (`unsupportedHint`).

### State
Outputs and workspaces come live from Quickshell's `I3` module (as Hyprland's do from `Quickshell.Hyprland`); everything else from sway's replies, read through `swaymsg` (`SwayIpcManager`: `I3.dispatch` runs a command with no reply, and `I3` has no window tree, inputs or outputs in full). The replies become the [shapes](contract.md#shapes) in `SwayState` (`tst_SwayState`, on replies captured in nested sway under `tests/fixtures/sway/`).
- **Events**: an `I3IpcListener` on `window`, `workspace`, `output`, `input` and `binding`; any of them re-reads the tree (`get_tree`, debounced 50 ms).
  - `configReloaded`: a `workspace` event with change `reload`.
  - `outputsHotplugged`: an `output` event that changed the set of output names (sway sends `output` for any output change).
  - `keyboardLayoutChanged`: `input` with `xkb_layout` / `xkb_keymap`.
  - `windowFocused`: `window` with `focus`. `layersChanged`: never (sway reports no layer surfaces).
  - `binding`: axiom's own binds run `nop axiom <what> <verb> [argument]` (`switcher step|commit|cancel` → `switcherKey`; `special toggle|move <name>`), so a key costs no process.
- **windows** (`SwayState.tree`): the tree's leaves with a pid, under `nodes` and `floating_nodes`; the scratchpad's aren't listed until shown.
  - `id` = `String(con_id)`; `appId` = `app_id`, else the X11 `class`; `initialAppId` the same.
  - `workspaceId` = the workspace's `num` (-1 on a named one); `fullscreen`: `fullscreen_mode` > 0; `maximized`: never.
  - `hidden`: behind the front tab of a tabbed or stacked container.
  - geometry = `rect` (global, logical, with the title bar). Sway reports no change to the space layer surfaces reserve, so the tree is read again 1.5 s after start, and the overview and dock `refresh()` on opening.
  - `focusRank`: the windows focused since axiom started (a JSON list in `PersistentProperties`), then the order sway's per-container focus stacks give (`SwayState.ranked`).
- **outputs** (`SwayState.output`): `I3.monitors`; `description` = `make model serial` (the parts that aren't `Unknown`), sway's own identifier for an output; `reserved` = the output's rect minus its active workspace's (from the tree); `specialWorkspaceId` always 0.
- **workspaces** (`SwayState.workspace`): `I3.workspaces` with a number; `windowCount` from the tree.
- **gapsOut**: sway's IPC has no gaps. Read from its config with its includes (`axiom compositor sway-text`, `SwayState.configInfo`: `get_config` holds only the main file): outer plus inner per edge, as sway leaves both at the screen edge; read again on every reload.
- **Keyboard**: `get_inputs`, the first keyboard named like one. Sway names layouts in full ("English (US)"): their short names come from `Input.keyboard.layout` when axiom sets the keyboard, else the config's `xkb_layout`, else from the name (`SwayState.keyboard`).

### Primitives
- `activateWindow` / `closeWindow`: `[con_id=N] focus` / `kill`.
- `travel`: no slide (`workspaceSlide` off), so only the last leg: `focus output <name>` when given, then `workspace number N`, `move container to workspace number N; workspace number N`, or `[con_id=focusId] focus`. `travelingTo` stays -1.
- `sendWindowToWorkspace`: `move container to workspace number N`.
- `applyRemap`: Hyprland's detour through named workspaces (`axiom-remap-…`). Sway creates a workspace on the focused output, so each output is focused before its windows move.
- `placeWindow` (the overview's drop): next to a target, it marks the target (`axiom-drop`), splits it on the side's axis and moves the window to the mark, which puts it after the target; left and top then swap the two. With no target, onto the workspace; a floating window then moves to `floatAt` (`move absolute position`). Sway can't put the cursor back (`restore` unused).
- `resizeWindow`: `resize grow|shrink width|height N px`; a floating window also moves by (dx, dy).
- Special workspaces are groups of scratchpad windows (`namedSpecial`, once binds can reach them):
  - `moveToSpecial(name)`: marks the focused window `axiom-special-<name>-<id>` (unmarking any other group's, as a window is on one special workspace at a time) and moves it to the scratchpad. A mark's group is everything up to its last `-` (`SwayState.specialGroup`), so `a` and `a-b` are separate groups.
  - `toggleSpecial(name)`: shows the group's windows on the focused output (`scratchpad show`, floating), or hides them all (`move scratchpad`) when any is shown there (`SwayState.specialToggle`).
- `withOutputDetails`: `get_outputs` (`SwayState.outputDetails`; modes as `WxH@R.RRHz`). `applyOutputs`: one `output … enable mode … pos … scale … transform … adaptive_sync … render_bit_depth 8|10` command per rule (`SwayConf.outputCommands`), disabled ones last. No mirroring and no color settings.
- `cycleKeyboardLayout`: `input type:keyboard xkb_switch_layout next|prev`. `exitSession`: `exit`. `leaveSwitcher`: nothing (the switcher's binds enter no mode).
- `toplevelFor`: null. Quickshell can't capture a toplevel on sway (`ScreencopyView` calls it not captureable), so the overview shows icons.
- `withLayerRects`, `withCursorPos`: null; `warpCursorToLayer`, `scrollStrip`: nothing. `surfacesReady` is true at once.

### The config writer (the daemon's `manager/sway.go`)
The [config modes](config-modes.md) on sway; the text comes from `render` (`sway.go`), as Hyprland's does.
- **detached** (the writer's [runtime layer](config-modes.md#the-runtime-layer)): the binds and the live lines sent over sway's IPC, again after every reload, which drops them.
  - Sway can't list its binds, so the user's are read from their config files: `axiom compositor sway-text` (`compositor/userconf`) prints the config sway runs (the `-c` of the sway `$SWAYSOCK` names, else where sway looks) with its `include`s put in and axiom's own file left out, and `render.SwayConfigBinds` reads its `bindsym`/`bindcode` lines (with `$variables`, `mode` blocks and `bindsym { … }` blocks; a `bar { … }` block's are swaybar's clicks, left out) as BindKeys' entries. A key the user binds is skipped (`skippedKeys`). With no config found, axiom's binds still go on (the overlay stays reachable) and `problem` says so (`UnreadBinds`), shown in detached mode too.
  - The binds go as one command list, which sway ends at a bind it refuses (an unknown key); when one fails, each line is sent again alone, before the next list goes (else unbinds sent again would take out the binds just made), so one bad key costs only its own bind.
  - What it bound is kept as the commands unbinding it (`unbindsym …`, a `PersistentProperties`), sent first on the next apply.
- **included**: `$XDG_STATE_HOME/axiom/sway.conf`, which the user's config includes (`includeLines`: `include <path>`). `checkLoaded`: axiom's file (this or the managed config) defines a mode nothing else does (`render.SwayLoadedMode`, `axiom_layer`; `get_binding_modes`). The monitor profile for what's connected is written as `output` lines (`render.SwayOutputLines`, here and in the managed config): a sway reload sets the outputs as its config says, dropping what was set at runtime (checked in sway 1.12). Until `MonitorManager` has read the outputs (`outputsRead`), the file keeps the lines it has (`render.SwayFileOutputLines`), so starting the shell doesn't write them out and back. With no `outputProfiles`, `MonitorManager` also applies the profile at start, on every hotplug, and after a reload while no file of axiom's is loaded (detached).
- **managed** (the binary's takeover, kind sway, as Hyprland's): axiom writes `~/.config/sway/config` (`$XDG_CONFIG_HOME/sway/`, `Paths.swayPath`) with the module's lines, the `WindowBehaviour` and `Sway` options (`render.SwayOptionLines`, by `x-sway`) and the session, then `include ~/.config/sway/user/*`.
  - The takeover adopts the previous config as `user/00-previous.conf` (a dated backup beside the original), its lines starting axiom (`exec`/`exec_always`, not a bind or `set` calling its IPC, which the merge reads) or including the module commented out and its relative `include`s made absolute; sway's example config (`/etc/sway/config`) is only backed up. Release puts back what that claim set aside, as `.axiom-claimed` beside the config records it (an earlier claim's dated backup is never what a later one found).
  - The adopted file's binds move into axiom (the binary's merge, kind sway, the same verbs and JSON as Hyprland's): an action where one does the same (axiom's own IPC calls read back through `BindActions.ipcActions`), `exec`, else `raw` for sway; binds inside a `bindsym { … }` block stay (`block`); the moved lines are commented out (`# (moved into axiom)`, backups in `user/.backups/`, which `user/*` doesn't include). A moved bind repeats only where axiom's action does (`BindActions.actionFlags`) or as a raw command without `--no-repeat`: sway's implicit repeat isn't carried over, since the binds are shared with Hyprland.
  - Sway has no `env`: the session's environment (`render.SessionEnv`) goes to axiom's start line (`exec env … qs …`) and `dbus-update-activation-environment`. Apps sway's own binds start don't get it.
  - `exec` lines run once, at sway's start, not on a reload.
  - Like every managed takeover, it waits for the user's approval when the config is theirs ([config modes](config-modes.md) › Approving a takeover).
- **Reading the user's binds** in managed mode: `sway-text --skip-header` leaves out the managed config's own lines, so only `user/` counts.
- **Binds** (`render.SwayBindLine`): `bindsym --no-warn [--whole-window] [--locked] [--release] [--no-repeat] Mod4+Shift+q <command>`. A letter is lower case; `code:N` is a `bindcode`; the wheel is `button4`-`7` and mouse buttons `BTN_*`, over the whole window. Sway repeats a held bind unless told, Hyprland doesn't: every bind without `repeating` gets `--no-repeat`.
  - Actions: `focus`/`move <dir>`, `resize grow|shrink width|height N px`, `kill`, `fullscreen toggle`, `floating toggle`, `sticky toggle` (pin), `move position center`, `layout toggle split`, `exit`; IPC actions and apps as `exec`, quoted when sway would split or unquote them. Raw binds written for sway pass through.
  - **Quoting** (`SwayConf.quote`, `bindCommand`; checked against sway 1.12's parser). Sway takes unescaped quotes out and keeps a backslash before one, so a `"` can't be escaped: `quote` puts each run without a `"` in double quotes and each `"` in single ones. A config file keeps a bind's command as written but unescapes it (backslashes doubled). At runtime sway splits the command list at `;`/`,` before `bindsym` sees it (an unquoted `a, b` runs `b` at once) and strips the quotes, so the runtime layer sends any command holding those quoted whole (`bindLine(…, runtime)`). The merge (`compositor/binds/sway.go`) reads a user's command the way sway does (`storedCommand`, `execText`).
  - A modifier tapped on its own (`modifierTap`) is its keysym alone with `--release` (`bindsym --release Super_L`): sway fires it only when no other key came between, and not at all with `Mod4+` before it (checked in a headless sway 1.12).
  - **A release bind's press** (a tap's, `restartShell`'s, any bind with `release`; not a mouse button's) is bound too, to `nop` (`render.swayKeptPresses`), so sway keeps it: an input method (fcitx5) sends back the keys sway passes it through a virtual keyboard of its own, which sway matches binds on too, so without it the release fired once per keyboard: the tap after every combo (Super+Tab) and twice after a tap (seen on sway 1.12 with fcitx5), and likely the restart bind that started several axioms (reported 2026-10-18). The release still fires (checked in a headless sway 1.12 for a tap and a combo). It carries the bind's `--locked`, and is left out when another bind of axiom's uses that press.
  - `mouseDrag`/`mouseResize` are sway's `floating_modifier <mod> normal|inverse`: one modifier with the left or right button, from the drag bind (else the resize bind). A mouse bind on several modifiers or another button isn't complete on sway (`isComplete`); a resize bind on a different modifier from the drag's can't be had too.
  - Strips, pseudotiling and groups aren't sway's: those binds are left out.
  - axiom's own: the switcher (`nop axiom switcher step ±1`) and special groups (`nop axiom special toggle|move <name>`), which `SwayManager` reads from `binding` events.
- **The look** (`render.SwayLookLines`): `client.focused|focused_inactive|unfocused` from the border colors (title text black or white, whichever reads), `default_border pixel <width>`, `gaps inner|outer`. Sent live, they also apply to what's open (`[all] border pixel`, `gaps … all set`), and `gapsOut` follows the gaps until the next reload (`SwayManager.setLiveLook`).
- **SwayFX's part** (`render.SwayFxLines`, with `fx`): `corner_radius`, the blur (`blur`, `blur_radius` capped at 10, `blur_passes`, `blur_xray`, `blur_noise`, `blur_contrast`), `shadows`/`shadow_blur_radius`/`shadow_offset`/`shadow_color` (its alpha the spec's; matching axiom's, the radius and alpha `render.GaussianShadow` fits), `default_dim_inactive`, and per axiom layer in `LayerStack.blurSurfaces`/`blurBackdrops`/`blurOverOverlay` a `layer_effects "axiom-…" "blur …; blur_xray …; blur_ignore_transparent enable"` (namespaces match exactly; each effect merges into the layer's). These set SwayFX's globals. Sent without criteria at runtime, `blur`/`shadows`/`dim_inactive` reach only the focused window (`config->handler_context.container`; checked in SwayFX 0.6's source), and `default_dim_inactive`/`corner_radius` only windows opened later, so a window's blur, shadows and dim are set a window at a time instead (below). **Only ever sent at runtime** (the sway writer's `liveLines`), never written into a file: plain sway would refuse the lines, so switching back keeps a config it loads. A reload drops them, and the file modes evaluate them again after it. `blur_ignore_transparent` leaves out only fully clear pixels (scenefx 0.5's `tex.frag`), so the chrome's shadows are cast from windows of their own that aren't blurred (`axiom-shadows`, `axiom-shadows-overlay`; no `blurThreshold`); layer popups (tooltips, menus) aren't blurred by `layer_effects`.
- **Per-window look** (`SwayManager`, from `SwayState.windowCommands`): sway has no focused/unfocused opacity, so each window's (`[con_id=N] opacity`) is set as focus moves (both sways). On SwayFX each window's `blur` (`look.blur.windows`), `shadows` and `dim_inactive` go the same way, so windows opened later get them too. Only what changes is sent, one command list per window. Opacity off puts every window back to 1, dim off back to the config's `default_dim_inactive`; blur and shadows are left to the reload that turns their part off. What's set is kept in the `PersistentProperties`; after a reload of the shell nothing changes until the look is set again. A config reload leaves opacity and dim alone but resets blur and shadows, which the look sent after it sets again.
- **The input** (`SwayConf.inputLines`): Input's fields by their `x-sway` command ([schema annotations](../core/schema-annotations.md)); `xkb_numlock` only in the file (`x-swayConfigOnly`). The cursor: `seat * xcursor_theme <theme> <size>`.
- **Key capture** (`keyCapture`): a `mode "axiom_record_<n>"` with one unreachable bind, defined at runtime, and a sleeping `swaymsg` that leaves it after 30 s should the shell die (each capture names its mode anew, so an earlier one's sleeper can't end it).
- **Command order**: `SwayIpcManager.dispatch` (no reply) goes out at once over `I3.dispatch` only while no `command()` is still running, else after it, so commands keep the order they were sent in (a recorder turned off just after on can't leave sway in its mode).
- **The switcher**: sway fires a `--release` bind only when no other key came between, so it can't tell the modifier's release after Tab. Without `switcherRelease`, `SwitcherKeys` (an invisible pixel taking the keyboard while the switcher is open) picks on the release, cancels on Escape. A very quick tap may release before it has the keyboard (fine at 20 ms in nested sway).

### `supports` for sway
`configModes`, `keybinds`, `monitors`, `switcher`, `windowGeometry`, `outputCapture` (ext-image-copy-capture), `layerFrameSync`, `windowBorders`, `windowShape` (the border width; the radius too on SwayFX), `windowGaps`, `windowOpacity` (emulated), `inputConfig`, `keyCapture`, `modifierTap`, `bindMerge` (the list and conflicts; merging the user's binds in comes with managed), `scratchpad`, `namedSpecial`, `mouseBinds`, `splitToggle`, `pin`. SwayFX adds `windowRounding`, `windowBlur`, `blur`, `windowShadow`, `windowDim`. Not: `switcherRelease`, `outputProfiles`, `pseudoTile`, `windowGroups`, `monitorColor`, `monitorMirror`, `strips`, `focusGrab`, `layerOrder`, `cursorPos`, `cursorWarp`, `workspaceSlide`.

### Open questions (check in the nested session)
- **Click outside.** Without `focusGrab`, a grabbing surface takes the keyboard exclusively and each screen's backdrop window catches the click outside it ([README](README.md) › Focus grab). Typing into the launcher opened by IPC works in nested sway; check by hand that bar popouts with text fields, the launcher, the overlay and the power menu close on an outside click.
- **Layer stacking.** With no `layerOrder`, `LayerManager` maps the stacked surfaces in `LayerStack` order ([layer arrangement](layer-arrangement.md)); checked in nested sway for a solid and a floating-pills bar against the border, and an integrated edge menu.
- **Workspace blocks.** `workspace number N` creates N on the focused output, and the facade focuses the output first. Checked on two nested outputs (`swaymsg create_output`); the perMonitor and grid blocks and a live remap still need a look.
- **Focus follows the mouse.** In nested sway the pointer over the nested window refocuses the output under it after a command; read state with that in mind.
- **The greeter** runs on its own sway when sway is installed (`greeter-session.sh`, [greeter runtime](../features/greeter-runtime.md)): `GreetdManager` applies the monitors and input there through `CompositorManager.applyOutputs` / `applyInput`.
