# Translation (i18n)

> **Files:** `qml/config/I18n.qml`, `qml/config/i18n/<code>.json`, `qml/config/i18n/template/language.json`, `scripts/check_i18n.py`, `.githooks/pre-commit`, `qml/components/forms/FieldHeader.qml`, `qml/components/forms/SchemaComboBox.qml`
> **Config:** `General.language`
> **Related:** [Schema annotations](schema-annotations.md), [Settings page](settings-page.md)

How user-visible text is translated. The rules themselves are in CLAUDE.md › Theme, animation, text; this doc adds the mechanics.

### Source language
- `General.language` picks the language.
- English is the source: user-visible text is written in English, inline, as `I18n.tr("Text")`.
- **Dynamic values** use placeholders, so the whole sentence stays one key: `I18n.tr("{0} updates", count)`. Never template-string sentences.

### Dates and times
- Through `I18n.formatDate(date, format)`, never `Qt.formatDateTime`, so day and month names follow the language (`check_structure` refuses it; screenshot file names, kept out of the language so no locale changes their digits, are marked `// allowed: <reason>`).
- Named formats: `I18n.dateFormat("longDate" | "mediumDate" | "shortDate" | "monthYear" | "fullDate" | "dateTime" | "time24" | "time12" | "clock24" | "clock24s" | "clock12" | "clock12s")` (the `clock*` ones are the bar clock's, `s` with seconds). A language overrides any of them in its `_meta.formats`; the rest stay English's (`I18n._formats`).
- `I18n.formatRelative(epochMs)` ("now", "5m", "3h", "2d"), `I18n.meridiem(date)` (AM/PM in the language) and `I18n.formatHour(date, use24Hour, padded)` (the hour alone: Qt's `h` is 12-hour only beside an `AP` field) for the rest.

### Schema forms translate themselves
- The schema-driven form widgets (`qml/components/forms/`) translate their own text: labels and help through `FieldHeader`, dropdown options in `SchemaComboBox` (an `x-enumLabels` label, else the value), and `SchemaField`'s notes, empty labels (`x-emptyLabel`) and why a tile or a field kept in place is greyed (`x-tileHint`). The settings page translates the `x-categories` names and card titles.
- Callers pass English; schema titles and descriptions need no code.

### Languages
- Adding a language = adding `qml/config/i18n/<code>.json`:
  `{"_meta": {"name", "locale", "formats"}, "strings": {english: translation}}`.
- It then appears in the language dropdown (`x-options: "languages"`).
- Missing entries fall back to English.
- **The template**, `qml/config/i18n/template/language.json`, is what a new language is copied from: every key with an empty translation (sorted), and `_meta` with an empty name and locale plus English's date formats (read from `I18n._formats`). `check_i18n.py` generates it: `--fill`, `--prune` and `--format` rewrite it, and a plain run fails when it's stale. It sits in a subfolder, so `I18n`'s scan (`showDirs: false`) and the checker's per-language pass don't take it for a language.
- The active dictionary reloads live when edited. Write it atomically (temp file + rename), since a half-written file gets read.

### Checking coverage
- **The pre-commit hook** (`.githooks/pre-commit`) runs `check_i18n.py --fill --prune` on the index whenever a commit touches QML, the schema (`qml/config/schema/`, `backend/internal/schema/` or a widget, module or view's `schema.yaml`), `qml/config/i18n/` or the checker, and stages the template and each language file it changed: new keys added empty, keys no `I18n.tr()` or schema string uses any more dropped (a reworded string's old translation goes with it). A language file with unstaged edits stops the commit instead (rewriting it from the index would drop them). So nobody runs `--fill` or `--prune` by hand. Agents never translate (CLAUDE.md › Never); the empty entries are for the maintainer and human contributors.
- `scripts/check_i18n.py` on its own lists missing (empty), absent and unused entries, and a file not in the canonical format (`json.dumps(indent=2, ensure_ascii=False)`; another indent rewrites every line in a diff). It fails (in CI too, through `check_all.sh`) on everything but an empty entry: the rest is what the hook fixes, so a commit made without it fails.
  - `--fill` adds the missing ones, empty (they still count as missing until translated).
  - `--prune` removes unused ones; `--format` only rewrites. All three write atomically, and all three rewrite the template.
  - `--untranslated` finds UI literals not wrapped in `tr()`, and a `tr()` of a runtime value in a file that declares none of its keys.
- Keys chosen only at runtime (e.g. `I18n.tr(form.shape)`) must be declared in a comment next to the call, as `I18n.tr("square") ...`, so the checker sees them; a file whose keys come from its callers or the schema says so instead (`// i18n: keys from callers`).
- Leave developer-facing strings in English: logs, validation errors, migration notes.
