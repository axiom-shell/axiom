# Translation (i18n)

> **Files:** `config/I18n.qml`, `config/i18n/<code>.json`, `config/i18n/template/language.json`, `scripts/check_i18n.py`
> **Config:** `General.language`
> **Related:** [Schema annotations](schema-annotations.md), [Settings page](settings-page.md)

How user-visible text is translated. The rules themselves are in AGENTS.md › Translation; this doc adds the mechanics.

### Source language
- `General.language` picks the language.
- English is the source: user-visible text is written in English, inline, as `I18n.tr("Text")`.
- **Dynamic values** use placeholders, so the whole sentence stays one key: `I18n.tr("{0} updates", count)`. Never template-string sentences.

### Dates and times
- Through `I18n.formatDate(date, format)`, never `Qt.formatDateTime`, so day and month names follow the language.
- Named formats: `I18n.dateFormat("longDate" | "mediumDate" | "shortDate" | "monthYear" | "fullDate" | "dateTime" | "time24" | "time12")`.

### Schema forms translate themselves
- The generic `Schema*` form widgets translate their own `label` / `title` / `description` and dropdown option labels.
- Callers pass English; schema titles and descriptions need no code.

### Languages
- Adding a language = adding `config/i18n/<code>.json`:
  `{"_meta": {"name", "locale", "formats"}, "strings": {english: translation}}`.
- It then appears in the language dropdown (`x-options: "languages"`).
- Missing entries fall back to English.
- **The template**, `config/i18n/template/language.json`, is what a new language is copied from: every key with an empty translation (sorted), and `_meta` with an empty name and locale plus English's date formats (read from `I18n._formats`). `check_i18n.py` generates it: `--fill`, `--prune` and `--format` rewrite it, and a plain run fails when it's stale. It sits in a subfolder, so `I18n`'s scan (`showDirs: false`) and the checker's per-language pass don't take it for a language.
- The active dictionary reloads live when edited. Write it atomically (temp file + rename), since a half-written file gets read.

### Checking coverage
- **The pre-commit hook** (`.githooks/pre-commit`) runs `check_i18n.py --fill --prune` on the index whenever a commit touches QML, the schema (`config/schema/` or a widget, module or view's `schema.yaml`), `config/i18n/` or the checker, and stages the template and each language file it changed: new keys added empty, keys no `I18n.tr()` or schema string uses any more dropped (a reworded string's old translation goes with it). A language file with unstaged edits stops the commit instead (rewriting it from the index would drop them). So nobody runs `--fill` or `--prune` by hand. Agents never translate (AGENTS.md › Checks); the empty entries are for the maintainer and human contributors.
- `scripts/check_i18n.py` on its own lists missing (empty or absent) and unused entries, and a file not in the canonical format (`json.dumps(indent=2, ensure_ascii=False)`; another indent rewrites every line in a diff). It fails (in CI too, through `check_all.sh`) on everything but an empty entry: the rest is what the hook fixes, so a commit made without it fails.
  - `--fill` adds the missing ones, empty (they still count as missing until translated).
  - `--prune` removes unused ones; `--format` only rewrites. All three write atomically, and all three rewrite the template.
  - `--untranslated` finds UI literals not wrapped in `tr()`.
- Keys chosen only at runtime (e.g. `I18n.tr(form.shape)`) must be declared in a comment next to the call, as `I18n.tr("square") ...`, so the checker sees them.
- Leave developer-facing strings in English: logs, validation errors, migration notes.
