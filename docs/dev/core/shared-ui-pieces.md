# Shared UI pieces

> **Files:** `qml/components/reusable/`, `qml/components/forms/`, `qml/components/content/parts/`, `qml/components/views/base/`, `qml/components/methods/Utils.qml`, `qml/components/methods/Search.qml`, `qml/components/views/Settings/EntryListCard.qml`, `qml/components/views/Settings/ScreenSpotPicker.qml`, `qml/components/views/Settings/PlaceIntro.qml`
> **Config:** none
> **Related:** [Editors pattern](editors-pattern.md), [Content roots](../overlay/content-roots.md), [Writing modules](../overlay/writing-modules.md), [Popout surface context](../popouts/surface-context.md), [Translucency and blur](../theming/translucency-blur.md)

An index of reusable pieces. Reach for one of these before drawing your own; when a pattern appears a second time, it becomes one of these. Every file in `reusable/`, `forms/`, `content/parts/` and `views/base/` is named here or in the docs it links to (`scripts/check_docs.py` checks): add a line when you add a piece.

### Sizes
Colours, text and icon sizes: `Style` ([style](style.md)).

Everything outside the bars follows the Interface scale and Density through `Widget` (`qml/config/Widget.qml`); a size written as a number doesn't, and `scripts/check_sizes.py` fails on one of 3 px or more, set alone or added, subtracted or chosen in a size's expression (`Widget.height - 4` is `Widget.height - Widget.px(4)`; factors like `* 2` and grid units like `span(8)` are fine).

| What | Use |
|---|---|
| A gap: 3–6 / 8 / 12–14 px | `Widget.spacing` / `Widget.spacing * 2` / `Widget.padding` |
| Inner margins of a row, field or dropdown (6–8 px) | `Widget.smallPadding` |
| A panel's or card's padding (10–22 px) | `Widget.padding` (× 2 for 18–22) |
| A control's height (fields, switches, tabs) | `Widget.height` (or a fixed share of it); it, `smallHeight` and `iconButton` grow with the font size so a control always holds a line of its text (`StyleTokens.controlHeight`) |
| A square icon button | `Widget.iconButton` (`StyledIconButton`'s default `size`) |
| A chip, pill or small button (18–22 px) | `Widget.smallHeight` |
| A compact control beside a full one (a list row's action, a lane's tool button) | `Widget.compactHeight` |
| A switch's or segmented row's track, a chip or button sized to sit in a full-height line | `Widget.slimHeight` (`height` less 4 px at scale) |
| A draggable or listed chip's row (bar lanes, grid drag chips, keybind rows) | `Style.chipRowHeight` |
| A text or icon size | a `role` / `size` (`Style.textRole`, `Style.iconSize`) |
| A fitted text or icon size only | `Appearance.fontSizeBy(n)` for n px more or less (never `fontSize ± n`: the offset wouldn't scale), on a line marked `// fitted:` |
| A width, an avatar, a dot, a thin bar | `Widget.px(n)` (the Interface scale only) |
| A hairline (0–2 px, `border.width`) | the number |
| Measured against the screen, a measuring font, a placeholder or stand-in, a layout weight | the number, marked `// fixed px: <reason>` |

A size setting in px outside the bars (`Launcher.width`, `Notifications.width`, tile sizes, `Popouts.padding`) is scaled in its reader (`Widget.px(_c.width)`), so it follows the Interface scale too; gaps that line up with the compositor's (the toasts' `gap`) stay as set, and hover strips are a fixed `ScreenEdge.triggerSize` deep.

Bars size their own widgets (`BarsConfig.enrichBarConfig`) and never use these: a shared piece the bar uses takes its size from the bar (`CountBadge.textSize`, the bar's `iconGap`).

### Style pieces (`reusable/`)
What to reach for ([style](style.md) › Pieces); every one reads `Style` and takes no colour or size from its caller.
- `Surface`: the one way to draw a box. A `Rectangle` with a `tone` (`page`, `sunken`, `surface`, `raised`, `highest`, `accent`, a container), `outlined` (a hairline), `solid` (opaque in a Popup), `shadowed` (a `RectangularShadow` under it, never a layer: a clipping parent cuts the shadow) and `ink`, the colours that read on it. Text and icons inside inherit the ink: put content inside the Surface it sits on. It publishes `drawnZoom`, the zoom its content is drawn at.
- `StateLayer`: the hover, press and drag tint, first in the control, under its content; `onAccent` for a solid fill, `bleed` to reach past the sides (`leftBleed` the left alone; the parent must not clip). It rounds as its parent (`radius`), else `Style.radiusInner`; an inset use sets `radius`; `squareBottom` squares the bottom corners (a header band over a body).
- `StyledScrollView`'s `bleed`: room past the content on the left and right, inside the clip, for a row's tint; the host sets it outside by `-bleed` (`Style.rowBleed` for FormRows). While `bleed > 0` the ScrollView's Flickable does not clip (it would clip at the padding, cutting the bleed) and the view's own clip does, so such a host keeps its top and bottom padding at 0 (or the focus ring's width, as ToolPane's pinned list).
- `FoldChevron` (`open`, `hot`): the fold's chevron, used by `FoldHeader`. `DropMark` (`vertical`): the accent line showing where a drop lands, placed by its caller (`FlowDropTarget`). `ActionTone`: the colours an `ActionTile` / `ActionPill` take from `activeTone`, `active` and `hot`. `TipIcon`'s `tipWidth` caps its tooltip's width and `hovered` reports the hover. `RingOutline` (`ringColor`, `gap`): the OSD outline, an outer ring and a page-colour line inside it (`OSDTile`, `OSDLevelBar`).  `TruncationTip` (`target`, `text`, `hovered`, `maxWidth`): the full text of an elided label as a tooltip (`ListEntryRow`, `DragChip`, `InspectorHeader`, `CardHeader`).
- `FocusRing`: the keyboard focus outline outside its parent; bind `shown` to a Tab or arrow focus, only on controls that take keyboard focus; `squareBottom` squares its bottom corners as `StateLayer`'s.
- `Skeleton`: the loading placeholder, `lines` bars of a text `role`'s height (the last `lastLineShare` wide), an optional `avatar`, a shimmer gated on `Appearance.animations`. Spinners stay for actions in progress.
- `MotionListView`: a `ListView` whose rows fade and slide in, fade out and glide aside; the first fill does not animate unless `animateFirstFill`.
- `MenuRow`: one menu, dropdown or picker row: `icon` or `image`, `text`, `trailing`, `chevron`, `checked`, `current` (accent container), `lit` (keyboard highlight), `danger`, `dense` (context and edge menus), a `leading` slot, `hovered`, signal `activated`. It sits on its menu's Surface and inherits the ink.
- `SegmentTrack` (private to `SegmentRow`): the track Surface and sliding thumb of `count` equal segments, the thumb under `index`.

### Text and structure (`reusable/`)
- `StyledText` / `StyledIcon`: `role` (`micro` to `display`) and `tone` choose size, weight and colour from `Style`; the colour is the nearest enclosing Surface's ink. `overflow` (`line`, `wrap`, `none`; the role's default when empty) and `maxLines` replace `wrapMode`/`elide`/`maximumLineCount` (R14); never `font.bold` (set `font.weight`). `renderType` is native at rest and distance field under a declared `contentZoom`. `textColor` and `textSize` stay for a state or a fitted size. `StyledIcon` takes `size` (`xs` to `xl`, default `sm`) and never wraps or elides.
- `StyledLabel`: a `StyledText` centred on its letters (its `TextBandPadding`), the text of every label placed by its box: beside an icon, in a pill, chip, button, tab, menu or list row, a title and status stacked beside an icon (centred as a block). Its size is a `StyledText`'s; `bandOffset` is its `TextBandPadding`'s `offset`. The shared pieces' labels are ones (`StyledTextButton`, `DragChip`, `ActionPill`, `StatusChip`, `StyledTabButton`, `StyledToggle`, `MenuList`, `KeyHint`, `ListEntryRow`, `TypePickerPopup`, `StyledComboEntry`, `InspectorHeader`, `StyledVolumeBar`'s percentage, `StyledToolTip`, …). A paragraph, a heading over a column, a big display figure (the clock) and text sharing a line with a field's typed text (a unit, a preview) stay `StyledText`: the field's text isn't moved, and a pair on one baseline (`FigureValue`) keeps it.
- `TextBandPadding`: the `topPadding` / `bottomPadding` that centre a Text on its letters (`methods/TextBand`) instead of its line box, so a Text placed by its box (centred in a cell, beside an icon, turned along a vertical bar) centres what reads. A line box holds the descent and an accent's room, so centred as a box all-lowercase text sits a pixel or two low beside an icon. It moves the lines inside the box and keeps the box's size (one side's padding is the other's negative), so no layout grows or shrinks for it; over several lines it centres them as a block. The lines move by whole pixels (a baseline is drawn on one, so a fraction would round either way with where the box lands); the half pixel left is its `offset`, which a host placing the Text itself takes off before rounding (`IconTextRow`'s label, the ticker's and the Workspaces cells' `verticalCenterOffset`), as a `StyledLabel` centred by anchors does by itself. The band is the font's, not the string's ink, so a label doesn't move with its descenders or capitals (only, by half the bands' difference, when lowercase comes or goes): the x-height for text with a lowercase letter in it (its middle is also the middle of ascenders over descenders, so "gaming", "Gaming" and "vpn.batk.me" sit alike), a digit's height for text without (numbers, capitals). It's handed the Text (`label`) and reads its first line's ascent off it as laid out (`TextBand.lineAscent`, from its `baselineOffset`): a fallback font's taller ascent (CJK, emoji) moves the baseline down only on the line it's on and not once elided away, and Qt lays some fallback glyphs (Arabic, an icon font's) on the primary font's ascent, so measuring the text instead is off in those. It reads it when the Text is complete (so it's padded from its first frame), then once each layout is done (`Qt.callLater` on the Text's layout and font signals, which fire only when the line's ascent or height or the font changes, not on each new text), and takes the font's bands with it, so a new font's bands never meet the old font's line: a binding through `baselineOffset` loops, as it holds the padding, and read inside the layout's own signals the line's height is still the old one. Each one keeps two `TextMetrics` (the bands, re-measured only when the font changes), so it goes on labels, not every Text. `StyledLabel` carries one; on a bar, `IconTextRow`'s label (not upright under its icon), `ValueGraphic`'s ticker and the Workspaces cells' names and labels (a plain lead and its text on one band) bind one themselves, and the cells' numbers are `StyledLabel`s.
- `SpinningIcon`: a `StyledIcon` that turns while `spinning` (gated on `Appearance.animations`), upright again when it stops: the busy mark (the radio menus' scan, the dev build in the DevMode widget and the Settings banner).
- `SlashedIcon`: an icon struck through while `slashed`, one drawn slash (top left to bottom right, Material's direction) over a `cutout` line in what it sits on. Every off state is the base icon slashed, never an icon's own `_off` form, so they all look the same (the OSD's bars and status icons).
- `SectionHeading`: `title`-role title (text colour, hidden when empty) + muted `caption` description, folded past three lines; the onboarding's pages use it for their section titles. `icon` puts an accent `md` glyph before the title and `rule` fills the rest of the title's line with a `StyledSeparator` (a heading over a block).
- `ClampedText`: muted help text cut to `maxLines` (3) with a More / Less link, built and shown only when it's longer. Field and card descriptions use it.
- `FoldHeader` / `FoldingCard`: the whole header is the fold trigger, a button (a `Pressable`, objectName `foldTrigger`: tint on hover and press, ring on Tab focus, Space/Enter fold, a Tab stop while `foldable`). `FoldHeader`'s `reach*` (`reachLeft`/`Right`/`Top`/`Bottom`) say how far the trigger reaches past the header (the host's padding), `radius` is the shape it tints in and `squareBottom` squares the bottom corners. `FoldingCard` sets them: folded, the trigger is the whole card in its rounded shape; open, the header band down to the body's first row, bottom square, the `headerExtras` drawn over it taking their own clicks. `status` and `statusTone` put a `StatusChip` centred on the chevron, kept while folded (a settings card's `x-intro` supplies them).
- `FieldGroup`: the settings page's card, for an editor's group of fields (a `FoldingCard`, tone `surface`, outlined, on any host): the header (title, description, chevron; `headerExtras` after the chevron, hidden while folded) at the top, then the rows inside the card's padding (`Style.space3`). Rows stack with no gap (`bodySpacing: 0`; a row pads itself); a non-row child that follows another takes `Layout.topMargin: Style.space2`; the column it sits in spaces cards by `Style.cardGap`. Rows indent only under the row their value depends on (`RowTree`); extra options are a fold row (`FoldFormRow`) inside the card, as the login screen card's Settings fold. The fold is the card's own `collapsed` (open whenever the card is built, never saved); `foldable: false` for a card that must stay open (the layouts editor's "Can't save yet", the settings page's ten hand-built cards, which also set `bodySpacing: Style.space2`). A card with no `title` doesn't fold and has no header unless it has a `description` (the selection's own identity rows, `OptionsGroup`). A card whose rows are all hidden hides itself (`FormRows.empty`; a Binding on `visible`, so the host's own `visible` returns after): only its direct children count, a form's `allHidden` or a `FormRow`'s `shown`, never a `visible` or a height. A card ending on a shut fold row (`FoldFormRow`) takes no bottom padding: that row's own padding closes it (`FoldingCard.endsShut`, `FormRows.endsShut`). No card sits inside another card; list-item boxes (`ActionRow`, `KindBlock`) are list items and stay.
- `FoldFormRow` (`forms/`): the fold row of every card, on the settings page and in the editors: a `FoldHeader` in a `FormRow` (no row tint, no row click, no rail; the header's own trigger is the row's band, `reach*` the row's padding, so the whole row tints and folds as a button). `SettingsField` is one (it builds on it: `fold` set for an `x-fold` or `x-intro` Settings row, false for a value row, which draws no header; `foldable` false in search results), so both draw the same piece and `FoldingCard` reads `shutFold` (a fold row, shut) from either. The host owns `open` (a plain property), the rows behind it are its siblings with `shown: open && …` (a `SchemaPropertiesForm` takes `folded: !open`) and keep their own tree levels: a fold isn't a dependency, so no indent. `title`, `open`, `foldable`, `marked`, `fold`, `foldHeight`, `shutFold`, signal `toggled`.
- `ItemBox`: a box inside a card holding one item (a list entry, an editor's selected item, notes, an import): a sunken `Surface`. `dense` is the one-line item (`Widget.padding` left and right, `Widget.smallPadding` above and below), else `Widget.padding` all round. A `title` makes a header: `icon`, the title, a faint `caption`, a `headerActions` slot and, while `removable` (`removeTooltip`), a close button (`remove`). `foldable` makes the whole header a button that folds the body (a `Pressable` over the padded header, as `FoldingCard`'s; `open`, `toggled` for the host to flip it, `summary` the line shown while folded). Its default slot is a column spaced `Widget.spacing` that is a `FormColumn`, so the rows in it get their dividers right.
- `FactGrid`: label and value facts in columns, the labels muted (`facts`: `{ label, value, mono, wrap, middle }`); `pairsPerLine` 1 or 2, `monoLabels` sets the labels in the monospace font. The self-update and dev tree cards.
- `Thumbnail`: a picture in a rounded `ClippingRectangle` on `Style.surfaceHighest`, decoded asynchronously at `decodeSize` (the box by default) and cropped (`fillMode`, `cache`); an `ItemRow`'s thumbnail, a custom widget's Image element and list tiles are ones. `round` makes it a circle (an avatar) and `placeholderIcon` is a glyph shown while the picture isn't `Ready`.
- `CardScroll` (`reusable/`): a box's scrolling column of cards: the settings page's gutter (inside the box's padding, the scroll bar's lane on the right, `Style.rowBleed` of room past both sides for a row's tint) and `Style.cardGap` between cards. `TitledCard`'s body is one; a host never writes bleed margins for a card body.
- `StyledScrollView`: a ScrollView with the shell's padding and a thin accent scroll bar. `StyledScrollIndicator`: a `ScrollIndicator` drawn from `Style` (a bare one draws in the user's Qt palette); every popup list uses it.
- `BackdropScrim`: the soft shade of the theme background behind a bare module on the desktop, lock screen or greeter (`ScreenLayoutView` puts one behind each), as strong as the wallpaper under it (after the layout's dim) needs for `ink` (the module's `backdropInk`, else `Style.text`) to read, none on a calm wallpaper. `area` (screen px), `dim`, `blurred`, `ink`, `minContrast`, `worstCase` (assume the pole while the tone is unknown: the lock, the greeter), `fixedRegion` (a colour backdrop's flat grey levels). A `RectangularShadow`, never a layer; reads `WallpaperToneManager`, never waits for the daemon.
- `ModalCard`: the one card of every modal (the prompt, the power menu, the monitor prompt, the screen-share picker): a page-tone `Surface` that fades and slides in by `Style.enterOffset` (`shown`; `reveal` is the slide, a blur region's `moving`), swallows clicks, and insets its children (the default slot) by `padding` (`Style.space5`); the host sizes it from `padding` plus its content. `asking` draws the accent border; `window` registers that window as a modal (`SurfaceManager.registerModal`) for the card's lifetime. Beside it `ModalScrim`: the dimmed screen behind a card (`Style.scrim`, faded with `shown`), its `blur` the window's blur region. Its `blur` is the card's blur region (`BoxBlurRegion`, following `opacity` and `reveal`) for a window to hand to `BackgroundEffect.blurRegion` (the power menu, the monitor prompt). The card's head and foot are `ModalHeader` (icon well or an app's icon, headline, message, a slot right of the text) and `ModalFooter` (key `hints` left, buttons in the default slot right); the prompts' 400 ms settle stays `surfaces/prompt/PromptSettle`.
- `KeyHint`: a keycap and what it does (`[↵] open`), for a controls hint.
- `content/parts/KeyCap` (a key, or a folded direction set's keys spaced in one cap, H J K L), `ModifierCap` (a combo's modifiers in one cap, as glyphs or words): keycaps for binds (a sunken keycap). `KeybindSection` / `KeybindRow` draw the keybinds reference (the Keybinds page and the Cheatsheet); `compact` follows `KeybindManager.page.refDensity`; a modifier group folds (`KeybindManager.page.refFolded`). `KeyboardMap`: a US keyboard (`methods/KeyMap`) whose keys are toned (`toneFor`), labelled and clicked through hooks (the editor's key map); `KeyboardReference`: the reference drawn on it, under picked modifiers.
- `StyledSeparator`: a `Style.dividerWidth` divider in the divider colour of the fill it sits on (`backTone`: `raised` in menus, dropdowns and tooltips); `strong`, or `accent` where a divider is accent by design.
- `SeparatorMark`: a line, dot, slash or chevron divider (the Separator widget's, the bar's `separatorStyle` and a custom widget's Separator element).
- `StatusChip` (filled status pill, a `tone`: its container and ink; a caller that fills it with its own `color:` passes `ink`, the colour its word reads in (a custom widget's Status element); never below the chip floor, its word never elided), `CountBadge` (a count on a button's or icon's corner; bumps when it changes), `UnsavedDot` (`onAccent` on a selected row).
  - All three are `PopInRectangle`s: set `shown` (not `visible`) and they slide up as they fade in and back as they fade out; `pulse()` for a bump.
- `IssueList`: `[{ level, text }]`, errors red, warnings amber.
- `TipIcon`: an icon saying what it means in a tooltip on hover (`tip`), for a flag or a problem shown without its text (the bind list's flags).
- `IssueIcon`: one problem's icon in those colors (`level`, `tone`), a `TipIcon` saying what's wrong (`tip`). Every warning or error icon shown without its text beside it is one (a bind row, a bind section, the onboarding's binds table, the keybinds reference).
- `DropdownSurface`: the box of anything that drops down, a raised outlined `Surface`. `floating` (the default) makes it solid with a soft shadow: in a `Popup` (a combo box's list, `TypePickerPopup`, `StyledContextMenu`) nothing blurs behind it, so a translucent fill would show the page through it.
- `OptionPair` (`surfaces/onboarding/pages/`): two `OptionCard`s side by side, equal halves each as tall as the taller.
- `TileFlow`: equal tiles in an even grid: its own `columns` is the floor rule (as many as fit at `minTileWidth`, at least `minColumns`).
- `ChoiceTiles`: a single choice as a `TileFlow` of tiles, its column count `methods/ChoiceGrid.columns` (one line while all fit, else the fewest columns that keep the same rows, never one tile per line while two sit side by side), each a `PreviewTile` (a `preview` over its label, or a card when an option has `icon`, `description` or `tag`): `layout` `"grid"` (the even grid) or `"rows"` (two to a line, every tile as tall as the tallest on its line: the onboarding's pairs), `options` `[{ value, label, preview, icon, description, tag, tagTone, disabledReason }]` (`preview` a Component whose root declares `required property var value`, or the tiles' shared `preview`, drawn `previewHeight` tall on every tile while any has one, made with `previewProperties` too, once, from the build queue (a `StreamedLoader` with `always`), and kept up to date in place: a new option value or property is set only where it differs, so handing equal ones again redraws nothing), `value` pushed in, `picked(value)`. The chosen tile is in the accent; one with a `disabledReason` is greyed, says it in a `StyledToolTip` on hover and can't be picked (from `SchemaField`: the option's `x-tileHint`, else "Doesn't apply here"). One Tab stop (the tiles take none, `PreviewTile.tabStop: false`): arrow keys move between the tiles, Enter or Space picks. Drawn for an enum by `SchemaField` (`x-control: tiles`), its previews from its form's `tilePreview` hook (`SchemaPropertiesForm`: given the field's path, `{ component, properties }`; the [Bar style block](../bar/style-block.md)'s `BarLookSample`).
- `PreviewTile`: a clickable tile (a `Surface` and a `Pressable`), `title` under a `preview` Component (`previewProperties`, made once from the build queue and kept up to date in place, `previewHeight`) or, with an `icon`, `description` or `tag` (a `StatusChip`, `tagTone`), a card; `selected` (accent), `disabledReason` (greyed, a tooltip, no clicks), `clicked`, `menuRequested(x, y)`, `tabStop`/`ringed` for a host that owns the keys (`ChoiceTiles`). Templates and community setups are these too.
- `ZoomFrame`: content at its `naturalWidth` x `naturalHeight` scaled to fit the frame (`zoom` = `min(1, fit)`, never up), centred and cut to it; the scaled item declares `contentZoom`. Every scaled preview (module cards, element tiles) is one.
- `MonitorMap`: monitors where they stand, read-only: a caller's `delegate` per `model` entry, placed over its rect in `rects` (layout pixels, by index), the layout fitted and centred (`MonitorLayout.fit` / `place`, which the Monitors page's draggable `MonitorCanvas` uses too). The screen-share picker's Screens tab.
- `SplitColumns`: two parts side by side from `minWidth` on (the first taking `share`, each sized by `firstWidth` / `secondWidth`), stacked below it: a list beside the selected entry's form (an OSD's systems), a wide `EntryListCard`'s picker and first settings group beside its other groups.
- `TypeLibrary`: the editors' libraries of types to add; `groupable` off hides the A–Z / By category switch (types with no groups), `fitsContent` sizes it to its tiles for a library inside a pane that scrolls (the custom widgets inspector's elements).
  - An A–Z / By category switch over equal tiles of a caller's `delegate`, by label or under a heading per group (`methods/LibraryOrder`).
  - The label and heading come from the caller's `labelOf` / `headingOf` hooks (the editors translate the schema's).
  - The caller keeps `grouped`.
  - A search box beside the switch, at the right, narrows the tiles to the types whose label, type or group heading holds the text (`LibraryOrder.filtered`); the query lasts as long as the library is built (the layouts editor keeps it under a module's options).
- `CountModel`: a ListView's model of `count` rows read by index (a `ScriptModel` of `0…count-1`), so a new count adds or removes rows at the end and the view keeps its place; a plain number as a ListView's model rebuilds every row and scrolls back to the top.
- `KeyedLoader`: rebuilds a form when `key` changes, so rows never write old values onto a new selection.
- `StreamedLoader`: a relay (the walks of the texts it builds stop at it) and a Loader built a moment later from `BuildQueueManager`'s queue, then faded in and slid up into place (a `Translate`): a page's panels, cards, sections and long lists, so a page shows at once. `wanted` gates it like `active`; `always` streams after the page's first build too, and so do the loaders inside it while it fills in. See [streamed-building](streamed-building.md).
- `LayoutOrder`: shows a layout's items in reverse order while `reversed` (`Panel.flips`: a popout growing up keeps its controls last, by the bar). Only for a layout of plain items, no Repeater directly in it.

### Controls (`reusable/`)
- `StyledTextButton`, `StyledIconButton`, `SquareIconButton`, `FlatIconButton` (a `kind`, a hover and press state layer). `StyledTextButton` kinds: `tonal` (default), `primary`, `text`, `outlined`, `danger`, `dangerPrimary`; it is a Tab stop with the focus ring (Space, Return and Enter click; `tabStop: false` for a button sharing a stop, a `SegmentRow`'s), takes `acceptedButtons` and emits `menuRequested(x, y)` on a right click, both through `Pressable`; it dims itself while `enabled` is off (`Style.opacityDisabled`: a caller never sets that opacity); its label is one line and the button never narrower than it (`Layout.minimumWidth`); `overflow: "line"` caps it; `ownFill` (set with `color`) gives a fill of the owner's own colour the solid-fill hover and press tints; `inkColor` sets the label's and icon's colour (null: the kind's). `StyledIconButton` kinds: `text` (default), `tonal`, `primary`, `danger` (quiet: the error container on hover), `dangerPrimary`; it takes Tab focus and shows the focus ring; `SquareIconButton` is a `tonal` one at `Widget.height`. `StyledIconButton` is a square of side `size` that doesn't stretch in a layout; `FlatIconButton` is one with a dimmer icon.
- `StyledToolTip`: a hover tooltip in a popup window of its own, so the small layer windows buttons live in don't clip it. Buttons take `tooltipText`; `rich` draws rich text (line breaks as `<br>`); a bar widget's is a `BarToolTip`. It stays in `reusable/` though it reads services (blur, capture freeze): the buttons here use it.
- `StyledSlider`: trough, accent fill and a round handle (`handleSize`); `moved` while dragged, `released` at the end (still `pressed`, so a value pushed in from it shows without a snap back). `value` is only pushed in (a drag never writes it, so bind it) and animates when it changes; `position` is what it shows (the drag's place while `pressed`).
- `StyledVolumeBar`: a volume bar with its icon, mute and optional percentage (drag, click or scroll; its trough clips the fill, so a low level keeps to its rounded ends); muted, its icon (the base one) is a `SlashedIcon`; with `iconClickable` the icon is a button (`iconClicked`, hover highlight, `iconTip`); the OSD's bars are one (`surfaces/osd/design/OSDLevelBar`; Audio's `systems/Audio/design/VolumeBar` binds one to a Pipewire stream, the system volume or the microphone).
- `PercentageCircle`: a ring gauge with an icon in the middle; `sweep` below 360 opens it at the bottom (a gauge).
- `LevelMeter`: a level shown, not set: `StyledSlider`'s trough and fill without the handle, across or filling up (`vertical`); the fill is never shorter than its rounded ends. Any meter in a rounded trough is one (the custom widgets', Disks, Claude usage).
- `SegmentMeter`: a level as blocks or dots lit up to `share`, in a row or a column filling up.
- `Sparkline`: a small graph of `values` (oldest first) between `minValue` and `maxValue` (0: the largest shown), a line filled underneath or, with `style: "bars"`, a bar per value; `values2` adds a second line in `lineColor2` (`Style.series[1]`) on the same range. It paints only from its own properties, so it needs no `Style.revision`.
  - All three are drawn by the bar's display styles (`bar/widgets/base/ValueGraphic`, [Display styles](../bar/display-styles.md)) and a custom widget's elements; a bar sets the meters' sizes from its font.
- `SegmentButton`: a choice, accent when `active`, as wide as its label (and icon); `Layout.fillWidth: false` in a row of pills. Only inside a `SegmentRow` or `SegmentTabs` (a single choice); a multi-select is `ToggleChip`s.
- `SegmentRow`: a single choice of SegmentButtons on one `SegmentTrack`, the thumb sliding to the active one; the segments are equal and as wide as the widest label, never elided (a form row stacks the control under its label when it doesn't fit). One Tab stop with the focus ring on its track: Left/Right step to the neighbouring available button, Space flips two; a pick is that button's `clicked`. Multi-select chips are `ToggleChip`s in a Flow.
- `Pressable`: anything clickable that isn't a button, filling its parent: a Tab stop (`tabStop`), `clicked` on a click or Space/Return/Enter, a `StateLayer` (`tinted`, `onAccent`, `bleed`), a `FocusRing` on keyboard focus, the pointing cursor, `hovered`/`pressed`, `acceptedButtons` and `menuRequested(x, y)` on a right click. Declare it before the content. `StyledTextButton`, `FoldRow`, `FoldHeader`, `ItemBox`'s header, `Notice` (`clickable`) and `ToggleChip` are built on it. `squareBottom` squares the tint's and ring's bottom corners.
- `SegmentTabs` (`reusable/`, was `Settings/EntryTabs`): one `SegmentButton` tab per entry in a wrapping row (`count`, `current`, `labelAt(i)` / `iconAt(i)`, `picked(i)`, `menuRequested(i, item, x, y)`, only with `menus: true`, else a right click goes to what is under the tabs); the entry list cards use it.
- `StyledTabBar` (of `StyledTabButton`s): a 2 px accent underline under the current tab's label slides between tabs in one eased move (x and width glide together toward fixed targets), on a full-width baseline. With `scrollable` the tabs keep their own widths (every label whole), packed at the start, in a row that scrolls sideways, the current tab kept in view (a `ToolPane`'s tabs). `marked` (tab indices, `ToolPane.tabMarked`) puts an `UnsavedDot` after those tabs' labels, inside the label's width.
- `StyledTextEntry`: see [QML pitfalls](qml-pitfalls.md) (push the value in, act on `textEdited`). Search boxes set `clearable`: an X at the right while there's text, which clears it as a typed edit (`clear()`) and keeps the focus; with `escapeClears`, Escape clears it too (passed on when it's empty). The launcher's own field has the same X. A field hiding its text (`echoMode` not Normal: a password, a key, a passphrase) also keeps every input method out while `sensitive` (default: hides its text; PasswordEntry sets it always; `inputMethodHints` sensitive, no prediction, hidden; bullets, no mask delay) and warns while Caps Lock is on by itself: it loads `CapsLockHint` (plumbing, the one reusable piece reading `LockKeysManager`) at the right only while it has focus, and says so in `capsHintShown`; no host sets anything ([Lock keys](../features/lock-keys.md)). `StyledTextArea`: multi-line, optionally growing with its text (`expandable`, capped at `maxLines`, then it scrolls); `singleLine` makes it a one-line value that wraps (line breaks become spaces, Enter submits, Tab moves on).
  - Both draw their box through `FieldFrame` (the sunken, outlined Surface: `active` = the accent focus border, `invalid` = the error border; field-like triggers take it too) and their cursor with `TextCursor` (an accent bar blinking while its input has focus, steady with animations off), the `cursorDelegate` of any text input drawn by hand.
- `FieldFrame`: the frame of a text field or a field-like trigger: a sunken, outlined `Surface` with `active` (accent, focus width) and `invalid` (error) borders. `StyledTextEntry` and `StyledTextArea` are FieldFrames.
- `SubmitEntry`: an entry and its button in a row (`text`, `placeholderText`, `secret` hides the text, `buttonText` / `buttonIcon` (icon-only without text), `buttonTip`, `canSubmit`, `focusOnShow`; `submitted` on Enter or the button, both only while `canSubmit`, `cancelled` on Escape): WifiJoinForm's password, DriveRow's passphrase.
- `CommitEntry` (forms): a `StyledTextEntry` editing a value kept elsewhere: `value` is pushed in only while it's unfocused and holds nothing typed (the Binding with `RestoreNone` is inside it, never bind `text`); `live` emits `edited(text)` per edit, else `committed(text)` on Enter, losing focus, the page's Save (`EditsManager.holdTyping`, `commitTyped()` / `discardTyped()`) or, unless `commitOnDestroy` is false, its teardown. `SchemaTextField` keeps `StyledTextArea` (multi-line, wrapped up to four lines) with the same rule written in it, so it doesn't use it yet.
- `PasswordEntry`: a password field with a message, a busy bar and `shake()`. Its entry is `sensitive` shown or not (`secret`, default true; off for an answer that is never hidden, a user name: PromptCard), so every input method stays out (StyledTextEntry's hints: [input sources](../features/input-sources.md)). While its message is empty and Caps Lock is on, the message line (or the placeholder, `inlineMessage`) says so in `Theme.warning` (unless `capsMessage` is off).
  - It has no authenticator of its own: the lock screen's `PasswordField`, the greeter's `LoginField` and the shared prompt (polkit's card, `PromptCard`'s fields) wire it.
- `StyledComboEntry`: a choice from a list dropping down under a field, optionally typed. `search` (a function of the typed text returning the options) stands in for `options` when the list is too long to hold, asked only once the list opens or something is typed: the icon field (`x-control: icon`, [icons](icons.md)). In a popout or edge menu (its window declares `popoutRoom`) the list opens inline (`expandsInline`), inside the field's layout, since a dropdown Popup there is a window the popout's hover and blur don't reach. It's capped by the room the box has left to grow, or in an edge menu by the Flickable around it, which scrolls it into view. The dropdown Popup (a shadowed surface and a ListView) is built the first time the list opens, never for a closed field.
  - `options` `[{ value, label, icon? }]`, `value` pushed in, `picked(value)`; `activate()` is a click on the form row holding it (`FormRow.activates`: opens or closes the list, as `SchemaComboBox.activate`).
  - Used by the greeter's user and session pickers.
- `StyledSwitch`: track `surfaceHighest` off, `accent` on; the focus ring on keyboard focus. `compact` makes the track `Widget.smallHeight` high (a dense row's, beside other leading content: Keybinds' bind rows and section headers).
- `ToggleChip`: a multi-select chip (`text`, `iconText`, `checked`, `toggled`; a Tab stop through `Pressable`): the highest surface off, the accent container with a leading check on (never colour alone), one line. A page owns `checked`. Keybinds' `FilterChips` builds its `Filters` popover and its active chips from it.
- `StyledToggle`: a `SegmentRow` of one `SegmentButton` per option (equal segments as wide as the widest label, a thumb that glides to the chosen one). A click picks the segment (the chosen one again does nothing); one Tab stop, Space flips two, Left/Right step. `options` (two or three values), `labels` `{ value: label }`, `value` pushed in, `picked(value)`. Drawn for a two- or three-value enum by `SchemaToggle` (`x-control: toggle`).
- `NotchWheel`: a `WheelHandler` that steps once per wheel notch (120, a touchpad's scroll adding up to one first), `stepped(direction)` -1 up/left, 1 down/right. Used by the workspace switchers and the overlay's page navigator.
- `TypePickerPopup`: pick a type, `{ type, label, icon, image?, detail?, group?, keywords? }` (`image`: a picture drawn in place of the glyph, an app's icon; `detail`: a faint second text after the label, elided), from a list under a search field that filters as the libraries do (`LibraryOrder.filtered`: label, type, group heading, keywords). With `groups` (the schema's `x-libraryGroups`) the types are under a heading per group (`LibraryOrder.grouped`), Up/Down skipping the headings; without, in the order given. `labelOf` / `headingOf` translate the schema's keys. `openAt(item)` opens it under `item` (above it with no room below), its own width, or with `matchWidth` exactly `item`'s as drawn (a Popup isn't scaled with an overlay page fitted to its screen, so it takes the item's mapped width), labels and headings elided. The bar editor's + (flat, its own width: the button is small) and an OSD's Add system (grouped, `matchWidth`: as wide as the Add button), the Window rules page's Add from open window and Add app (`image`, `detail`, `labelOf` showing names as they are).
- `MenuList`: a menu's rows and keys, for the box holding them. `items` `[{ id, text, icon, shortcut, enabled, checked, submenu, danger }]` (`danger` highlights it in the error colour) or `{ separator: true, accent }`; a `submenu` opens in place under a row leading back; `triggered(id)`. Up/Down, Enter or Right, Left, Escape (at the top level `dismissed()`); `reset()` back to the top. In `StyledContextMenu` and the dock's `DockMenu`.
- `StyledContextMenu`: a right-click menu on a `DropdownSurface`, opened at a point (`openAt(item, x, y)`): a `MenuList` (`items`, `triggered(id)`), closing once an item is picked or on Escape; a press outside closes it (Popup's `closePolicy`, as `TypePickerPopup`). The bar editor's chips.
- `Notice`: a status callout on the status's container (`status`: `info`, `success`, `warning`, `error`, `accent`; `icon`, `title`, `text`, `actionText` and `triggered` for its one small button; `enabled: false` disables the button); `actions` (its default slot) holds any more buttons after the text, and `clickable` makes the whole callout a button (`clicked`, a `Pressable` under the buttons: a Tab stop, Space or Enter press it). Tailscale's "needs your permission" and "log in" lines, and the onboarding pages' notes.
- `ActionTile`: an icon well over a label (`activeTone`: `accent` or `error`, the fill while `active`; hovered, the well takes the tone's container). With `opens`, a right click or long press is `opened`.
- `ActionPill`: the wide one, a well beside a name and status. With `opens`, the well toggles and the rest opens. Where the pill already has the height (it never grows for them), the name wraps to two lines and the status takes the lines left, three in all.
  - Both drain a `CountdownBar` (a bar along the bottom emptying over `duration` while `running`) over their `countdown` while active.

### Editor lists and drags (`reusable/`)
- `Style.listRowHeight` is a list entry row's height (`ListEntryRow` and the lists that reserve its room); `Style.minHit(icon)` is the least square a small icon button is hit at.
- `ListEntryRow` (+ `RowAction`, `AddEntryButton`): a `Rectangle`, filled with the accent container while `selected`; its `RowAction`s show while the row is `revealed` (hovered, focused or selected) and always keep their room, so the badges beside them are never covered; an elided label shows in a tooltip. It takes keyboard focus, one Tab stop per list: Up/Down walk the rows (skipping their actions), Enter is `clicked`, Delete `removeRequested` (the page runs its remove, with its own blocked rule), Escape `escapePressed` while the row is selected and the page set `escapeClears` (otherwise Escape reaches the host); Tab goes through the row's own controls (`leading`, then its actions), then out of the list. Slots: `leading` (before the icon: a switch, keycaps), `subtitle` (a caption after the name, at most a quarter of the row, `subtitleLines` lines), `issue` (`error`, `warning` or `info`: an `IssueIcon` after the unsaved dot, saying `issueTip`) and `strikeout` (the name struck through); order: leading, icon, name, subtitle, badges, unsaved dot, issue mark, actions, standard actions. `image` shows a picture (an app's icon) instead of the glyph. The standard actions follow the page's own, each a `RowAction`: `canDuplicate` (`duplicateTooltip`, `duplicated()`) and `canRemove` (`removeTooltip`, `removeRequested()`, the same as Delete; always `close`, danger); a row with neither builds no standard action (one `Loader`). `AddEntryButton` owns the gap above it (`Widget.spacing / 2`), so a list's host adds no margins.
- `DragArea`: drag vs tap; with `dragLayer` + `payload` it carries.
- `DragLayer`: one drag (`dragging`, its `kind` as `draggingKind`), a target registry, and a hit test.
  - `accepts` / `priority` hooks; `priority` defaults to a target's `dropPriority`.
  - Signals: `started` / `moved` / `dropped`.
- `InlineDragLayer`: a `DragLayer` inside a form or card that takes no room in its layout (only the coordinate space, above its siblings) and draws the carried payload's `label` in an accent pill by the pointer, so `views/Layouts/EntryListTarget` rows work on it. `PickedChips`, the bind editor's rows and an OSD's systems (`OSDSystemsEditor`).
- `TrashTarget`: a "Drop to remove" pill (the error container while hovered) shown while `active`, `targetKind: "trash"`, above overlapping targets. The layer's `accepts` says what it takes and its `dropped` removes it.
- `DragChip`: a carryable icon + name pill; `highlighted` draws it hovered for a pointer elsewhere, and with `hasMenu` a right click is `menuRequested(x, y)`.
- `views/Layouts/EntryListTarget`: a list of rows that reorders its own carried rows.
- `GridCanvas.underlay` (`[{ place, label, element? }]`): places drawn dimmed under the modules, not selectable, widening the lattice (the custom widget editor shows the base elements under a screen). `GridCanvas.tileContent` (a Component with a `module`) replaces a tile's icon and label (and an underlay item's label), and `tileContext` is a right click on a tile.
- `views/CustomWidgets/CustomWidgetPaths`: the paths of an output with the value at each (`paths`, `maxRows`, `pickable`, `picked(path)`): the Data tab's list.
- `FlowDropTarget`: a target over a Flow of carried items (its `repeater`'s): `indexAt` is the item nearest the pointer on its row (before or after its middle), with an accent bar where a drop lands. Used by `PickedChips`.
- `InspectorHeader`: icon well, name, place (middle-elided, the whole of it on hover), the page's own actions (children, e.g. state toggles), then the standard ones: `canDuplicate`, `revertable`, `canRemove` (`danger`; disabled with `removeBlockedReason` as its tooltip) and `closable`, with their signals and tooltips; then a wrapping row of `links` (shown while the host's `showsLinks`), divider.
- `UndoRedoButtons`: an editor's Undo and Redo buttons, enabled from its `canUndo` / `canRedo` (an `EditHistory`'s, `qml/services/ui/EditHistory`: snapshots before each edit, edits to one field joining a step, up to 50).
- `content/base/SaveResetActions`: an editor's Save/Discard pair, both shown only with unsaved edits or typed text (`canReset: false` hides Discard while `dirty` means something else, as the Monitors page's draft differing from the monitors). `compact` drops to icons, as `CardHeader` does when its row is too narrow. Items placed in a `CardHeader` sit just after its title, and its `trailingTools` at the right before the buttons. Its `help` is a "?" after the title saying what the panel is for in a `StyledToolTip` on hover (wrapped at its `maxWidth`).

### Tool pages (`views/base/`)
- `BaseView`: the base of every overlay page: `grid`, `viewConfig`, the sizes `pageHeight`, `cardPageWidth`, `sideWidth`, `editorWidth`, and the tool pages' `pageWidth`, `inspectorWidth`, `listWidth`.
- `FoldRow` (`reusable/`): a compact folding row with a chevron, a Tab stop (Space/Enter fold) through `Pressable`; `tinted` off leaves the hover tint to the host (`ActionRow` tints its whole folded box). `TitledCard.headerTools`: controls at the header's right, before Save and Discard (the custom widgets page's Undo/Redo).
- `PinnedList`: a list that scrolls inside once it passes `maxHeight` (by default `maxShare`, 0.4, of `shareOf`'s height, a box its host sizes, never its own layout parent (a loop); with neither it takes its content height; padded by the focus ring so a row's ring isn't cut); `cut` says it scrolls, `contentHeight` is the list's own height. `ToolPane`'s `pinned` is one, and the layouts editor's lists.
- `ToolPane`: a `TitledCard` for a tool page's pane: `headerIcon` (the accent icon before its title), `pinned` (a list above the tabs, scrolling inside past `pinnedShare` of the pane), `tabModel`/`tabIndex`/`tabClicked` (a scrolling `StyledTabBar`), `toolbar`, the body (its children), `footer`, and the empty states (`emptyKind` `"none"`, `"select"` or `"results"`, with `emptyIcon` (for `"none"` set the page's icon; `"select"` and `"results"` default to `touch_app` and `search_off`), `emptyText`, `emptyHint`, `emptyActionText`, `emptyTriggered`). `bodyHeight` sizes a work surface in the body.
- `ToolBar`: a `ToolPane`'s toolbar: `leading`, a search field (`searchable`), `trailing`, a `count` (read "count of total" while a `total` is set and the count is under it), and a `filters` row; narrower than `wrapAt` the trailing controls and count go to a second line.
- `InspectorCard` (`views/base/`): an editor's inspector box: a `surface` card padded `Widget.padding`, a `header` slot (an `InspectorHeader`), then its children in a `CardScroll`, the scroll kept across the overlay closing under `scrollKey` (`ScrollMemory`).
- `EditorLibrary` (`views/base/`): an editor's library of things to add: a `CardHeader` (`title`, `icon`), a `caption` and a `TypeLibrary` of `types` with the schema's labels and `groups`, the A–Z / By category choice kept in `EditsManager`; `delegate` builds a tile per type at `tileWidth`; `groupable`, `minColumns`, `minTileWidth`, `fitsContent` as the `TypeLibrary`'s.
- `ListSection`: a titled group of rows (`title`, `count` right after the title, `hint`, a `trailing` slot at the far end); `collapsible` makes the header a toggle (`toggled`; the page keeps `open`).
- `WorkArea`: an editor's work surface: a box with a `CardHeader` (`icon`, `title`, `count`, `help`; `undoRedo` and `tools` at the right, then Save and Discard, through `CardHeader.trailingTools`), a `status` line and a sunken well holding its children; `embedded` drops the box where it is the pane's only main content.
- `GroupColumns`: an inspector's `FieldGroup`s (and short forms) as newspaper columns, as many as the width holds (a column never under `Style.columnMin`; `gap`, default `Style.cardGap`, is the gap between groups, down and across: the settings page's card gap).

### Forms (`forms/`)
- `SchemaField`: one schema row, any type. It picks `SchemaSwitch`, `SchemaNumberField` (slider or stepper; it builds only its mode's control), `SchemaComboBox` (a non-editable `StyledComboEntry`; a colour list's rows are filled with the colour, their ink picked once per option), `SchemaToggle` (a two- or three-value enum with `x-control: toggle`: a `StyledToggle` at the row's end, on its label's line when it fits beside the label (else under it, filling the width), placed by `FieldLine` (`FieldFit`); a click on the row off the toggle cycles to the next option, `SchemaToggle.activate`), `ChoiceTiles` under its label (an enum with `x-control: tiles`), `SchemaTextField` (commits on Enter, focus loss or a suggestion; a long value wraps, growing to four lines, then scrolls; a Browse button with `x-control: "folder"`; a decimal, `type: number`, is one too, `beside` its label on a wide form like a dropdown, committed as a number within its bounds: `SchemaNumberField` is integers only) or `SchemaObjectArray` (a list of `SchemaArrayItem`s): use `SchemaField`, not those, unless you need one alone.
- `forms/RefEntry`: the editor of an `x-ref` field (`kind`): a `StyledComboEntry` (`editable`) over `SettingsManager.refOptions`/`refLabels`, emitting `committed` only for a valid id (`refValid`; anything else shows the value again). `SchemaField` (hot corners' argument) and `BindInspector` (a keybind's) both use it.
- `IconEntry`: an icon picked by name from the icon font or pasted as a glyph (a `StyledComboEntry` searching `IconManager`, a note while the value reads as a name the font lacks): `SchemaField`'s icon fields and the special workspaces' list rows. `value` in, `picked` out.
- `FieldLine` (forms): the one layout of a schema field and its control (every `Schema*` control, the custom widgets' `InspectorRow`): the label line (`FieldHeader`), the notes (description and links, a label-less `FieldHeader`), the control (the default child) and a `body` under all of them. `kind` (`switch`, `fixed`, `flex`, `slider`, `fill`, `block`) and `controlLeast` give `FieldFit.place` the constant widths it decides by (its own `width`, which hosts fill, the label's `FieldHeader.lineWidth`, marks counted at `FieldChangeMarks.fullWidth`); `fit`, `inline` and `leastWidth` are read from it. Inline, the description and links sit beside the control at any width (wrapping earlier on a narrow field) with the control centred on the whole box; stacked, they sit above it.
- `FieldHeader`: a field's label (`label` role; `title` for a list's title) with its description right under it, a `trailing` slot on the label's line (the settings row's unsaved dot and reset, passed down as `SchemaField.headerExtra`) and a `below` part under the description, read with the label (the field's `x-link` line and action, passed down as `SchemaField.headerBelow`; its root declares `readonly property bool shows`, from data, never layout). So a trailing control centres on title, description and links together, in every layout; stacked ones show the links above the control. Those marks are `FieldChangeMarks` (`schema`, `current`, `optionLabels`, `changed`; `reset(value)` with a copy of the default, `discard()`): a schema form gets them on every field with its `changedAt` hook (`SchemaPropertiesForm`, `OptionsGroup`; the dot's click is `discardAt(path)`). Every schema control draws its label through it; a switch sits at the row's right end, centred on the label and description. Every setting row tints under the pointer (`SchemaField.tinted`, `FormRow.tinted`), but a list of objects (its items' rows tint); only a switch, an automatic number, a toggle, the icon field's Icon/Text/Both switch and a dropdown act on a click on the row off their control (`SchemaField.hoverable` makes its `FormRow` hoverable, and `FormRow.rowClicked` is routed to the control's `activate()`: a switch flips, a toggle or the icon switch cycles, a dropdown opens or closes). Where a control sits, on the label's line or under it, is `FieldLine`'s (`FieldFit`): a dropdown, colour, decimal, toggle or stepper stays on the label's line whenever the label's line fits beside it, so narrow forms read like the settings page; a slider needs `Widget.fieldInlineFrom` (`FieldFit` `inlineFrom`); text boxes stay under the label. The settings page's reset button's tooltip names the default.
- `FormRow`: one row of any schema form (a `SchemaFormRow`: the settings page's `SettingsField`, `SchemaPropertiesForm`'s and `SettingRows`' rows): a row of the boxed list: padded `Style.rowPadding` above and below and at least `Style.rowHeight` tall (`bodyHeight` is the content's height; `fullHeight` the row's at full reveal), a divider on its top boundary (none on the top row: `first` is by default the `firstRow` of the `FormColumn` it sits in (`FormRows.first`, which a `FieldGroup`'s and `FoldingCard`'s body publish too), a host laying rows out itself sets it (`Utils.firstFormRow`, a wrapper of `FormRows.first`), and none above an empty row; never from the row's own `y`, which the layout sets from its height: a row flipping between the two once kept the layout polishing forever and froze the shell), an accent rail beside a row shown by another row's value, `depth` = `level` (the row's place in its form's `RowTree`, which `SchemaPropertiesForm`, `SettingsGroupCard` and `SettingRows` give; a hand-built row under another sets `level: 1`): one rail per depth, the body `depth` steps (`Widget.spacing * 2`) in, the tint starting at the row's own innermost rule (`StateLayer.leftBleed`; only a depth-0 row bleeds `Style.rowBleed` past its left), and `beside` (the right half of a pair) drawing none; a fold open and shut as `shown` flips, and, while `tinted` (the default; `hovered` says the pointer is over the band), a state layer under the pointer reaching `Style.rowBleed` past its sides. The `HoverHandler` is on the row itself, an ancestor of every control, so a child that takes hover (a switch, slider, text box, link) never clears it. `activates` names the control a click on the row off the controls acts on (its `activate()`: a switch flips, a list opens) and makes the row `hoverable` (the default is `activates !== null`). While `hoverable` the row also has one visible `MouseArea` (`rowClicked`, pointing cursor, under the body so a control takes its own clicks). `hitHeight` limits the tint and the click to the band: the body's first `hitHeight`, padded below by as much as above so the field sits centred in it (the whole row when the field is all there is); a hookup or footprint row under the field is outside it. A form's grid or column keeps no row spacing of its own. A row is a relay (it publishes `inkHostAbove` and `drawnZoom`).
- `FormColumn` (`forms/`): a column of `FormRow`s, spacing 0, publishing `firstRow` (the top row drawn: `FormRows.first` over its children, read from `shown` and `bodyHeight`, never `y`, `height` or `visible`), which each `FormRow` in it takes for `first`. `FoldingColumn`'s inner column is one, so the rows of a `FieldGroup` or `FoldingCard` need no `first`.
- `FieldRow` (`forms/`): a hand-built field of a card, a `FormRow` holding a `FieldLine` and any control: `label`, `description`, `shortControl` (a dropdown on the label's line when it fits), `besideLabel`, `below` / `belowShown` (items under the field, outside the tint), `activates` (a click off the controls acts on that control). `views/CustomWidgets/InspectorRow` and `views/Keybinds/BindRow` are today's copies, deleted as their callers move.
- `SwitchRow` (`forms/`): a switch line, a `FormRow` holding a `SchemaSwitch` at the right end, a click anywhere on the row flipping it: `label`, `description`, `checked` (pushed in), `toggled(bool)`, `leading` (an icon or colour dot before the label), `unavailableReason` (greys the row and says why in place of the description; a row already on can still be turned off).
- `PickedChips` (`forms/`): an array of picks as chips, a click taking one away: an `x-ref` array of ids (a window rule's paused shortcuts) or an array of enum strings (`x-ordered`), as `SchemaField` draws them. `value`, `options` (what can be picked, in order), `labels`, `icons`, `groups` (`x-enumGroups`), `edited(array)`, the `FieldHeader` passthrough (`label`, `description`, `headerExtra`, `headerBelow`). `ordered`: the chips are `DragChip`s in a `FlowDropTarget` on an `InlineDragLayer` of its own, dragged into place. `addMode` `"inline"` lists the others under the chips (under their group's header; `AddEntryButton`-style outlined chips, a click adds one at the end), `"picker"` is one `addText` button opening a `TypePickerPopup` of the others. A value no longer in `options` still shows, so it can be taken away.
- `SchemaPropertiesForm`: a flat object; `order`. `follows` keeps its top row's divider when a hand-built row sits above it in the same box. `keepsPlace` greys a field marked `x-keepsPlace` whose `x-showIf` fails instead of hiding it, saying why on hover; `tilePreview` gives its tiles fields' previews (the [Bar style block](../bar/style-block.md)). `tree` is `RowTree.plan(rows)`: each row's `level` is its depth in that tree; `folded` hides every row (behind a shut `FoldFormRow`); `allHidden` says every row is known hidden (a streaming row counts as shown).
- `SettingRows`: dotted config paths as `SchemaFormRow`s (with the reset button and `x-link`s as on the settings page), saved debounced.

- `methods/GridPosition`: the workspace grid's shown row or column: `line(activeId, base, columns, rows, vertical)` (`{ line, count }`), `glyph(position, count, vertical)`, `head(count, active, vertical, across, fontSize)` (the position head's dots, or the arrow).
- `methods/SchemaRefs.sites(schema, kind)`: the fields of the built config schema marked `x-ref` of a kind (where they are, which items hold one, the reason text): `[{ path, field, many, key, when, usedBy, name }]`, and `SchemaRefs.references(config, sites)` the ids settings hold. `methods/SpecialWorkspaces`: special workspaces as data: `validId`, `list(entries, specials, refs)` (the rows: entries, referenced, live), `blockers(row)` / `deletable(row)`, `cells(list, specials, mode)` (the switcher's and overview's cells), `entryFor`, `content` (what a cell shows).
- `forms/SecretStatusChip` (`status`, `envName`, `missingText`): a `StatusChip` for where a secret comes from (env, keyring, file, none, unneeded, checking).
- `methods/ColorTemperature.color(kelvin)`: light's color at a temperature (the night light's button).
- `methods/RecommendedSetup`: the Recommended setup list from the schema's `x-recommended`: its entries, rows (available, done, ticked by default, why not), the ordered plan of an Apply and the portal's defer-or-restart choice.
- `KeybindFilter.columns(sections, count)`: the masonry split of the Keybinds page and the Cheatsheet module.
- **Utils** (`methods/Utils`):
  - `clone`, `freeId(base, taken, sep)` (`dock2` → `dock3`)
  - `valueAt(object, path)`: a value by its key path (every form's `valueAt`, `SettingsManager.configValueAt`, `ConfigDraft`'s read); a schema property's default by path is `SchemaLayout.defaultAt`
  - `spaceWords` (CamelCase → words), `edgeArrow(edge)`
  - `formatRate` / `rateParts` / `formatSize`, `formatBytes` (a file size, "4.2 MiB")
  - `recordUse`, `truncate`.
- `Paths.expandHome` / `shortenHome`; `KeyNames.modifierLabel`.
