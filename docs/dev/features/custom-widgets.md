# Custom widgets

> **Files:** `config/CustomWidgetsConfig.qml`, `services/apps/CustomWidgetsManager.qml`, `services/apps/CustomWidgetsEditor.qml`, `components/views/CustomWidgets/`, `components/methods/CustomWidgetData.qml`, `components/content/CustomWidget/CustomWidget.qml`, `components/content/parts/custom/` (the elements in `elements/<Type>/`), `components/bar/widgets/CustomWidget/CustomWidget.qml`, `config/schema/sections/CustomWidgets.yaml`, `config/schema/definitions/custom/`, `config/schema/definitions/kinds/CustomElementBase.yaml`
> **Config:** `CustomWidgets.items` (reader `CustomWidgetsConfig`)
> **Related:** [Services pattern](../core/services-pattern.md), [Protocol](../backend/protocol.md) (`exec.watch`), [the plan](../plans/custom-json-widgets.md)

A custom widget is a script drawn as a bar widget, that widget's popout and a module (overlay, desktop, edge menu and, when allowed, the lock screen), all from one definition in `CustomWidgets.items`, so the script runs once for all of them. Its output is read as Waybar reads a `custom/*` module's, so Waybar scripts run unchanged.

### Definitions
Each item (`definitions/custom/CustomWidget.yaml`) holds:
- the script: `command` (run by `sh -c`), `mode` (`poll` every `interval`, `stream` one sample a line, `once`), `output` (`waybar`, `json`, `text`), `execIf` (Waybar's exec-if) and `refreshName`;
- `actions`: Waybar's on-click, right and middle click, scroll up and down;
- Waybar's `format`, `formatIcons`, `maxLength`, `escape`, plus `states` (class → theme colour), `hideEmpty`, `tooltip`;
- `bar` (the bar widget's style) and `module` (its design size, its elements, whether the lock screen offers it).

The fields, each read from the output's key of the same name (the script shapes its own JSON; nothing maps them): Waybar's `text`, `alt`, `tooltip`, `class`, `percentage`, and axiom's `icon` (Material Symbols), `value` / `min` / `max` / `unit`, `subtext`, `state`, `badge`, `urgent`, `image`, `items` (rows of `{text, icon, value, subtext}`) and `hidden`. Plain text that's a number is the `value`; text matching a `formatIcons` key is the `alt`; a format-icons pick that's a Material Symbols name is the `icon` when the output has none.

### Reading an output
`CustomWidgetData` is the pure half:
- `parse`: a JSON object as is; Waybar's text output as lines text, tooltip, class (a streamed line is only text).
- `resolve`: the fields, the format filled (`{}` / `{0}` the text, `{icon}` the format-icons pick, any field or path), `escape` before filling, Pango markup turned into Qt rich text (`pango`), the state colour (`stateColor`: the `state` field, else the first class `states` or the defaults map), `ratio` (the value between min and max; `percentage` alone is a value on 0–100), `hidden` (empty text, as Waybar).
- `flatten` lists a sample's paths for the editor's dropdowns.
- `lattice`, `designSize`, `pageSize`, `rect`: the module's lattice, 4 sub-cells a grid unit (16 a card), the elements' bounds (so the box fits them), laid out proportionally over whatever size the module gets.

### Running
`CustomWidgetsManager.acquire(owner, id)` watches the definition's command through `CommandManager` (format `json` unless the output is plain text) under its own owner per id; the merge by command string means a widget on two bars and a module still runs one script. Each push whose `CommandManager.runs[command].at` changed is resolved into `fields[id]`, and an edited definition (its format, icons, states: the page's preview) re-resolves its last output at once, without adding to the history; `outputs[id]` keeps the raw text, value, exit code and error for the editor, and `history[id]` the last 60 values of the widget's value and of each Sparkline element's binding. With an `execIf`, the script is watched only once that command succeeds (checked when first shown and on refresh).

`act(id, action)` and `runCommand(id, command, value)` run actions detached (`{value}` filled in, shell-quoted unless a number), then refresh the script 300 ms later. Nothing runs in the greeter or while the built-in lock screen is up. `axiom ipc customWidgets refresh <name>` (refresh name, id or name) stands in for Waybar's `signal`: a script calling `pkill -RTMIN+N waybar` should call that instead.

A stream is coalesced to 4 pushes a second by axiom (`backend/internal/command/stream.go`), so frame-rate scripts (cava) look choppy.

### The module
`components/content/CustomWidget/CustomWidget.qml` is a `Panel`: in a card (`properties.definition`) it fills its slot; as the bar widget's popout (`definitionId` from the anchor's `extraData`) it's the definition's design size at the screen's card size (`OverlayConfig.cardUnitOn`, `GridPlacement.span`), declared up front as `maxImplicitWidth/Height`, since an open popout never resizes. It acquires its definition while shown; actions are off on the lock screen (`host.kind`) and in previews (`host.preview`). It sets no `fullMinWidth`/`fullMinHeight` and has no `compactContent`: its elements are laid out proportionally, so any size draws them (the editor's previews show the usual ones). It builds either the layout or, with nothing to show, an `EmptyState` saying why.

`CustomLayout` (`components/content/parts/custom/`) draws the elements: a Repeater by count over `module.elements` (or `CustomWidgetsConfig.defaultElements` when there are none), each a `CustomElement` (a Loader of `elements/<Type>/Custom<Type>.qml`: prefixed, so an element named after a Qt type, Text, Image or List, never shadows it) at `CustomWidgetData.rect` of its place, a `Widget.px(6)` gap between neighbours.

Element kinds are a schema kind like bar widgets and modules (`index.yaml`'s `kinds.CustomElement`): each `elements/<Type>/schema.yaml` (a `label`, `icon`, `defaultSize` in sub-cells, `slots`, `actions` and its look as `settings`, expanded over `CustomElementBase.yaml` into `<Type>CustomElement`) beside its QML. So its options have their defaults filled at load like any setting, `CustomWidgetsConfig.elementKinds` reads the library from the schema, and the reference is generated (`docs/dev/config/CustomElements/`). The `color` part gives graphics an Auto colour that's the state's when the script gives one (`color: state`) and text a colour plus a Colour by state switch (`color: text`); `CustomElementBase.colorOf` reads either. Each element is a `CustomElementBase` with the element's config, the fields, the history and helpers for its bindings (`value`, `text`, `ratio`, `range`, `colorOf`, `act`, `vertical`: a box taller than wide), drawn with the shell's own pieces:
- Text (fitted to its box when plain; rich text at a size from the box), Text block (scrolls; the tooltip by default), Icon (Material name or the format-icons glyph, a `CountBadge`).
- Ring and Gauge (`PercentageCircle`, `sweep` 360 or 240; the value inside carries the output's `unit`), Bar (a `LevelMeter`, or a `StyledSlider` with a change command, holding the released value until the next sample), Segments (`SegmentMeter`), Sparkline (`Sparkline` over the service's history, between `CustomWidgetData.graphRange`'s min and max). Value, min and max are slots (`CustomWidgetData.elementRange`: bound, or the output's own `value`/`min`/`max`).
- List (`ItemRow`s from a ListModel updated in place; a click command runs with the row's text), Image (`ClippingRectangle`), Button (`StyledTextButton`), Toggle (a `StyledSwitch` beside its label or an `ActionPill`; holds its new state until the next sample), Status (a `StatusChip` or a dot), Separator (`SeparatorMark` with the Separator bar widget's style, thickness, length and colour; its style is the shared `SeparatorStyle`).

The module library offers each definition by itself (`OverlayConfig.customModuleTypes`, group Custom, A–Z by name), keyed `CustomWidget:<id>`; `GridEditor._newModule` turns the key into `{type: "CustomWidget", properties: {definition}}` (`CustomWidgetsConfig.splitKey`), and the definition's design size is where it starts. The lock screen's library lists only definitions with `module.lockscreen`.

### The bar widget
`components/bar/widgets/CustomWidget/CustomWidget.qml` is a `BarIconWidget` drawing the definition's `bar.style`: `label` (icon and the format filled, as plain text: Waybar's look), `icon` (the icon alone), `ring`, `fill` (`LevelMeter`), `segments` (`SegmentMeter`), `sparkline` (a graphic in `IconTextWidget`'s `lead` slot, `leadLength` long, before the icon), `pill` (the widget's background filled to the value: its `backgroundLevel`, which its WidgetGroup draws in the background's own shape, so it keeps the bar's caps and radius), `ticker` (long text scrolls in `bar.width`) and `stacked` (the text over the subtext); a vertical bar draws ticker and stacked as labels. The state colour is its `accentColor`, so the bar's widget style shows it (a fill, tint, outline or the icon); the graphics draw in `colors.icon`, which reads on a filled background, and `bar.colorText` colours the text only where the state isn't already the fill; `urgent` pulses it; `hidden` hides it. Clicks and scrolls run the definition's actions; hovering opens the CustomWidget popout (`extraData: {definitionId}`) while `bar.popout` and the widget's own popout are on.

The bar editor's library is `BarsConfig.libraryWidgetTypes`: the types without CustomWidget, then one entry per definition (`CustomWidgetsConfig.libraryEntries`, keyed `CustomWidget:<id>`), which `BarManager.addWidget` splits back into the type and its definition; a placed one's chip goes by the same key, so it's named after its definition.

### The page
The Custom widgets tool page (`components/views/CustomWidgets/`, `/widgets` in the launcher) edits `CustomWidgets` through `CustomWidgetsManager.editor` (`CustomWidgetsEditor`: a `ConfigDraft`, `selectedIndex` / `selectDefinition`, `elements` (a `GridEditor` over the selected module's elements), `tab`; registered in `EditsManager`). Edits show live on the bars and pages through `ConfigManager.setPreview("CustomWidgets", …)`, and the selected definition stays acquired while the page is shown (`pageShown`), so its sample is there to bind from.
- **Left** (`DefinitionsPanel`): the definitions (add, duplicate, remove), the selected one's script fields (`SchemaPropertiesForm` over the definition's schema, limited with `Utils.pick`), Pick a script (`FilePickerManager`), the refresh command, and the script's first lines when the command starts with a path.
- **Data** (`DataTab`): the run state and Run now, the raw output, and every value in it by its path (`CustomWidgetData.flatten`, by count, the first 200), which the module's elements bind to.
- **Bar** (`BarTab`): the real bar widget on the first bar's look, across and down a side, over the `WidgetBackground` its WidgetGroup would draw (a lone widget's caps, the pill's fill), then the bar style, the text (format, longest text, escape, hide when empty, tooltip; the format icons and state colours typed as JSON) and the actions.
- **Module** (`ModuleTab`): previews across the top (the popout at the design size, and square, wide, large and strip, since a page can give the module any size) with whether the lock screen offers it; under them `ElementInspector` down the left (the element library as `ModuleChip`s: drag one onto the module or click it, then the selected element's bindings per slot, its look as a schema form of its kind's options, and its commands), and the layouts editor's `GridCanvas` filling the rest, in a `GridDragLayer` over `editor.elements` that is its own file's root (`ElementEditorLayout`, as `LayoutsEditorLayout` is): the same drag in, move, resize from any side, push, box-select, guides, keys and undo as a submenu's modules.

`editor.elements` is a `GridEditor` over the selected module's elements, unbounded and kept from the top left as a submenu's grid is, so the module's box is its elements' bounds (`CustomWidgetData.lattice`); `module.size` follows them rounded up to whole units (`pageSize`), the size a page starts it at, and the popout is the exact `designSize`. A `factory` makes elements instead of overlay modules (`GridEditor.factory`: `make(type, place)`, `size(type)`), and the drag layer names element kinds through `GridDragLayer.describe` and sizes in grid units through `sizeLabel`. A definition with no elements draws `CustomWidgetData.defaultElements`; Start from the default layout copies those into it.

### Import and presets
- **Import from Waybar…** (the list's panel) takes a pasted `"custom/…": { … }` block, a bare `{ "exec": … }` or a whole Waybar config (`CustomWidgetData.fromWaybar`, after `stripJsonc` drops comments and trailing commas): `exec` → `command`; `interval` in seconds → poll, `"once"` → once, none → stream (Waybar reads such a script line by line); `exec-if`, `format`, `format-icons`, `max-length`, `escape`, `tooltip`, the click and scroll actions; `signal` → a `refreshName`. Each custom module becomes a definition.
- **From a preset…**: `CustomWidgetData.presets`, well-known scripts and commands (SwayNC, dunst, Waybar's mediaplayer.py, updates, wttr.in, failed services, WireGuard, NVIDIA load). Their icon maps hold Material Symbols names, drawn as icons (a pick that's a symbol name is the `icon`). Waybar's own icons are usually Nerd Font glyphs, drawn in the text font: they need a Nerd Font installed (fontconfig falls back to one), which axiom doesn't install.
- A script that refreshes Waybar by signal (`pkill -RTMIN+N waybar`) gets a note on the page naming the `axiom ipc customWidgets refresh` call to use instead.

### CommandOutput, folded in
The CommandOutput module is gone: migration v81 (`backend/internal/migrate/steps/v81.go`) turns each one, in any module grid, into a definition (its command polled as plain text every `interval`, escaped so it shows as typed, its click command the click action, `hideEmpty` off) drawn by one Text block filling a module of the place's size (monospace when it was), and the module into a `CustomWidget` showing it. A format-1 config converts to CommandOutput first (`migrate/convert`), then v81 runs on it like any other.
