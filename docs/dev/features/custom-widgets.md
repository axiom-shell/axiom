# Custom widgets

> **Files:** `qml/config/CustomWidgetsConfig.qml`, `qml/services/apps/CustomWidgetsManager.qml`, `qml/services/apps/CustomWidgetsEditor.qml`, `qml/components/views/CustomWidgets/`, `qml/components/methods/CustomWidgetData.qml`, `qml/components/content/CustomWidget/CustomWidget.qml`, `qml/components/content/parts/custom/` (the elements in `elements/<Type>/`), `qml/components/bar/widgets/CustomWidget/CustomWidget.qml`, `qml/config/schema/sections/CustomWidgets.yaml`, `qml/config/schema/definitions/custom/`, `qml/config/schema/definitions/kinds/CustomElementBase.yaml`
> **Config:** `CustomWidgets.items` (reader `CustomWidgetsConfig`)
> **Related:** [Services pattern](../core/services-pattern.md), [Protocol](../backend/protocol.md) (`exec.watch`)

A custom widget is a script drawn as a bar widget, that widget's popout and a module (overlay, desktop, edge menu and, when allowed, the lock screen), all from one definition in `CustomWidgets.items`, so the script runs once for all of them. Its output is read as Waybar reads a `custom/*` module's, so Waybar scripts run unchanged.

### The page
Two `ToolPane`s on a `BaseView` (docs/recipes/tool-page.md): "Custom widgets" on the left (the list and New) and "Custom widget" on the right (an `InspectorHeader` for the selected definition, with hint links "Put it on a bar" (BarEditor) and "Put it on a page" (Layouts) while nothing is unsaved: they only open the page, nothing writes a bar or a page; its Data, Bar, Module and Help tabs, the Data and Bar tabs' groups in `GroupColumns`); the Module tab is two columns: the element column the tab's full height, and beside it the previews, the layer strip, the screen's form and the canvas.

### Definitions
Each item (`definitions/custom/CustomWidget.yaml`) holds:
- the script: `command` (run by `sh -c`), `mode` (`poll` every `interval`, stored in ms and shown in seconds, `stream` one sample a line, `once`), `output` (`waybar`, `json`, `text`), `execIf` (Waybar's exec-if) and `refreshName`;
- `actions`: `items` (the widget's actions, `CustomWidgetAction.yaml`: `id`, `name`, `kind` `command` or `axiom`, `command`, `axiom`, `wait`) and `refreshAfter`; elements pick one in their `run`, the bar in `bar.run` (below);
- Waybar's `format`, `formatIcons`, `maxLength`, `escape`, plus `hideEmpty`, `tooltip`;
- `bar` (the bar widget's style) and `module` (its design size, its base `elements`, its `views` (screens), its `font` for Text elements, whether the lock screen offers it);
- `samples`: a sample output per screen (the screen's id, `""` for no screen), at most 16 entries and 64 KB as JSON, saved in the definition (`x-settings: false`, edited through the Data tab).

The fields, each read from the output's key of the same name (the script shapes its own JSON; nothing maps them): Waybar's `text`, `alt`, `tooltip`, `class`, `percentage`, and axiom's `icon` (Material Symbols), `value` / `min` / `max` / `unit`, `subtext`, `state`, `badge`, `urgent`, `image`, `items` (rows of `{text, icon, value, subtext, id}`) and `hidden`. Plain text that's a number is the `value`; text matching a `formatIcons` key is the `alt`; a format-icons pick that's a Material Symbols name is the `icon` when the output has none.

### Reading an output
`CustomWidgetData` is the pure half:
- `parse`: `waybar` and `json` are both Auto: a JSON object as is, an array as `{text: its length, value: its length, items}`, any other JSON value as `{text, value}` (a string's text is itself, any other scalar keeps the text as printed: `3.10` stays `3.10`), else Waybar's text lines text, tooltip, class (a streamed line is only text); `text` ignores the JSON.
- `elementValue(fields, binding)` (an element's text field, below; with `fields.noSample` an unresolved `{path}` reads empty: the previews with no sample show no braces, while the canvas keeps the template), `ownValue(fields, bind, slot)` (the field when typed, else the output's own), `unknownPaths` (the `{paths}` of a field that read nothing in the sample: the editor's warning) and `rows(v, map)` (a List's rows; `map` is its `row` option: each of text, subtext, icon, id typed text or `{key}` of the item, a key it lacks empty; every row keeps its `raw` item).
- `resolve(definition, sample, context)`: the fields, the format filled (`{}` / `{0}` the text, `{icon}` the format-icons pick, any field or path), `escape` before filling, Pango markup turned into Qt rich text (`pango`), the colour (`stateColor`, see the script contract), `ratio` (the value between min and max; `percentage` alone is a value on 0–100), `hidden` (empty text, as Waybar; never while failing), and `state`, `rev`, `actions` (`actionsOf`), `failure` / `error` (`failure`), `hiddenByScript` (the output's own `hidden`), `interactive` and `noSample`. The `context` is the manager's (`CustomWidgetsManager._context`): the theme's colour names, the script's last run and whether the definition is interactive (`CustomWidgetData.interactive`, below), plus `noScript` for a definition with no script (never hidden, `noSample` set so a `{path}` reads empty); without one `resolve` still works (no colour names, no failure).
- Actions: `actionOf(def, ref)` (an action by id, else by name; null for none), `axiomValues(shellIds, refused, needsArgument, screenIds)` (the values an Axiom action takes: refresh, restart, `screen:`, `screen:<id>`, then the shell's allowed ids), `actionRefs` / `withoutActionRefs` (the triggers naming an action id, in elements of every layer and `bar.run`), `withoutScreen(def, viewId)` (a copy without that screen's Go to actions and the triggers that ran them; removing a screen is one undo step with them), `actionEnabled(actions, item)` (an Axiom action always; no `actions` in the sample: all; else only the ids it lists on), `shellQuote` and `fillCommand(template, {value, rev, tree})` (one pass, each value inserted already quoted: a plain number bare, else single-quoted, empty `''`; a placeholder after `$`, with no value, `{action}` or `{text}` stays as typed), `builtinAllowed(id, refused)` (false for a session or destructive shell action: a bare id), `commandsOf` (the commands Import lists: `command`, `execIf`, each command action as `actions/<name or id>`) and `lockIssues`.
- `truthy` (what a script's value counts as on: `false`, `0`, `no`, `off`, `disabled`, `inactive` and `""` are off; a Toggle reads its state through it), `isThemeColor`, `actionsOf`, `failure`: the rules the script contract names.
- `flatten` lists a sample's paths for the editor's dropdowns.
- Screens: `allElements` (the base and every screen's elements), `matches(when, fields)` (a screen's condition; an empty key never holds), `conditionView(module, fields)` (the first screen whose condition holds), `pickView(module, fields, chosen)` (`{ index, builtinError }`; `chosen` is the manager's Go to screen choice), `historyBindings` (the Sparkline `value` and `value2` bindings of every layer), `series(v, cap)` (a script's list as its finite numbers, the last `cap`; null for a non-list).
- `lattice`, `designSize`, `pageSize`, `rect`: the module's lattice, 4 sub-cells a grid unit (16 a card), the elements' bounds (so the box fits them), laid out proportionally over whatever size the module gets.

### Script contract
What a script prints and how the definition reads it. Output modes (`poll`, `stream` one sample a line, `once`) and formats (`waybar`, `json`, `text`) are as above; Waybar `custom/*` scripts keep working unchanged.

| key | meaning |
| --- | --- |
| `text`, `alt`, `tooltip`, `class`, `percentage` | Waybar's (Pango in `text` / `tooltip` unless `escape`) |
| `icon`, `value`, `min`, `max`, `unit`, `subtext`, `badge`, `urgent`, `image`, `items`, `hidden` | axiom's, as above |
| `state` | the script's **mode name**: matched by screens (`module.views`), its own colour when it is a built-in word (below), and what a Color by state rule can read |
| `rev` | the screen's revision, kept as text; later passed back to an action as `{rev}`, so an action can refuse a stale screen |
| `actions` | `{<id>: {enabled}}`: with it, an action it doesn't list is off; `enabled` is read through `truthy` (`false`, `"false"`, `0`, `no`, `off`, `disabled`, `inactive`, `""` are off; missing is on). Ids that aren't action ids (`^[A-Za-z0-9_.-]{1,64}$`) are dropped |
| `error` | non-empty: the widget is failing (interactive definitions only, below). Plain text (`false`, `0` and other values `truthy` reads as off are no error) |
| anything else | data, bound by path (`player.title`, `items.0.text`) |

- **Colour.** `stateColor(state, classList, colorNames)` is the first that holds: the built-in class map (`defaultStates`: `ok`/`good` success, `warning`/`warn` warning, `critical`/`error`/`urgent` error, `info` info, `active` accent) maps the `state`; the `state` is itself a theme colour name; the map maps the first `class` it knows. **A `state` that is none of these, or a hex, colours nothing.** That is what Auto means on a graphic, a Status, the bar and a Text. Any other word colours through a Color by state rule (see Elements).
- **Interactive.** A definition with screens (`module.views`) or an element whose trigger names a command action (`actions.items` with a `command`: `CustomWidgetData.interactive`) is interactive; an action only the bar's `bar.run` names doesn't count, so a Waybar module with an on-click still hides on exit 1. Only an interactive definition fails: `failure` is, in this order, `start` (the script couldn't start), `stopped` (a stream that ended with a non-zero exit), `exit` (a non-zero exit with no output) or `script` (the sample's own `error`). It carries `kind`, `message`, `exitCode` and `stderr`; `resolve` returns it with `error` (the message) and never hides a failing widget. While it fails, an element's `stateColor` (`CustomElementBase`) is the error colour (`Style.error`), over the state's. A definition without either draws and hides as it always did: exit codes, start errors and `error` change nothing there.
- **Stderr and exits.** An entry carries the run's last non-empty stderr line (300 bytes) and, for a stream that ended with a non-zero exit, `exited`: the exit is published even with no output, so a stream that dies at once (`echo boom >&2; exit 3`) is `stopped` with "exited with code 3: boom". `exited` clears (with the exit code and `stderr`) once the next process has run 1 s. A stream restarts after a backoff; Restart (`axiom ipc customWidgets restart`) doesn't wait for it.
- **No script.** A definition with an empty `command` runs nothing: its format and elements draw at once (`CustomWidgetsManager._resolveNoScript`, `noScript`: no failure, never hidden, `{path}`s empty), and an action still holds and logs its run. `refresh` and `restart` do nothing for it.
- **Lifetime.** A watched command runs only while some bar widget, popout, module or the editor shows its widget (`CustomWidgetsManager._sync`; a stream is killed). A stateful widget keeps its state **outside** the stream (a daemon or a file), and its action commands must not need the stream. An element or bar click always has its widget shown. `invoke`'s `fromIpc` answers `not shown` when nothing shows the widget (shown = an id in the manager's registry; the editor's running definition counts), for the action IPC (`axiom ipc customWidgets act` / `actValue`). Long jobs (an update) detach and report through that state; a command action that waits exits quickly (one that opens an app sets `wait` off).
- cava and other frame-rate streams are unsupported: a stream is coalesced to 4 pushes a second.

### Actions
A definition lists its actions (`actions.items`, `CustomWidgetAction.yaml`) and the places that run one name it by id: an element's `run` (`click` On press, `change`, `on`, `off`, `submit`; the kind's `x-actions` lists the triggers it has) and the bar's `bar.run` (`click`, `rightClick`, `middleClick`, `scrollUp`, `scrollDown`). Ids are made from the name once and never change; `run` holds `""` (nothing) or an id (`ActionId`: the ItemId rule). A trigger with no action does nothing: a Button or List rows aren't pressable, a Bar element is a meter, an Entry keeps its text. An action is one of two kinds:
- **`command`**: runs `command` (one `sh -c` line) with `{value}` (what the element sends: a List row's `id`, else `value` without its unit, else its text, a Toggle's `on` / `off`, a Bar element's released number, an Entry's text; a Button's click and the bar's clicks send none, so there `{value}` is the trigger's argument as one word), `{rev}`, `{tree}` and `{arg}` filled in (`CustomWidgetData.commandLine` over `fillCommand`; values quoted). **The argument** (`args.<trigger>`, `bar.args.<trigger>`, a string, set in TriggerField under the picked command action): split on whitespace (a `"…"` group is one word), `{path}`s filled from the output in each word after the split, each word quoted (`shellQuote`), then put where the command says `{arg}`, else added at the end (not when a trigger with no value of its own has `{value}` already). Nothing in it can end the command or start another, and a filled `{arg}` is never searched again. Axiom actions ignore it (TriggerField hides the row, the text stays). `invoke(id, ref, value, continuous, fromIpc, arg)`; a continuous run waiting holds `{value, arg}`. `wait` (default on, except for an action made from the Bar tab's New action…, which has it off) runs it through `CommandManager.run`, holds the widget (below), logs the exit and, at exit 0, runs the script again when `actions.refreshAfter`; off it starts it detached (`CommandManager.runDetached`: an app) and refreshes after 300 ms, with no hold and no failure.
- **`axiom`**: `axiom` is `refresh` or `restart` (this widget's script), `screen:` / `screen:<id>` (Go to screen, with the screens) or a shell action of `ActionsManager` that takes no argument (`KeybindManager.needsArgument`); never a session action (`ActionsManager.sessionActions`) or a destructive one (`ActionsManager.destructive`): `"refused"`. It is always enabled, never holds and is never refused for another action's hold. `screen:<id>` calls `CustomWidgetsManager.goTo` (an id no screen has is `"refused"`).

`CustomWidgetsManager.invoke(id, ref, value, continuous, fromIpc)` (`ref`: an id, or a name, `CustomWidgetData.actionOf`) runs one and returns `""` or why not: `"no widget"`, `"not shown"` (`fromIpc` and nothing shows the widget: an id in the manager's registry, the editor's running definition counts), `"locked"` (the greeter or the built-in lock up), `"no action"` (none by that id or name), `"refused"` (an Axiom action it may not run), `"no command"`, `"failing"` (the script isn't answering: `start`, `exit`, `stopped`; a `script` failure leaves the sample's `actions` in charge; a screen keyed on `error` keeps its actions: `CustomWidgetData.actionsFailing`, also what `CustomLayout.failing` reads), `"disabled"` (the sample's `actions` don't list it, or list it off) or `"busy"`. The action IPC (`axiom ipc customWidgets act <name> <action>` and `actValue <name> <action> <value>`: `CustomWidgetsManager._ipcAct` finds the widget as `refresh` does and passes `fromIpc`) takes an action's id or name and answers the reason, or an empty line when it ran.
- `act(id, trigger)` (the bar) runs `bar.run[trigger]` through `invoke` (a scroll is continuous, one run per notch: `CustomWidgetData.runShape`); nothing for an empty one.
- In an element, `CustomElementBase.actionFor(trigger)` is the action its `run` picks (from `widgetActions`, which `CustomLayout` passes down), `canRun(trigger)` is false (greying Button, List rows, Toggle and a Bar slider) when actions are off, none is picked, the sample disables it, or a command can't run (`busy`, `failing`), and `runTrigger(trigger, value, continuous)` invokes it and returns the reason. The element's Enabled condition (`enabledWhen`, `CustomElementBase.allowed`, a `CustomShowWhen`) switches it off too, and Entry's field with it. Its label falls back to the click action's name.
- **Hold.** A discrete command action that waits (a Button, List row, Toggle or a bar click) holds the widget's script actions (`CustomWidgetsManager.busy[id]`, `{action, run, phase, until, sampled}`, `action` the id): `"busy"` for another one meanwhile (hold covers the whole widget's script actions, not just the pressed element's), so a double press acts once; actions that don't wait never hold but are refused while one holds. It lasts while the command runs (`holdCap`, 15 s), then until the next sample or a second after the exit (`holdGrace`; a sample that arrived while it ran ends it at the exit); a failing command releases it at once. Each hold carries its run's number, so a late exit of an older run leaves a newer hold alone. A **continuous** run (a bar scroll, a Bar element's slider) never holds: one runs at a time per action and a run with a value (a slider) has the latest value wait, replacing any waiting one; a scroll notch has none: with `wait` off each notch is started and forgotten, with `wait` on each notch runs in turn (the waiting entry counts them, at most 10). Axiom actions never hold; one `Timer` is set to the earliest end. Elements read `busy` through `CustomLayout`, so `canRun` greys them.
- **Failure feedback.** `lastAction[id]` (`{action, failed, exitCode, message, at, run}`; `action` the action's id; the message is the last stderr line, 300 chars, or "The action failed with code N") is what an element reads as `failedRun` (`CustomElementBase`: its own last accepted trigger's action, finished since): its box flashes (`Style.errorWash` through `ColorGlide`, held 1.2 s by a fixed Timer) and says it in its tooltip until it runs again, a Toggle or a Bar slider lets go of the state it held (as it does when the run is refused) and an Entry keeps its text; a failure is also one `console.log` line (a script failing is not a shell problem). The Button's `color` (a theme name, `Style.resolve`) makes it a filled `Surface` with `CustomElementBase.inkOn` for its label and icon (the one place that computes the ink of a data colour; Status uses it too); `disabled: hide` hides it while the script or its Enabled condition has it off.
- There are no keyboard keys any more: `module.keys` is gone, and so is the layout's key handling.


### Running
`CustomWidgetsManager.acquire(owner, id)` watches the definition's command through `CommandManager` (format `json` unless the output is plain text) under its own owner per id; the merge by command string means a widget on two bars and a module still runs one script. Each push whose `CommandManager.runs[command].at` changed is resolved into `fields[id]`, and an edited definition (its format, icons, states: the page's preview) re-resolves its last output at once, without adding to the history; `outputs[id]` keeps the raw text, value, exit code and error for the editor, and `history[id]` the last 60 values of the widget's value and of each Sparkline element's binding. With an `execIf`, the script is watched only once that command succeeds (checked when first shown and on refresh).

An action that doesn't wait runs detached (`{value}` filled in by `fillCommand`, shell-quoted unless a number) and refreshes the script 300 ms later. Nothing runs in the greeter or while the built-in lock screen is up. `axiom ipc customWidgets refresh <name>` (refresh name, id or name) stands in for Waybar's `signal`: a script calling `pkill -RTMIN+N waybar` should call that instead.

A stream is coalesced to 4 pushes a second by axiom (`backend/internal/command/stream.go`), so frame-rate scripts (cava) look choppy. `outputs[id]` also keeps `stderr` (the script's last stderr line) and `exited` (a stream that ended with a non-zero exit; its output is its last line), which come with each push (`CommandManager.runs[command]`) and feed `_context`. `CustomWidgetsManager.restart(id)` (`axiom ipc customWidgets restart <name>`, name as `refresh`) stops a stream's process and starts a new one at once (`CommandManager.restart`, `exec.restart`); a poll just runs again. `_command(def)` is the command a definition's script runs as.

### Screens
`module.elements` is the **base layer**, drawn under every screen (today's elements: no migration); `module.views` adds a layer per screen: `{ id, name, base, when: { key, test, values }, elements }`. `when.key` is a key or path in the output, or `error` for the failure; **empty (the default) means no condition: only a Go to screen action shows that screen**; `test` is `is` / `isNot` (the value's text is, or is not, one of `values`; `isNot` with none never holds, `is` with none never holds; an `error` key's `is` / `isNot` never hold while the widget isn't failing) or `set` / `unset` (the value has text, even `"0"` or `"no"`, or else is truthy: the same "has a value" as an element's Visible). The first screen whose condition holds is drawn over the base (`base: false` hides the base under it); none: the base alone. A **Go to screen** action (`axiom: screen:<id>`; `screen:` the base) records a choice in `CustomWidgetsManager.pages` (`id → {view, matched}`, in memory, per definition): `pickView` draws it until the condition's pick differs from `matched`, or a later Go to screen. It clears on Restart, when the definition goes and when the condition's pick changes (`CustomWidgetData.keepChoice`, checked at each sample and edit; a failure doesn't count), so it doesn't come back when the condition does. A failing widget ignores it: and a definition with neither screens nor elements draws the default icon and text. While the widget fails (`fields.failure`) only screens keyed on `error` are tried, none: the **stock error screen** (an `EmptyState` with the message and, while actions are on, a Restart button running `CustomWidgetsManager.restart`). A definition with screens is interactive, so a script printing no `text` still draws (`hiddenByScript`, not `hidden`, hides an interactive module) while a Waybar script that exits 1 with no output stays hidden. All layers share one lattice (the bounds of every layer, `allElements`), so the popout is sized once.

### Samples
So a screen can be designed before the script reaches it, the definition keeps a sample per screen. `CustomWidgetData.viewKey(module, index)` is the key (a screen's id, `""` for the base alone), `keepSample(samples, key, sample, limits)` returns `{ samples, refused }` (`"count"` for a new key past the entries cap, `"size"` past the byte cap; nothing is changed when refused) and `sampleForView(definition, index, seen, liveFields)` picks the one a screen is previewed with: the kept one, else the last one seen live for it, else the live one when it is what picks that screen. `CustomWidgetsManager.resolveSample(id, sample)` resolves a sample as a successful run would be (`exitCode` 0, so it never fails). `CustomWidgetsEditor.addView` makes a screen with an empty key (and sets the page-only `focusScreenName` for its form), `setViewKey(index, key)` writes the key (`error` also sets test `set` and `base` off, one undo step). The editor keeps `seen` (view key → the last live sample that picked it) and `seenStates` (the distinct `state` values seen, the first 8) for the page only, cleared when another definition is selected; `keepSample()` saves the live sample for the edited layer, `removeSample(key)` forgets one and `previewFields` is what the Module tab's previews draw (a warning line under the screen's form says "No screen for this sample" when the base is empty and nothing picks a screen). Keep sits on the Module tab's previews header (greyed, with the cap's reason as its tooltip, while previewing live); the Data tab's Samples group has the paste or edit button and the list of kept ones. These editor members read the manager only while the page shows (`pageShown`), as the manager creates the editor.

### The module
`qml/components/content/CustomWidget/CustomWidget.qml` is a `Panel`: in a card (`properties.definition`) it fills its slot; as the bar widget's popout (`definitionId` from the anchor's `extraData`) it's the definition's design size at the screen's card size (`OverlayConfig.cardUnitOn`, `GridPlacement.span`), declared up front as `maxImplicitWidth/Height`, since an open popout never resizes. It acquires its definition while shown; actions are off on the lock screen (`host.kind`) and in previews (`host.preview`). It sets no `fullMinWidth`/`fullMinHeight` and has no `compactContent`: its elements are laid out proportionally, so any size draws them (the editor's previews show the usual ones). It builds either the layout or, with nothing to show, an `EmptyState` saying why.

`CustomLayout` (`qml/components/content/parts/custom/`) draws the elements in two layers, each a `KeyedLoader` (key `base` or `v:<screen id>`; nothing built while empty) holding a Repeater by count over the base elements (or `CustomWidgetsConfig.defaultElements` when there are neither screens nor elements) and over `module.views[viewIndex]`'s, each a `CustomElement` (a Loader of `elements/<Type>/Custom<Type>.qml`: prefixed, so an element named after a Qt type, Text, Image or List, never shadows it) at `CustomWidgetData.rect` of its place, a `Widget.px(6)` gap between neighbours.

Element kinds are a schema kind like bar widgets and modules (`index.yaml`'s `kinds.CustomElement`): each `elements/<Type>/schema.yaml` (a `label`, `icon`, `defaultSize` in sub-cells, `slots`, `actions` and its look as `settings`, expanded over `CustomElementBase.yaml` into `<Type>CustomElement`) beside its QML. So its options have their defaults filled at load like any setting, `CustomWidgetsConfig.elementKinds` reads the library from the schema, and the reference is generated (`docs/dev/config/CustomElements/`). The `color` part gives each kind its colours (see Colours below). Each element is a `CustomElementBase` with the element's config, the fields, the history and helpers for its bindings (`value`, `text`, `ratio`, `range`, `colorOf`, `act`, `vertical`: a box taller than wide), drawn with the shell's own pieces. Every element field (`bind`) is typed text or a `{path}` of the output (`elementValue`): empty falls back to the output's own key; exactly one `{path}` alone passes the value itself (a field of `resolve`, else a path in the sample: a list, a number, text; `{text}` the plain text; missing is undefined); other text with a `{` is filled, a `{x}` that is no field and no path staying as typed; anything else is literal (a number when it is one). `=` means nothing special. Button, Toggle, Entry and List have no `label`, `icon` or `placeholder` option any more: they are the `label`, `icon` and `placeholder` fields. A List's `row` option maps a row's text, subtext, icon and the id a press sends (default each the row's own key). A bound Text or Text block value is plain text unless the element sets `markup` (then `pango` draws it); the widget's own `text` and `tooltip` keep Waybar's Pango handling. Their font is the element's `font`, else monospace, else the module's `module.font` (`moduleFont`, passed `CustomLayout` → `CustomElement` → the element), else the shell's.
Every element has a `name` (shown on the editor's canvas; empty: its kind), `showWhen` and its colours. `x-slots` are the kind's own bindings (the base lists none). **Visible** (`showWhen`: `{test, key, value}`, `CustomShowWhen`) hides the element while its test fails (`CustomWidgetData.shown`; `always` by default; `is`, `isNot`, `above`, `below`, `set`, `unset`, `on`, `off` (`on` is `truthy`: false, 0, no, off and empty are off) over a key or path of the output, empty: what the element shows): `CustomLayout` sets `visible`, never unloading, so a value flipping every sample rebuilds nothing. **Enabled** (`enabledWhen`, the same object, a base property shown in the inspector's Runs group for kinds with actions) is the same test over the same keys: while it fails `canRun` is false. Both are edited by `ConditionRows` (page-local). **Colours** are the `color` part's keys (`CustomElementBase.yaml`'s `x-parts.color`: `state` for graphics, Status, List and Separator; `text` for Text and Text block; `button`; `icon`): a colour key (`color`, `background`, `textColor`) names a colour, empty is Auto (or None for a background), and its `<key>States` (`CustomColorStates`: `enabled`, `key`, `rules` `{test, value, color}`, at most 16) turns it into "Color by state": the first rule that holds picks the colour (`CustomWidgetData.colorFor`, `holds` for the tests: `above`/`below` read numbers, `"85%"` is 85), a rule with no colour is Auto, none holding leaves the picked colour. An empty `key` reads what the element shows (`CustomElementBase.own`: the element's first slot, `ownValue`); a List reads each row's own keys (`rowColor`, `state` by default). `CustomWidgetData.colorFields` pairs the colours with their `…States` for the editor (`CustomWidgetsConfig.elementKinds`' `colors` and `lookOrder`). `CustomElementBase.colorFor(key, auto)` resolves one colour (`colorOf` is `color` with the script's state colour as the Auto, so Ring, Bar, Segments, Sparkline, Icon, Text and Status follow it); the Button draws one `StyledTextButton` (Auto is the tonal button; a background fills it, its ink reading on it unless Text color is set) and the Icon a background `Surface`. `resolve` hands `colorNames` on, and `elementValue` never reads it, `actions`, `interactive` or `failure` of `resolve` as an output key (a sample's own key of that name binds to the sample's).
- **Place and Size** are shared parts (`CustomElementBase.yaml`'s `x-parts.place` and `size`, picked in a kind's `schema.yaml`): an element whose drawing is smaller than its box gets **place**, `align` (Across: Left, Center, Right) and `valign` (Down: Top, Middle, Bottom; Entry has only Down), and one that draws text or a glyph gets **size** (`auto` is "Fit", `small`, `normal`, `large`, `huge`). `CustomElementBase` turns them into `placeX(w)`/`placeY(h)` (`CustomWidgetData.alignOffset`), `hAlign`/`vAlign`, `fixedTextSize` (`Style.typeCaption`, `typeBody`, `typeHeadline`, twice `typeBody`), `fixedIconSize` (`iconSm`…`iconXl`) and `textSizeFor(boxH)`. **Fit has no cap**: text is four fifths of the box (never below `Style.typeMicro`), an icon three quarters of the short side, a Button's label two fifths of its height; the fixed sizes follow the shell's type scale, not the box, and `CustomWidgetData.textLines` works the lines a box holds from the size drawn, so a size too big for its box elides on line one instead of being cut. Markup can't be fitted and is drawn at the one-line size from the box. `inset` (0, `Widget.px(4)` once a Text has a background) is the only padding.
- Text and Text block both draw `CustomTextBody` (place `both`, size `text`; Text defaults to centre, middle, Fit; Text block to left, top, Normal): Fit wraps, shrinks, then elides; a fixed size on the Text block scrolls (the text is at least the viewport tall, so Down applies while it is short). Monospace is drawn plain with no wrapping (rich text keeps its runs of spaces with `white-space:pre`). Icon (place and size `icon`; Material name or the format-icons glyph, a `CountBadge`), Button (size; one `StyledTextButton` for every look), Status, Ring and Gauge (place: the ring is the box's short side), Image (place applies to a Round picture) and Entry (Down: it keeps its own height in a taller box). A Bar, Segments, Sparkline, Separator, List and Toggle fill their box and have neither.
- Ring and Gauge (`PercentageCircle`, `sweep` 360 or 240; the value inside carries the output's `unit`), Bar (a `LevelMeter`, or a `StyledSlider` with a change command, holding the released value until the next sample), Segments (`SegmentMeter`), Sparkline (`Sparkline`, between `CustomWidgetData.graphRange`'s min and max: a list the script prints, in the `value` binding or a path, is the series itself, `CustomWidgetData.series` keeping the last 240 numbers, drawn at once and after a restart; a number is graphed from the service's history, which skips list bindings. `value2` is a second series the same way, drawn as a line in `Style.series[1]` on the one range; `style` is `line` or `bars`). Value, min and max are slots (`CustomWidgetData.elementRange`: bound, or the output's own `value`/`min`/`max`).
- List (rows `{text, icon, value, subtext, id, state, max, image}` (`CustomWidgetData.rows`) in a ListModel updated in place, drawn as `CustomListRow`s (an `ItemRow` with a thumbnail from `image`, via `CustomElementBase.imageUrl`, which the Image element shares) down the element, or with `orientation: horizontal` as `CustomListTile`s (icon or image over text over subtext) of equal width, none narrower than `Widget.textPx(56)`; the colour rules tone a row's icon and meter (`rowColor`), and a numeric `value` shows beside the row followed by the item's own `unit` (`CustomWidgetData.rowValueText`: "84%"), and with a `max` above 0 draws a `LevelMeter` under it; the row files sit beside `CustomList.qml`, so `CustomElement` imports that folder for qs to scan it; a click runs the click action with the row's id, else its value (the number, without its unit), else its text: `CustomWidgetData.rowKey`), Image (`ClippingRectangle`), Button (`StyledTextButton`; its label from the action's name when it has none and no icon: an icon alone stays a bare icon), Toggle (a `StyledSwitch` beside its label or an `ActionPill`; holds its new state until the next sample), Entry (a `StyledTextEntry`: Return runs its submit action with the typed text as `{value}`, then clears the field unless `clear` is off (an empty Return does nothing; an action that waits clears it once it finished without failing); `run` refusing it (a hold, a failing script, an action the sample turned off) keeps the text and the focus, as does an Entry with no submit action (nothing ran), and the field stays enabled during a hold; it never takes its text from a sample and is off where the host can't take keys: `CustomWidget.keysHost`, true in a popout, an overlay card and an edge menu, is passed `CustomLayout` → `CustomElement` → the element; a popout holding an Entry sets `wantsKeyboardFocus`, so it keeps the keyboard and a click outside closes it), Status (a `StatusChip` or a dot), Separator (`SeparatorMark` with the Separator bar widget's style, thickness, length and colour; its style is the shared `SeparatorStyle`). The List's Size (the shared `text` size part: Fit, Small to Huge, default Normal) scales the whole row as one (`CustomList.zoom`: the shell's text size over the body size; Fit grows the rows to the box, never below Normal).

The module library offers each definition by itself (`OverlayConfig.customModuleTypes`, group Custom, A–Z by name), keyed `CustomWidget:<id>`; `GridEditor._newModule` turns the key into `{type: "CustomWidget", properties: {definition}}` (`CustomWidgetsConfig.splitKey`), and the definition's design size is where it starts. The lock screen's library lists only definitions with `module.lockscreen`, and a module there whose definition lacks it (switched off after placing, or picked in its settings) runs nothing: its `widgetId` is empty and it says the widget isn't offered there.

### The bar widget
`qml/components/bar/widgets/CustomWidget/CustomWidget.qml` is a `BarWidget` (the built-in widgets' display styles, [Display styles](../bar/display-styles.md); `bar` extends their `BarDisplay` settings) drawing the definition's `bar.style`: `label` (icon and the format filled, as plain text: Waybar's look), `icon` (the icon alone), `ring`, `fill` (`LevelMeter`), `segments` (`SegmentMeter`), `sparkline` (a graphic in `IconTextRow`'s `lead` slot, `leadLength` long, before the icon), `pill` (the widget's background filled to the value: its `backgroundLevel`, which its background's `LevelFill` draws in the background's own shape, so it keeps the bar's caps and radius), `ticker` (the text, as long as it is up to `bar.width`, scrolling past that) and `stacked` (the text over the subtext), both after the icon where a label goes (`IconTextRow.leadAfterIcon`); a vertical bar turns the ticker along it, as its label is, and draws stacked as a label. The status colour is the base's `stateColorName` (the guard's one exception, T8: a script names it): the error while failing, else `bar.color` (empty: Auto, the script's state colour) or a rule of `bar.colorStates` (`CustomWidgetData.colorFor`, `attentionLevel` reads the result), so the bar's widget style shows it (a fill, tint, outline or the icon); the graphics draw in `colors.icon`, which reads on a filled background; `urgent` pulses it; `hidden` hides it. While the script fails (`fields.failure`) the widget shows the `error` icon and a short "Error" label in the error colour, whatever its style, and the message as its tooltip (the module and popout show it whole). Clicks and scrolls run the definition's actions; hovering opens the CustomWidget popout (`extraData: {definitionId}`) while `bar.popout` (off by default: a script's text usually needs none) and the widget's own popout are on (`popoutOpens`); otherwise, with the definition's `tooltip` on (its switch is greyed while `bar.popout` is), it shows the output's `tooltip` field as Waybar does, rich text (Pango converted) in a `BarToolTip`.

The bar editor's library is `BarsConfig.libraryWidgetTypes`: the types without CustomWidget, then one entry per definition (`CustomWidgetsConfig.libraryEntries`, keyed `CustomWidget:<id>`), which `BarManager.addWidget` splits back into the type and its definition; a placed one's chip goes by the same key, so it's named after its definition.

### The page
The Custom widgets tool page (`qml/components/views/CustomWidgets/`, `/widgets` in the launcher) edits `CustomWidgets` through `CustomWidgetsManager.editor` (`CustomWidgetsEditor`: a `ConfigDraft`, `selectedIndex` / `selectDefinition`, `elements` (a `GridEditor` over the selected module's elements), `tab`; registered in `EditsManager`). The layer being edited is `viewIndex` (-1 the base, else a screen; `layerPath()`, `layerElements`, `element`, `selectView`, `addView`, `removeView`, `setView`): the element grid, its undo history and `setElement` work on that layer's elements (`elements.scopeKey` includes the index, so switching layer starts the history over), `_fitSize` sizes the module over every layer, and Start from the default layout is offered only on the base of a definition with no screens. Edits show live on the bars and pages through `ConfigManager.setPreview("CustomWidgets", …)`, and the selected definition stays acquired while the page is shown (`pageShown`), so its sample is there to bind from.

A definition with no elements draws `CustomWidgetData.defaultElements` (an icon, or a ring with a value, and the text left-aligned against it, as a built-in figure sits); Start from the default layout copies those into it.

### Sharing
Custom widgets never travel in a community setup or a look-only export: the `CustomWidgets` section is `x-scope: personal` (its commands `commands`), and the bar `CustomWidget` widget and the `CustomWidget` module are `personal` too (each type's `schema.yaml` `scopeIf`), so a shared look can't hold one that points at a definition it lacks, and the setups' CI refuses a file holding either. Export with personal on keeps them with the section; applying a shared file keeps the user's own. The overlay page type `Custom` is a different thing and isn't affected.

### New, Import, Copy and presets
- **New** (`DefinitionsPanel`'s one button opens a `StyledContextMenu` chooser): *Bar text from a script* (a blank definition, bar style Label, on the Data tab: `editor.addBlank`), *Interactive card* (opens `GalleryForm` in the inspector pane: a `TileFlow` of `CustomWidgetData.galleryPresets`, each drawn by a `CustomLayout` from its own first sample through `CustomWidgetsManager.resolveFor`, so it previews before its script has answered; a click `addTemplate`s it and opens its Module tab at the first screen), *From a known script* (a submenu of `CustomWidgetData.scriptPresets`, on the Data tab) and *Import a widget…*. Each ships a sample per screen, so it previews before its script has answered. `editor.add` strips `template`, `demo` and `description`.
- **The demo script** (`data/custom-widgets/demo.sh TEMPLATE VERB [ARG]`, bash, `set -u`): `show` prints the template's JSON (poll, 10 s; the list 60 s), the other verbs change its state and print nothing. State is small files in `${XDG_STATE_HOME:-$HOME/.local/state}/axiom/custom-widgets-demo/` (temp file + `mv`; never under the tree). **Toggle** (Focus mode): `on` / `off`, the Toggle sends them and the screen's icon follows. **Slider** (Desk lamp, 50 at first): `set N` takes a number, truncated to a whole 0–100 (a bad value exits 2). **List**: the mounted disks from `df -P` (tmpfs, devtmpfs, squashfs, overlay and efivarfs left out), `text` `N disks`, a row `{id: mount, subtext: "<n> GB free", value: percent used, max: 100, state: full (90 and over) | ok}` coloured by its `colorStates`; the row's `open` action runs `xdg-open {value}` (`wait` off, no script). **Media card**: three fixed tracks and `playing` / `paused` / `stopped`: `toggle` flips (a stopped one plays), `next` past the last stops, `prev` from stopped plays the last; the "Nothing playing" screen carries a Play button (`toggle`), since that screen hides the base. **Status**: `break` makes the output `{error, state: down}` with exit 0 (a `script` failure, so its actions stay on), `fix` makes it ok again, and the error screen has Fix it and Restart (an Axiom action). - **Copy** (the share button in the inspector's header, beside Duplicate, which keeps its plain tooltip): `ClipboardManager.copyText(CustomWidgetData.exportOf(definition))`, T30's wrapper `{"axiomCustomWidget": 1, "definition": {…}}` with everything but the id (screens, samples and commands included). A note under the header says "Copied. Nothing is added or run before Import (`editor.importDefinitions`: each definition through `add` with a fresh id and its texts as they are). `fromWaybar` takes a pasted `"custom/…": { … }` block, a bare `{ "exec": … }` or a whole Waybar config (after `stripJsonc` drops comments and trailing commas): `exec` → `command`; `interval` in seconds → poll, `"once"` → once, none → stream (Waybar reads such a script line by line); `exec-if`, `format`, `format-icons`, `max-length`, `escape`, `tooltip`, the click and scroll actions; `signal` → a `refreshName`. Each custom module becomes a definition.
- **Action log.** `CustomWidgetsManager.actionRan(id, entry)` (`{at, action (the id), name, command, exitCode, ms, stderr, refused, detached}`: when an action command ends, when one that doesn't wait starts (`exitCode` -1), and for each refusal `invoke` returns) feeds `editor.actionLog` (the last 20 of the selected definition, page-only, cleared on `selectDefinition`), shown as `ActionLog` under the test preview and on the Data tab.
- **Help** (the page's fourth tab, `CustomWidgetsHelp`; also the empty pane's "How custom widgets work"): a guide per task first (`task-bar`, the default, `task-button`, `task-color`, `task-list`, `task-screens`, `task-place`, `task-share`: 3–6 numbered steps naming the real controls), then the reference: the script contract as a table, text fields and `{paths}` (`text`: each kind's own bindings from the schema; the inspector's "More in Help" opens the section its kind names, `x-help` in the kind's `schema.yaml`: `task-list`, `task-button`, `actions`, else `text`), actions and their placeholders, example scripts with Copy, lifetime, failure kinds and Waybar notes, one section open at a time (`editor.helpSection`, set by `openHelp(section)` from the Data tab's link and the inspector). It mirrors Script contract above: change both together.
- **Icon theme icons.** An Icon element's `source: theme` and a List's `iconSource: theme` draw the name as a picture of the desktop icon theme (`CustomElementBase.themeIcon` over `AppIconManager.appIcon`, in a `Thumbnail`; a List row's own `image` wins).
- **Confirm.** A Button or List with `confirm` asks first: the first press says "Confirm?" (a Button in the danger look, a row in the error colour) for a fixed 3 s and the second runs it.
- **From a known script**: `CustomWidgetData.scriptPresets` (the presets with a command), well-known scripts and commands (SwayNC, dunst, Waybar's mediaplayer.py, updates, wttr.in, failed services, WireGuard, NVIDIA load, and the interactive starter Daily habits, below). Their icon maps hold Material Symbols names, drawn as icons (a pick that's a symbol name is the `icon`). Waybar's own icons are usually Nerd Font glyphs, drawn in the text font: they need a Nerd Font installed (fontconfig falls back to one), which axiom doesn't install.
- **Daily habits** (the starter no built-in widget replaces: it shows what a stateful, interactive widget is). `data/custom-widgets/habits.sh` is both its poll script (`show`, every 60 s, JSON: `state` `empty` / `open` / `done`, `text` `2/5`, `value` / `max`, `items` `{id, text, icon, subtext: "N days", state: "done" | "open"}`, `actions`: `add` always, `check` and `remove` with habits, `undo` while there is something to undo) and its actions' commands (`do check ID`, `do add NAME`, `do remove ID`, `do undo`; no element sends `remove`, so delete a habit with `axiom ipc customWidgets actValue <name> remove <id>`; a bad id or name exits 2 with a `habits:` line on stderr). The habits live in `${XDG_STATE_HOME:-$HOME/.local/state}/axiom/habits.tsv` (id, name, last day done, streak; `-` for never; `habits.tsv.prev` is what undo restores), so they survive closing the overlay and restarting qs; changes take an `mkdir` lock (`habits.tsv.lock`, broken after 5 s, and given up on after 10 s with exit 2, as when the state folder can't be written; no `flock`, which no package here depends on) and write a temp file and `mv` it in. Its `command` and its actions' commands hold `{tree}`, which `CustomWidgetsManager._expand` fills with `Paths.treePath` at run time through `fillCommand` (also in `execIf` and the action commands; a shell `${tree}` stays): config never holds an install path, and a dev or nested tree runs its own copy. The preset's module: a title, the count (coloured by `state` through its `colorStates`) and an Undo Button (`disabled: hide`, `run.click` `undo`) in the base layer, an Entry (`run.submit` `add`) below, then a screen per state: `open` a List (`run.click` `check`, rows coloured by `state` through the List's `colorStates`), `done` a check icon and "All done today", `empty` "Add your first habit below"; each screen has a sample. Its four actions (`check`, `add`, `undo`, `remove`) all wait. `CustomWidgetsEditor.add` runs a preset through `translated`: its action names, typed element labels and placeholders and screen names go through `I18n.tr` (keys listed in `presets`' comment). `tests/scripts/test_scripts.py` › `HabitsScript` runs the script; `shellcheck` covers `data/custom-widgets/*.sh`.
- **One undo history.** `editor.elements` (a `GridEditor` with `historyKey` the definition's id, not its per-screen `scopeKey`) keeps one history per definition: each snapshot holds the whole definition and the screen being edited (`_definitionSnapshot`), so Undo from another screen goes back to the screen the edit was on (`_restoreDefinition`) and puts every layer back. Adding, removing, duplicating and moving screens, removing an action, moving an action (`moveAction`, the up and down buttons of its row; ids unchanged) and Start from the default layout are one step each (`_recordStructure`); Duplicate selects the copy, Move keeps the screen selected. The Undo/Redo pair is in the right pane's header (`TitledCard.headerTools`), for every tab; the canvas's own pair is hidden here (`GridCanvas.showUndo`).
- **Changed marks.** The Data, Bar and inspector forms pass `changedAt` and `discardAt` to their `SchemaPropertiesForm`s (`editor.changedAt` / `discardAt` over the saved definition, `elementChangedAt` / `discardElementAt` for an element's options, found by id in the same layer), and the tabs carry a dot while a key they hold differs (`CustomWidgetData.changedTabs`: Data, Bar, Module; none for a definition never saved).
- **Copy.** An element's header has **Copy to screen** (a menu of `ElementEditorLayout.copyTargets`). A right click on a tile of a box selection keeps the group and its menu adds **Copy look to the selected** (`copyLook`: `CustomWidgetsConfig.lookKeys` of the target, its colours with their By state rules and `align`, `valign` and `size`, through `CustomWidgetData.withLook`, one undo step); Duplicate, Copy to screen and Remove act on the clicked element alone.
- **Room for the hover.** A row's tint reaches `Style.rowBleed` past its sides: the cards pad their rows by `Style.space3`, so it lies inside the scroll view that clips it (`tests-layout/tst_GroupCards.qml` asserts it for a card straight in a `StyledScrollView`).
- A script that refreshes Waybar by signal (`pkill -RTMIN+N waybar`) gets a Notice (warning) on the page naming the `axiom ipc customWidgets refresh` call to use instead.

### CommandOutput, folded in
The CommandOutput module is gone: migration v81 (`backend/internal/migrate/steps/v81.go`) turns each one, in any module grid, into a definition (its command polled as plain text every `interval`, escaped so it shows as typed, its click command the click action, `hideEmpty` off) drawn by one Text block binding `{text}` and filling a module of the place's size (monospace when it was), and the module into a `CustomWidget` showing it. A format-1 config converts to CommandOutput first (`migrate/convert`), then v81 runs on it like any other.

### Older configs
Migration v111 (`backend/internal/migrate/steps/v111.go`) rewrites definitions saved by v1.2.1 (`CustomWidgets.items[]`, their `module.elements` only), once: a definition whose `actions.items` is already an array is skipped, and every one it changes gets that array (empty when no action was made), which keeps a second run from wrapping the moved labels again. In order: bare-word bindings become `{word}` (numbers, formats and values with `}` or `:` stay); Button `options.label` / `options.icon` and Toggle `options.label` move into `bind` (a bound slot wins); each bar command (`click`, `rightClick`, `middleClick`, `scrollUp`, `scrollDown`) and each element command that ran on v1.2.1 (Button and List `click`, Toggle `on` / `off`, Bar `change`) becomes a command action with `wait` off (as the old detached run), pointed at by `bar.run` or the element's `run`; the same command is one action, a Button without a command takes the bar's click, and a `{value}` command gets its source (a Button's `args.click` its old `bind.value`, else the label (`bind.value` is deleted: a Button has no Value now), a List's `options.row.id` `{text}`); `states` and Text's `stateColor` become `colorStates` rules (user words first, then the built-in ones for Text, at most 16); a Button's `bind.enabled` that is exactly one `{path}` becomes `enabledWhen: {test: on, key: path}`, any other text is dropped (change line "enabled: not a value, dropped"). Left as they were: Fit sizes and the Text block's caption size (the new look is the point), `class`-only matches of user words, a theme-name `state` on a Text, a label holding `{`, and stack-only shapes (exports made by Copy, which `fromExport` does not migrate).

Where you were survives the overlay closing and reopening in the same shell session (in memory, `CustomWidgetsEditor.ensureLoaded` with `CustomWidgetData.restorePlace`): the definition (by id), the tab, the screen and the selected element; one that no longer exists falls back to the first definition, the base elements and no selection. Unsaved edits were already kept.
