# File search

> **Files:** `backend/internal/filesearch/`, `backend/internal/fileindex/`, `backend/internal/procprio/procprio.go`, `backend/internal/thumbnail/`, `backend/internal/mimeapps/globs.go`, `backend/internal/daemon/filesearch.go`, `backend/internal/cli/filesearch.go`, `qml/services/apps/FileSearchManager.qml`, `qml/services/ui/LauncherFiles.qml`, `qml/components/methods/FilePaths.qml`, `qml/components/surfaces/launcher/LauncherRow.qml`
> **Config:** `Launcher.providers.files.*` (reader `LauncherConfig`: `files`, `fileRoots`, `fileShowHidden`, `filesInSearch`, `fileThumbnails`)
> **Related:** [Launcher](launcher.md), [Launcher providers](launcher-providers.md), [Default apps](default-apps.md), [protocol](../backend/protocol.md)

The launcher's files: `~` (or `/files`) searches them, `~/` browses folders, `~` alone lists the recent files, and the main search shows the best few below the apps. The axiom daemon keeps its own index of the folders searched, current through inotify, so a search is a scan of memory, not of the disk. One rule shapes all of it: **building and keeping the index never slows anything down** (the maintainer, 2026-11-08: "The only concern I have is that building the index cannot slow anything down").

### What the user gets
- `~report` searches every folder searched; `~/Documents/` lists a folder from the disk; `~/Documents/rep` searches below it; `~` alone, the recent files (`recently-used.xbel` and what the launcher opened).
- **Matching:** smart case (an upper-case letter makes the token case-sensitive), every space-separated token must match, and fzf's folder segments (`doc/rep` is `rep` in a folder matching `doc`, `doc/` anything below one). A query or folder starting with `.` shows hidden entries.
- **Enter** opens the file with its default app (`DefaultAppsManager.open`, [Default apps](default-apps.md)), **Shift+Enter** shows it selected in its folder, **Ctrl+C** (nothing selected in the field) copies its path, **Tab** types its path (a folder's lists it).
- Pictures show their thumbnails (`Launcher.providers.files.thumbnails`), shared with the file manager's.
- **Settings** (`Launcher.providers.files`): `enabled` (on), `inSearch` (files in the main search, 0–5, 3), `thumbnails` (on), `showHidden` (off), `roots` (`["~"]`, `x-scope: machine`), `excludes` (names or path tails, `*` globs: `.git`, `node_modules`, `.cache`, `target`, `go/pkg`, `.local/share/Trash`, `*.pyc`, …). The daemon reads `enabled`, `roots`, `excludes` and `showHidden` itself (`fileSearchSettings`, a `~` in a root is `$HOME`); the shell reads `inSearch`, `thumbnails` and `showHidden` (for browsing).

### No slowdown: where the work runs
- **The crawl runs in a child process, never in the daemon:** `axiom index-crawl` (hidden; `fileindex.RunChild`, `/proc/self/exe`, the request as JSON on stdin, never in argv). Before it reads anything it lowers every thread in `/proc/self/task` (`procprio.Idle`) to `SCHED_IDLE` (CPU only when nothing else wants it) and the idle I/O class (`ioprio_set`: the disk only when it's idle); threads made later inherit both. Failing to lower itself fails the crawl: it never runs at normal priority. It runs with `GOMAXPROCS=1`, `GOGC=20`, an empty environment and its own process group (killed whole on disable or shutdown).
  - Why a process and not an idle thread: the daemon's garbage collector stops every thread, so an idle-priority thread starved by a busy CPU would hold every shell RPC through the collection. A child has its own runtime.
- **It walks breadth first** and streams one folder per binary frame on stdout (`fileindex/wire.go`: a length, a kind, the folder's path, time and entries; the daemon reads names straight from the frame, allocating nothing per entry). It sleeps 10 ms every 128 folders (`Options.Pause`), never follows a link (but a root), never crosses onto another device, always skips `/proc`, `/sys`, `/dev`, `/run`, `$XDG_RUNTIME_DIR` and `~/.cache/thumbnails`, and stops at `MaxEntries` (500k, at most 2M; `truncated` in the state).
- **The daemon only applies frames**, at normal priority, taking the write lock for one folder at a time (microseconds), so searches (read lock) never wait. The idle child holds nothing the daemon needs: no priority inversion.
- **Watching:** raw inotify through `golang.org/x/sys` (`fileindex/watch.go`; fsnotify exports neither flag), each folder watched with `IN_DONT_FOLLOW | IN_ONLYDIR` (and `IN_EXCL_UNLINK`). The **watch budget** is a quarter of `/proc/sys/fs/inotify/max_user_watches`, at most 64k, since that limit is shared with editors, syncthing and the rest. A watched folder's events are debounced 50 ms (500 ms at most for events that never stop) and the folder is read again in the daemon (one folder: small). A lost queue (`IN_Q_OVERFLOW`) checks every folder.
- **The stat pass** checks the folders past the budget: a folder's mtime changes when an entry in it is added, removed or renamed. It runs in the same child (`CrawlRequest.Stat`: the folders and their times on stdin; paced too, every 1024 folders checked), every 10 minutes and on a search after a quiet minute; folders it finds new are crawled next.
- **The cache** (`$XDG_CACHE_HOME/axiom/fileindex.bin`, 0600 in a 0700 folder; `filesearch/snapshot.go`): magic, version, the settings' key (roots, excludes, hidden, the cap), the entries breadth first, and a CRC32. Written atomically at most every 5 minutes, never while a crawl runs; a bad or foreign one is removed and the index built again. It loads 20 s after the daemon starts (or at the first search, if sooner), so nothing competes with the session's start, then a stat pass over every folder catches what changed while nothing watched. Turning file search off drops the index and deletes the cache; other roots or excludes drop it and wait for the next search.
- **Lazily started:** with no cache, the first search starts the crawl (`phase` `waiting` → `crawling` → `ready`); results grow as it goes.
- **Newest wins, without a cancel:** each `filesearch.query` carries an id that rises per connection; the daemon keeps the connection's newest (`queryKey`, gone with the connection), an older query answers `stale` with no items, and a scan replaced mid-way stops within 16k entries (`staleEvery`).
- **Thumbnails are made in a child too:** `axiom thumbnail` (`thumbnail.RunChild`) at nice 10 and the lowest best-effort I/O level (`procprio.Background`), with a 512 MiB Go memory limit, since a 50 MP image decodes into ~200 MB that must not land in the daemon's heap. At most 2 run at once (`maxRunning`), one per file however often it's asked, 30 s each.
- **The shell's side:** nothing is polled (the state is pushed); a keystroke sends one RPC (a search, a listing or the recent files) and nothing else; thumbnails are asked only for rows the list has built, at most 4 at once; answers to anything older than the newest asked are dropped by id.

### The index (`filesearch`, pure)
- **No pointers:** one byte arena of names and fixed 32-byte entries (name offset and length, parent index, mtime, flags, a character-class mask), plus a folder map by path. A million Go strings would make every collection scan a million pointers; this costs the collector nothing (about 22 MB at 500k files). Removals are tombstoned and compacted once they pass a quarter (built without the lock, swapped under it).
- **Matching** (`match.go`): the mask prefilter skips most entries cheaply; `Score` is the Go twin of `Search.score` (100 exact, 80 prefix, 65 word start, 50 inside, 5–30 letters in order), so files rank against apps fairly in the main search.
- **Ranking** (`rank.go`): the match (a folder's counting 0.6), less 1 per level below the root (at most 10), plus recency (10 within a day, 6 a week, 3 a month) and the use bonus (`Search.useBonus`'s twin over the launcher's history), less 5 for a hidden entry. The scan is split over `GOMAXPROCS` shards, each keeping its top K; only the top results cross the socket. The use bonus by entry is resolved at most every 2 s.
- **Recent files** (`fileindex/recent.go`): `recently-used.xbel` (only read, never written) merged with the launcher's own history (`$XDG_STATE_HOME/axiom/launcher-files.json`, 0600, written by `filesearch.used`).
- **Results' types** (`fileindex/meta.go`): shared-mime-info's globs through `mimeapps.Globs` (a plain `*.ext` map, the slow patterns apart, loaded once), its icons most specific first.

### RPC (every method the shell's alone)
- `filesearch.get {}` → the state `{ phase: off|waiting|loading|crawling|ready, entries, watched, unwatched, unreadable, truncated, error }`; pushed as `filesearch.state` (latest-wins, at most every 500 ms while it changes; the `fileSearch` hello topic).
- `filesearch.query { id, query, dir, limit, hidden }` → `{ id, items, stale, indexed }`; `indexed` is false while there's no index yet or for a `dir` it doesn't hold. limit 50 by default, 200 at most.
- `filesearch.browse { path, query, limit, hidden }` → `{ path, items, total }`, read from the disk (works while the index builds, and outside the roots), folders first, or best matching `query`; limit 200 by default, 1000 at most.
- `filesearch.recent { limit }` → `{ items }`; `filesearch.used { path }` records an open.
- `filesearch.thumbnail { path, size: normal|large }` → `{ path, failed }`.
- `filesearch.reveal { path }` → `{ via: showItems|folder }`: `org.freedesktop.FileManager1.ShowItems` on the session bus (Nautilus, Dolphin, Thunar, Nemo select the file), else its folder opens through `openTarget` (shared with `apps.open`).
- An item is `{ path, name, dir, link, mime, icons, size, mtime (ms), score }`; `dir` is a folder or a link to one.

### Thumbnails (`thumbnail`)
- The freedesktop spec: `$XDG_CACHE_HOME/thumbnails/{normal,large}/<md5 of the file URI>.png` (128 or 256 px), valid while its `Thumb::URI` and `Thumb::MTime` match the file, so a file manager's (videos, PDFs) are reused and axiom's are shared back. axiom makes them only for png, jpeg, gif, webp and bmp (`golang.org/x/image` for the last two), refusing over 50 MP or 64 MiB; an SVG under 1 MiB is its own thumbnail. A failure is recorded under `fail/axiom-1/` and not tried again until the file changes. Files are written atomically, 0600 in 0700 folders.

### The shell
- **FileSearchManager** ([Launcher providers](launcher-providers.md) › FileSearchManager): the calls, the state, icons and the thumbnail queue.
- **`FilePaths`** (pure, `tests/tst_FilePaths.qml`): `parse(text, home)` turns the text into `{ kind: recent|browse|search, dir, typed, query }` (`~/a/` lists `a`, `~/a/rep` searches below it, `~/a` searches `a` below home, `..` resolved), `completion(path, home, isDir)` the text Tab types (through `..` outside home), `under(path, roots)`, `join`, `parentOf`, `thumbnailable(mime)` (images, videos, PDFs).
- **`LauncherFiles`** (LauncherManager's part): `rowsFor(text)` for `~` mode and `mainRows(q)` (from two characters, `inSearch` of them; none at 0) return the newest answer's rows and ask once per new text; `updated` tells LauncherManager, which sets the rows without searching again. Until an answer lands the previous text's rows stay, so the list doesn't flicker. A search below a folder goes to the index once it's `ready` and the folder is under a root; otherwise (or when it answers `indexed: false`) the folder's own entries are listed instead. While the index builds, a last row says "Indexing… {0} files", and a shown search asks again on each state push until an answer from the built index lands. Closing the launcher forgets the answers (`LauncherManager.shown`).
- **Rows:** `{ kind: file|folder, image (the type's icon), glyph, thumb, mtime, title, subtitle (the folder, size and date), hint, complete, run(shift), copy() }`; `LauncherRow` shows the thumbnail cropped once it lands ([Launcher](launcher.md) › Row shape).

### Security and privacy
- Links are never followed out of the roots; the crawl stays on each root's device. Unreadable folders are skipped and counted (`unreadable`).
- The index, the cache and the history stay out of config.json; the cache and the history are 0600 in 0700 folders. Logs carry counts, never file names. The crawl's and the thumbnail's requests go on stdin.

### Testing
- Go: `go test ./internal/filesearch ./internal/fileindex ./internal/thumbnail ./internal/procprio`, and `go test ./internal/daemon -run FileSearch`: the crawl child's threads read back as `SCHED_IDLE` and the idle I/O class (`TestChildRunsIdle`, `TestLowersEveryThread`); a query and an unrelated call answer within budget while a paced crawl runs (`TestFileSearchAnswersDuringACrawl`); newest wins (`TestFileSearchQuery`); reveal against a fake FileManager1 and its fallback; a budget of 2 leaving folders to the stat pass. `go test -bench Search1M ./internal/filesearch` times a search of a million entries.
- QML: `scripts/run_tests.sh FilePaths`.
- Live: a nested axiom (`scripts/dev/nested.sh niri`, its config's `roots` on a scratch folder), then `axiom ipc appLauncher search "~report"`, `"~/Documents/"` and `"~"` through its socket, and a screenshot. A thumbnail made lands in the scratch `XDG_CACHE_HOME`'s `thumbnails/normal`.
