# OSD (on-screen displays)

> **Files:** `qml/config/OSDConfig.qml`, `qml/shell/OSD.qml`, `qml/components/surfaces/osd/OSDHost.qml`, `qml/components/surfaces/osd/OSDTriggers.qml`, `qml/components/surfaces/osd/design/`, `qml/components/surfaces/osd/engine/OSDSystem.qml`, `qml/components/surfaces/osd/engine/OSDWatch.qml`, `qml/components/surfaces/osd/engine/OSDSystemHost.qml`, `qml/components/surfaces/osd/systems/`, `qml/components/methods/OSDEngine.qml`, `qml/components/methods/OSDParts.qml`, `qml/components/views/Settings/OSDListCard.qml`, `qml/components/views/Settings/OSDSystemsEditor.qml`, `qml/config/schema/definitions/kinds/OSDSystemBase.yaml`, `tests/tst_OSDSystems.qml`, `tests/tst_OSDEngine.qml`, `tests/tst_OSDParts.qml`, `tests/osd/`
> **Config:** `OSD.*` (reader `OSDConfig`); entries are `definitions/OSDEntry`, their `systems` items the `OSDSystem` kind (each system's `schema.yaml`)
> **Related:** [Recipe: a new OSD system](../../recipes/osd-system.md) (rules: `qml/components/surfaces/osd/AGENTS.md`), [Actions](../core/actions.md), [Brightness](brightness.md), [Screenshots and recording](screenshots-recording.md), [Lock keys](lock-keys.md), [Drives](drives.md), [Held off an edge](../popouts/held-off-edge.md), [Edge attach](../popouts/edge-attach.md), [Popout registry](../popouts/registry.md), [Dock](dock.md)

The on-screen displays: levels (volumes, the microphone, brightness) as bars, the state of the machine as status icons (lock keys, the keyboard layout, the audio devices, toggles, connections, a recording, the camera and a screen share), and cards saying what just happened (a device switched, a VPN up, a drive mounted, a screenshot taken, a message, the track playing). Each OSD is a configurable `EdgePopout` showing an ordered list of **systems**, one per feature (Audio, Privacy, Vpn, …), each a folder of its own; one engine judges every system's changes alike, and the OSD shows whichever changed last.

**The card rule** (maintainer, 2026-11-07), behind every system's policies: **a card when the icon alone can't say what changed** (something new that needs details: a device's name, a network joined, the apps that started a capture; an unexpected or partial departure: a VPN dropping by itself, one app of several stopping, a call app dropping only its camera); **just the icon for an expected departure** (a VPN taken down on screen, the last capture stopping, a toggle).

### Config (`OSD` section, `OSDConfig`)
- **Section keys:** `scrollToChange`, `scrollStep`, `onScreenChanges` (see What opens it), `cardsToHistory` (see Where events go), `items` (the OSDs; each has its own `enabled`; the section-wide one went in config v69).
  - `OSDConfig.scrollStep` is the level change per wheel notch (0–1). It is 0 when scrolling is off.
- **Each OSD** (`definitions/OSDEntry`):
  - `id`, `name`, `enabled`;
  - `screen` (monitors);
  - `edge`, `position`;
  - `detached`, `distance`, `animation` (Slide or Fade);
  - `openOnHover`, `timeout`;
  - `openTogether` (off by default), `iconsPlace` (`outside` | `inside`), `holdStill` (see What shows);
  - `barLayout`: `orientation`, `alongEdge` (its `x-showIf` reads the entry's `edge` through `../`), `showPercent`;
  - `row` (`notable` | `all` | `changed`: which icons show);
  - `cardsEnabled` (off: no card at all; a change with a card shows as its icon, and a drive, low battery, monitor, screenshot or message is a notification instead), `cardTimeout` (how long a card stays out);
  - `systems`: what it shows, in order (the icons' and the bars' order), each an `OSDSystem` item (Engine › A system's folder): `{ type, tile, card, quiet, …its own settings }`. `tile` (default on) shows its bars and icons, `card` (default on) its cards, each only where its schema has that part; `quiet` (default off): its changes don't open the OSD, they still show on an open one. Each system's own settings are in its section below (Systems). Default: Audio (bars Other apps and System volume; both device icons), LockKeys (Caps Lock, Num Lock), KeyboardLayout, Dnd, Caffeine, NightLight, Recording, Drives, Message (the entry's `systems` default), `row` `notable`.
- **Config v101** made the OSD one ordered list (`backend/internal/migrate/steps/v101.go`, its comment has the mapping): the entry's `bars`, `statuses` and `cards` became `systems`, each system once, where its first type was (the bars' first; Audio's bars one of each kind but App: a second is dropped, and said); an item `quiet` only when every key it took was (a migration note per entry names the status types that lost their quiet: "OSD b: capsLock now opens the OSD (LockKeys is one item)"; a bar keeps its `showOsd`); `bars.orientation` / `alongEdge` / `showPercent` became `barLayout`, `statuses.row` `row`, `cards.enabled` / `timeout` `cardsEnabled` / `cardTimeout`. A system's bars stay in its own order, so bars of two systems no longer interleave (Brightness between two Audio bars), accepted. Before it: v86 made the bars one `items` list with the statuses and media, v87 split that into `bars`, `statuses` and `media` (lock keys one type per key; `micMute` and `inputDevice` became `microphone`, `outputDevice` `audio`), v91 gave the cards their own object (`cards.items`, `media` in it with its two options; messages stay on the OSDs listing them, else the first enabled one gets them unless quiet there).
- **Rebuilds:** the OSDs are read through a JSON string (`_osdsJson`), so a reload that leaves the list unchanged doesn't rebuild them; `OSDHost` keys its systems by their types alone (What shows › Systems). A type listed twice in `systems` (only by editing config.json by hand) keeps its first item, in `OSDConfig.osds` and the editor's list alike, so the editor's next edit writes the list back without it.
- **Reader helpers:**
  - `shownIds` (the enabled ones, by id);
  - `osdById(id)`;
  - `systemTypes` (every system, from the `OSDSystem` kind's `oneOf`: type, label, icon, group), `nameOf(type)` (a system's label), `labelOf(osd)` (its tab name: its own, else its bars' (each system's schema says how: `x-barNames`, Brightness its label, Audio each bar by its apps or its kind), else its systems' with icons, else, with its cards on, those it shows only as cards (Now playing, or a system with a card switch and its `tile` off), else Empty OSD);
  - `excludedApps` (every Audio App bar's apps, across OSDs);
  - `messageOsd(id)` (where `axiom message` goes as a card: the OSD of that id, else (`id` "") the first, of those showing Messages (`OSDEngine.opensCard`); "" with none, so it's a notification);
  - `routeOf(system, key, notify)` (where an event goes, Where events go), `cardsToHistory`.

### Systems
Each is a folder of `qml/components/surfaces/osd/systems/` (Engine › A system's folder): its keys (`exposes`; tiles and bars keep the old type names, so `ShellManager.onScreen(kind)` callers are unchanged), what each change shows, and the declarations it says it with. No system declares its own `judge()`. Its timelines (`tests/osd/<System>.js`) are its spec.

#### Audio
- **Bars** (its `bars` setting, in order, each `{ type, apps, icon, showOsd }`; default Other apps then System volume): `master` (the default output's volume; its icon `AudioManager.outputIcon` for the device's kind, never its muted form: muted, it's struck through), `other` (the first playing stream no App bar matches, of any OSD: `excludedApps`), `app:<its index>` (the streams its `apps` match, by name), `micLevel` (the default input's volume; mark `microphone`); one bar per kind but App (a second System volume bar is left out). Every bar but the microphone's is marked `audio`. `showOsd` off is `opens: false`: it never opens a shut OSD, but shows on and keeps open an open one. `icon` empty follows what it shows. Drawn by its own `design/VolumeBar`, which reads and sets PipeWire itself; its icon mutes it on a click (`StyledVolumeBar.iconClickable`; an App bar mutes the streams it matches). A bar counts a level only on the node it read before, with its volume in (`AudioManager.volumeKnown`: a node binds before PipeWire sends its volume, reading 0 until then): a stream bar's set of streams (a stream joins it once its volume is in) and the System volume and Microphone bars' `node` (the default's id once its volume is in, else "") changing is a reload (`resetBy: ["streams", "node"]`), not a level, so an app's stream appearing (Discord joining) or a device switching never brings out the bars.
- **Tiles** (its `tiles` setting, default both): `audio` and `microphone`, the default output's / input's device, by its kind's icon, struck through and unusual while muted; a click mutes it (`toggleMute`, `toggleMicMute`). Hidden with no device.
- **Changes:** a switch from one device to another is the device's card (`onChange: "card"`: its name, what it's now used for, its profile on the second line); a mute is the icon (`onUpdate`); a device appearing or going is nothing (`onAdd`, `onRemove` `"none"`). The output and the input switching to one device (a headset) is one card, "Output and input" (`groups: [{ keys: ["audio", "microphone"], role }]`, matched by value; the role re-read as the state changes).
- **The device** is the physical one (`AudioManager.deviceKey`: `device.id`, else the Bluetooth address, else the node), judged once the new node has bound, and kept through a gap with none (`keepThroughGap`): a Bluetooth headset's profile switch (A2DP ↔ headset, which replaces its nodes) is no switch, nor its icon changing with it (`updateFields: []`). Its name (`AudioManager.deviceLabel` → `AudioDevices.deviceName`): the node's nick unless a sound chip's generic one, else its description without the profile it ends with, else (a built-in chip) the kind's name.
- **Settling** (`settledKinds: ["update", "level"]`; the watcher's `settled()`): the System volume and Microphone bars and the device tiles count a level or a mute only while `AudioManager.sinkSettled()` / `sourceSettled()`: the default device unchanged and bound since before it and still bound, so a device switching, appearing, binding or going away (Quickshell unreadies a removed node, then clears its volumes to 0 while it's still the default), or a profile switch, isn't the user. A switch counts as its node binds.
- **Its card takes in its own knock-ons** (`takesIn: "system"`): within the quiet window, a mute or a level of any of its keys after a device card shows nothing, so a device's own level arriving late doesn't bring the bars out beside its card (bars arbitrate like tiles: Engine › Arbitration). A volume key within that window folds in too: the trade-off accepted.

#### Brightness
`brightness`, a bar: this screen's brightness, left out while the screen has no controller (`available`). Settings: `allMonitors` (every monitor at once, showing their mean: [Brightness](brightness.md)), `icon`; its one key, so its item's `quiet` is its old bar's `showOsd` off (v101). Only a level set through axiom counts (`countsWithin: { after: "setAt", ms: 500 }`: within 500 ms of its own set, the watcher's `setAt`, `BrightnessManager.brightnessChanged`), not one a refresh found or idle dimming; every set counts, so a key at 0 % or 100 % (the level clamped, unchanged) still shows the bar, as its set time moves on. It gates itself, so it isn't held by the watcher's settle window (a key just after a start or a list edit shows). A plain bar (`OSDLevelBar`): its drag and scroll set the monitors through the watcher (`setLevel`). As its OSD opens, the watcher's `opened()` has `BrightnessManager.refresh` pick up brightness changed outside axiom on the monitors its bar shows (none with its `tile` off).

#### LockKeys
`capsLock`, `numLock`, `scrollLock` (its `keys` setting; default Caps and Num Lock): the LED (`LockKeysManager`, held while the watcher exists, so the LEDs are polled the whole session as with the LockKeys widget); lit and unusual while on, Num Lock too; either way its icon. Hidden without LEDs, and nothing is judged across their appearing or going (each key's `available`). Its tiles take no click.

#### KeyboardLayout
`keyboardLayout`: the input source in use, by its label and its kind's icon (`InputSourceManager`, as the KeyboardLayout widget shows them: a layout's code drawn in place of the icon, an input method's own あ), so an input method's switch shows it too; hidden with one source, unusual past the first. A switch is its icon (`onAdd`, `onRemove` `"none"`, `updateFields: []`: only a switch from one source to another shows); a click moves to the next (`inputSourceNext`). A changed list of sources is a config reload, not a switch (`resetBy: ["ids"]`); a change within 1 s of the focused window changing (`CompositorManager.activeWindowId`) is that window's own input method coming back (fcitx5 keeps one per window with `shareState` off), unless axiom switched in that time too (`ignoreWithin: { after: "focusedAt", ms: 1000, unlessAfter: "switchedAt" }`, `InputSourceManager.switchedAt`). fcitx5's own switch popup is off while `Input.keyboard.method.showSwitchPopup` is ([input sources](input-sources.md)).

#### Privacy
`camera`, `micUse`, `screenShare` (its `kinds` setting, default all three): the apps using a camera / a microphone / sharing the screen (`PrivacyManager.cameraCaptures` / `AudioManager.micCaptures` / `PrivacyManager.screenCaptures`, also the Privacy widget's); unusual while on, never hidden, no click.
- **What counts as a capture:** axiom's own recording isn't a share, it's Recording. A camera's also lists the apps holding its device open themselves, which PipeWire never sees (Chromium and Electron apps such as Vesktop read `/dev/video*` through V4L2): the daemon's `camera.state` (`backend/internal/camera`: inotify on the devices, and on `/dev` for one coming, going or getting its access, which a camera plugged in gets from udev only after it appears; then who holds one open in `/proc`, PipeWire and WirePlumber left out, an app's processes counted once by its flatpak id or else its process name), each one shaped as a node with the id `device:<key>` and its desktop entry's name. Video comes from a `Video/Source` or a program's `Stream/Output/Video` (niri makes its screencast one, which Quickshell gives no type: PrivacyManager also tracks links between two Untracked nodes and reads their media class once bound), into an app's `Stream/Input/Video`; a camera is a source backed by a device (`device.api` v4l2 or libcamera), any other one a share.
- **Changes** (`model: "set"` by node id, `ownerField: "app"`, `anyone: true`: an app's doing counts): a stream starting is its card naming the apps (`onAdd: "card"`; judged by node id, so an app's name read after its stream starts isn't another app); one of several stopping a "still" card naming those left ("Still using the microphone: OBS"; `onRemove: "still"`), several stopping within the quiet window with some left one card (a still card keeps its key's still card out, re-read); the last one stopping the unlit icon. Its cards are the engine's, from each key's `roles` (`add`, `still`, `stopped`).
- **One app on the camera and the microphone** (a call) is one card, "Using the camera and microphone", whichever came first (`groups: [{ keys: ["camera", "micUse"], role }]`); a call app dropping its camera (the last on it) but keeping the microphone is a still card of the one kept ("Vesktop / Still using the microphone").
- **A capture that stops while its card shows** (a picker's preview: Electron apps such as Vesktop open the portal and stream a thumbnail before their own picker, then stop it) keeps naming the apps (the change's `members`, the card's memory) with "Stopped sharing the screen" (or the camera's, the microphone's), not an empty title; a capture stopping as it starts is its card's knock-on.

#### Bluetooth
`bluetooth`: the radio (`BluetoothManager.enabled`), never unusual (the connected devices name it in its tooltip); a click turns it on or off (`bluetooth`). One key holds both the radio (`value`) and its devices' events (`carriesEvents`: `BluetoothManager.lastEvent`, its `serial` the `seq`), anyone's doing: so its card folds back as the radio turns off (`retractsCardWhenOff`), and the radio coming on under it is its own knock-on. Hidden with no adapter.
- **Devices connecting or disconnecting** (`onEvent`: its card): the daemon's `bluetooth.event` ([Bluetooth](networking-bluetooth.md) › Connection events): those within a second of each other are one event, so the radio coming on and its devices reconnecting is one card; the disconnects of the radio turning off are dropped, so that's only the tile's change. One device: its icon (`BluetoothManager.deviceIcon`), its name, Connected, and its battery (`80%`) when it reports one; several: their names joined, with Bluetooth's icon; a disconnect: `bluetooth_disabled`, the names, Disconnected. Never at the start or as BlueZ is read again. Set whatever the route (no notification ever says them: `ConnectionNotes`' silent notes do).
- **A device's battery low:** `BluetoothManager._sayLevel`, once settled (the first state, and the first after a hello or BlueZ coming back, is taken as it stands), once per drop to `Bluetooth.lowBattery` and then `criticalBattery` per device, again once its level recovered or it connects again (`DeviceBatteries.step`): the device's name, Battery low or Battery critically low, the percent; critical's on the warning colour (`tone: "warning"`), `battery_low` / `battery_alert`. Routed as the laptop's battery is (`announce("Bluetooth", "bluetooth", Bluetooth.notify, …)`, Where events go), so with no OSD showing Bluetooth's cards it's a notification (one per device, critical replacing low); `lastEvent` is set only when the route is the OSD. It's an alert (`alertKinds: ["low", "critical"]`): it opens the OSD even just after a click.
- **A headset's "connected" card** takes in Audio switching the output or input to it, and its level arriving late (`absorbs`: Audio's card, or a bar, for the same Bluetooth address (`AudioManager.bluetoothAddress`: `api.bluez5.address`, since `deviceKey` is the node's `device.id` first), the change's tile's `address`: a bar's is its mark's device tile, `OSDEngine.contextTile`): one change, one card; the switch coming first, the Bluetooth card replaces it. Its mute still shows beside the card.
- Switching just after airplane mode is airplane mode's knock-on (`knockOnOf: ["Airplane"]`); `userWindow` 8 s.

#### Wifi
`wifi`: unusual while off; a click turns it on or off. Joining a network is its card (`onAdd: "card"`): the Wi-Fi device turning connected (`wifiDevice.connected`, steadier than the scanned list, which can drop the network joined for a moment), the network's name and signal filling in as the list catches up (the card is re-read). Another network is reached through disconnected, so it's a card too; leaving one is nothing (`onRemove: "none"`); turning Wi-Fi off loses the network and its look at once, and the icon shows (the stronger of the two). Its card folds back as Wi-Fi turns off (`retractsCardWhenOff`); switching just after airplane mode is its knock-on (`knockOnOf: ["Airplane"]`); `userWindow` 8 s. Hidden with no Wi-Fi device.

#### Airplane
`airplane`: lit and unusual while on, either way its icon; a click toggles it; `userWindow` 8 s. Wi-Fi and Bluetooth switching just after it are its knock-on (their `knockOnOf`): its ring stays.

#### Vpn
`vpn`: whether a VPN is up (`VpnManager.rows`; the watcher `holds` VpnManager, which polls Tailscale while held: [the issue](../issues.md#tailscales-state-is-polled-where-it-could-be-pushed)); lit and unusual while up, hidden with no VPN; a click brings the VPN last used up or down (`vpn`). Every change counts, the user's or not (`anyone`: a drop, an autoconnect).
- One coming up is its card (`onAdd: "card"`: their names, Connected, the first one's address).
- One taken down on screen is the unlit icon (`onRemove: "icon"`); the last one going down that nobody took down on screen is a "Disconnected" card (`onUnexpectedRemove: "last"`; another still up: the icon, the other half of a switch). "On screen" is the mark within `userWindow` (15 s): a VPN taken down by a keybind or IPC gets the card (it has no other feedback), one from the OSD's own tile the icon.
- Each VPN is judged by its last settled state (`memberState: { field: "state", on: "on", off: "off" }`), so up and down are judged across `connecting` / `disconnecting`, and a row appearing (Tailscale's first status) or going isn't a change.
- Its card folds back as the VPNs go down (`retractsCardWhenOff`).

#### Battery
`charger` and `battery` (its `tiles` setting, default both). Hidden with no battery.
- `charger` (`BatteryManager.onBattery`): unusual on battery; plugging in is its card (`onAdd: "card"`: the level, Charging / Fully charged / Plugged in, and the time to full), unplugging the icon; its card folds back as it's unplugged (`retractsCardWhenOff`).
- `battery` (an `event` key: `BatteryManager.levelEvent`, set by `_sayLevel` as `level` turns `low` / `critical` at `Battery.lowThreshold` / `criticalThreshold`, once settled, never at the start, its `serial` the `seq`): its card, the level, Battery low or Battery critically low, and the time left; critical's on the warning colour (`tone: "warning"`). The tile is lit and unusual while low or critical (`battery_low`, `battery_alert` when critical, else `battery_full` unlit). A critical battery also sends an urgent notification beside its card (`NotificationManager.announce`: `urgency` `critical`), unless `Battery.notify` is off. Its card goes where Battery shows `battery` (Where events go).

#### PowerProfile
`powerProfile` (`BatteryManager.profile`): the profile's own icon, lit and unusual off balanced; a click flips between power saver and balanced (`powerSaver`). Only a change from one profile to another shows (`onAdd`, `onRemove`, `onUpdate` `"none"`: the profiles daemon answering or going away is none); its tooltip names it alone (`nameOnly`: on and off say nothing).

#### Caffeine, Dnd, NightLight
`caffeine` (`IdleManager.caffeine`; click `idleInhibit`), `dnd` (`toggleDnd`), `nightLight` (`nightLight`): one tile each, lit and unusual while on, either way its icon (night light's hidden with no night-light tool, `NightLightManager.available`). Caffeine is the toggle the recipe copies from (`docs/recipes/osd-system.md`).

#### Recording
`recording` (`ScreenshotManager.recording`): axiom's own screen recording, lit and unusual while on, hidden with no recorder, either way its icon. A click stops a running recording (its `actionOf`: `screenRecord`'s `close`, only while it runs, so `OSDHost.toggleable` is a binding).

#### Drives
`drive` (an `event` model): removable drives (`DrivesManager`: `count`, and `lastEvent`, set by what happens to a drive, a mount by a file manager too, never by a drive there at login; set only while an OSD shows its cards, Where events go; [Drives](drives.md) › Who says what). Each event is its card: the drive's name, and Connected, Encrypted: click to unlock (`lock`), Mounted (the mount point as its detail), Unmounted, Safe to remove (`eject`), Disconnected (`usb_off`), Unplugged without ejecting, In use: close what's using it, or Couldn't eject. Its card takes a click (`clickable`; the watcher's `activate`): `DrivesManager.activate` opens the drive, asks for its passphrase, or shows the Drives module. The tile is lit and unusual while a drive is plugged in, hidden with none (or no udisks2), so a drive ejected and gone shows only as it changes.

#### Monitors
`monitor`, card only (an `event` model): a monitor connected or removed (`MonitorManager.lastEvent`, from comparing its reads of `CompositorManager.withOutputDetails` by connector, disabled ones included, so turning one off isn't unplugging it; never what's there at the start; read only with `supports.monitors`): its card, its description (else its connector), Connected or Disconnected (`desktop_access_disabled`), and the connector and resolution.

#### Screenshot
`screenshot`, card only (an `event` model): a screenshot taken (`ScreenshotManager.lastShot`, from `_sayTaken`; not one opened in the annotator, nor one taken for a caller): its card, the picture in place of the icon (the card's `image`, drawn by `OSDCard` cropped, decoded at its size), Screenshot saved, Copied to the clipboard and the folder. Its card takes a click: the watcher's `activate` runs `ScreenshotManager.open` on the picture. Recordings are Recording.

#### Message
`message`, card only (an `event` model; its watcher takes `ShellManager.osdMessage` for its own OSD, `osdId`, pulsed so the same text twice shows twice): what `axiom message <icon> <text>`, `ShellManager.confirm` and `ShellManager.refuse` send, as a card (its icon, the chat bubble for none; the text as the title; `detail` as the faint line; a refusal's picture on `Theme.warning`, `tone: "warning"`), shown as sent (the sender translates it), on the OSD `OSDConfig.messageOsd` picks: one with its cards on that lists Messages. With none `ShellManager` sends it as a notification instead, refusals too (a refusal's isn't kept: `transient`). It shows beside whatever else is out, and gives way within the quiet window only to another card, so its text gets read (the default `sameChange`: it never comes without its card, and has no tile to ring). Not lost at the start: an event model's events show during the settle window (Engine › The watcher).

#### Media
`media`, card only: the now playing card (its own `design/MediaCard`, an `OSDCard`: the cover, title, artist, playing or paused), on a new track (`onTrackChange`, default on: the track is the value, so a new one is an add or a change) and optionally on play and pause (`onPlayPause`, default off: playing is its look, an update); the artist and the cover filling in are neither (`updateFields: []`); never with no player or no title, nor as the only player quits while it plays (losing the track is `onRemove: "none"`, and a look's card never outranks its value going: Engine › The judgement). The card an OSD with no bars or icons opens on (`preview: true`: its hover strip, the Show button). The lowest card (`yieldsCard`): it never replaces another system's card out (Engine › Arbitration). Not in the default list.

### Status icons (the row)
Each system's tile keys, drawn by `design/OSDTileRow` / `OSDTile` (a tile per key it may show, by id `"<System>/<key>"`, in the list's order, shown while in `OSDParts.rowTypes`), each `OSDEngine.tileOf`'s `{ icon, label, on, slash, notable, hidden, name, … }`: the icon in a rounded square, **on the accent while `on`**, faint and unfilled while off; the one that just changed is ringed and pops in, the ring fading in and out: the foreground with a gap in the background inside it, so it reads on the accent fill too (`borderFocus` is the accent in most themes). The fill glides between on and off in the accent's own colour (off is the accent at alpha 0, so the glide changes no hue). `icon` is always the feature's base icon, never its `_off` form: off is told by the fill alone, and only a mute (audio, microphone) is also struck through (`slash`, drawn by `SlashedIcon`), as a muted bar's icon is, since a plain speaker doesn't read as muted. Text only where an icon can't say it: a layout's code drawn in place of the icon (`label`). A device's, a VPN's or the capturing apps' names (`name`) are in its tooltip, and its card's.
- **Clicks:** hovering a tile lays the ink faintly over it, at once (a layer, not the fill: an eased fill left tiles easing back behind the pointer, and lightening barely shows on a pale accent; a slash's cutout follows it on a lit tile) and names it and its state in a tooltip; a click runs the action its system names (`OSDSystemHost.actionOf`: the `exposes` entry's `action` / `call`, or the definition's `actionOf`; [Actions](../core/actions.md)) through `OSDHost.toggle`, which marks the key's `mark` first. A click comes while the OSD is open, so its change keeps the part shown (as any change then does), and a VPN taken down there is expected (its icon, not the Disconnected card). A clicked tile stays in the row though it turned back to ordinary (`_kept`, below); a quiet change with the OSD shut changes nothing.
- **Which show** (`OSDParts.rowTypes`, by `row`): `notable` the unusual ones, `all` every one not hidden, `changed` none; plus `kept`, always, in its place: the one that just changed and **every one the row has shown since the icons came out** (`OSDHost._kept`, gathered by `_keepRow` as the icons open and as a change rings, in every mode; emptied as they fold back or the OSD closes). So a tile that turns ordinary stays until the icons go: Caps Lock off, then Num Lock off, shows both, unlit, with `changed` too (each change joins the ones before it).
- **Unusual** (`notable`, from each definition's `tile()`):

  | Key | Unusual while |
  |---|---|
  | `capsLock`, `numLock`, `scrollLock` | on |
  | `keyboardLayout` | past the first input source |
  | `audio`, `microphone` | muted |
  | `powerProfile` | power saver or performance |
  | `caffeine`, `dnd`, `nightLight`, `airplane`, `recording` | on |
  | `wifi` | off |
  | `bluetooth` | never |
  | `vpn` | a VPN up |
  | `drive` | a drive plugged in |
  | `charger` | on battery |
  | `battery` | low or critical |
  | `camera`, `micUse`, `screenShare` | an app using it |

### Bars
Each system's bar keys (`OSDLevelBar`, or the key's `design`: Audio's `VolumeBar`), in the list's order, laid out by `barLayout`: vertical bars side by side; horizontal bars as rows; or, along its edge, one line parallel to it (end to end when the bars run along it too); `showPercent` adds the level. A bar without a design of its own is a plain `StyledVolumeBar` whose drag and scroll go to its watcher (`setLevel`). A system's bars show only with its item's `tile` on.

### Cards
- A card is `OSDSystemHost.card(change)` (`OSDEngine.cardOf` over the system's live state: the definition's `card()`, or a set's `roles`; `{ icon, image, title, role, detail, tone, clickable }`, its English role translated by the view), drawn by `design/OSDCard` (a square picture, a title, a faint line, an optional status icon) or by the key's own `design` (Now playing's `MediaCard`, itself an `OSDCard`).
- **Re-read, never copied:** the host keeps the change that brought the card out (`OSDHost._cardChange`, kept as it folds back and the OSD closes, so it doesn't empty as it goes) and shows its card bound to the live state, so it says what holds now (the apps left after another stops, a network's name filling in, "Stopped …" as a capture stops under it, "Output and input" as the second half of a headset comes). Its system taken off the OSD's list, the card folds back (`on_SystemsKeyChanged`; not as its host goes, since any change to the types rebuilds every host).
- **Shown alone:** the change's icon turns lit quietly, ringed only if the icons happen to be out.
- **Sized to its text:** the longer line's width, at least 160 and at most 400 px (`minTextWidth` / `maxTextWidth`, scaled). Past it the title (one line) ends in "…" and the faint line wraps, up to three lines (`subtitleLines`, the last elided), the card growing taller as it does (at least 64 px, scaled, with one line); its slot and the box read its height as it is, and the window keeps room for it at its largest (`OSDCard.maxShown`: its widest beside a side edge, else three faint lines, in `OSDHost.maxDepth`). Each system's own card design is built once (`_designsKey`), so the window keeps room for it too.
- **A click** on a `clickable` card (`OSDHost._activateCard`): its system's watcher's `activate(change)` acts on it (a drive's opens it, a screenshot's opens the picture).

### Where events go
`OSDConfig.routeOf(system, key, notify)`, applied by `NotificationManager.announce(system, key, notify, …)`, whose caller names the event's system and key (DrivesManager `Drives` / `drive`, BatteryManager `Battery` / `battery`, BluetoothManager `Bluetooth` / `bluetooth` (a device's battery low), MonitorManager `Monitors` / `monitor`, ScreenshotManager `Screenshot` / `screenshot`): an event shows as its card on the OSDs that open it (`OSDEngine.cardRoute` / `opensCard`: an enabled OSD with `cardsEnabled`, listing the event's system (Drives, Battery with `battery` in its `tiles`, Monitors, Screenshot, Bluetooth) with its `card` on and not `quiet`); with none (a quiet one never opens the OSD, and with its cards off there is no card) it's a notification, as without the OSD, unless its section's switch is off (`Drives.notify`, `Battery.notify`, `Monitors.notify` (off by default), `Screenshots.notify`, `Bluetooth.notify`), with the buttons it always had (a screenshot's Edit in …, a mount's Open / Eject); else nothing. A critical battery notifies beside its card too. Each service sets its event (`lastEvent`, `levelEvent`, `lastShot`) only when the route is the OSD.
- **`OSD.cardsToHistory`** (default on): an event card shown on an OSD (a drive, the battery, a Bluetooth device's battery, a monitor, a screenshot, a message, not a refusal) is also filed in the notification history's Quiet section: `sendNotification`'s `silent`, which puts an entry straight there (`NotificationManager._file`: no toast, not counted on the badge, its buttons run by its desktop entry's handler, a path icon its picture; [Notifications](notifications.md) › Levels), one per key (a drive's, a monitor's, the last screenshot's). Device switches, the VPN, Wi-Fi, the charger, Bluetooth devices connecting and capture cards stay transient (Bluetooth's connections are filed as `ConnectionNotes`' notes).

### What shows (`OSDHost`)
- **Systems:** an `OSDSystemHost` per item of the OSD's `systems` (Engine › The OSD's host), each building its watcher, so an OSD without a system never wakes its service. The Repeater's model is the items' types as a string (`_systemsKey`): an edit to any OSD parses every OSD anew, and the string changes only with the types, so an edit of an item's own settings reaches its system in place instead of rebuilding the watchers (deaf for 1.5 s as they settle). A change opens the OSD unless its item is `quiet` (Engine › The host of one system › Opening).
- **Three parts, each shown for its own change and on its own time** (`OSDParts.parts`):
  - `level` (a bar changed): the bars alone;
  - `status` (a tile changed without a card): the status icons `row` picks, the change ringed (`changed`);
  - `card`: a system's card (Cards).
  - **Opened with nothing out** (its hover strip) and the Show button bring out the bars and the icons (`_expose`; every icon when none would show, `_previewAll`, until they close); with neither, the card a system offers as its `preview` (Now playing; `_previewChange`). Never another card. The pointer moving onto an OSD already open (catching a change, a card) brings out nothing new: it only holds what's there.
- **Stacked out from the edge, in one box** (`_order`, `OSDParts.partOrder`): the bars nearest the edge and the icons past them (`iconsPlace` `outside`, the default; `inside` puts the icons by the edge), the card always last; with `holdStill` and the pointer on the OSD, it goes after the other instead (still inside the card), so nothing under the pointer moves, and that order stays while both are out (a card under the pointer still moves out as the bars or icons come in: rare, left so). **`openTogether`** (default off): a change to a bar or an icon brings out both (`_boxParts`, where the OSD has both; the icons with none to show show every one, `_previewAll`, as `_expose` does); off, only the one that changed. A part slides out from under the one before (its `_levelReveal` / `_statusReveal` / `_cardReveal`, eased over `animNormal`, a slot clipped to it); one opening on a shut OSD is simply there as it slides in (`_snapping`, set before the order changes, since the eased length reads it).
- **One box, as long as its longest part,** attached or held off the edge alike: a card shorter than the bars runs as long as them (centred in its slot), a longer one makes the box as long as it. The length eases (`_lengthEased`, toward `_lengthTarget`: the longest open part, a folding one giving its room up as it goes; closing, every one still out; over `animNormal`): the box's ends run out to meet a longer part as it slides out and back as it folds, and a part's own length changing while shown (an icon joining the row, a card's text) eases too. Contents are centred on whole pixels (`_farX` / `_farY`), as `EdgePopout.aligned` is, else a half pixel flipping as the length eased shimmered them.
- **Times:** the bars and the icons `timeout`, the card `cardTimeout` (`_deadlines`, one Timer). **Shared** (`OSDParts.sharedDeadlines`): the bars and the icons, while both are out, take the later of theirs, so they close together; the card keeps its own, neither holding them nor held by them (it says what happened once), so with the pointer away they fold back without it, or it without them. Times within `grace` (750 ms) of each other end together (`OSDParts.partsDue`). The pointer on the OSD holds the bars and the icons; the card only while it's on the card itself (`cardHovered`, a `HoverHandler` on each card): pointing at the bars, a card still folds at its time. Let go, a held part gets its time anew (`_renew`). When the last ones go together, the OSD slides away whole (`collapse`). While a part is out the content's `hovered` holds the host's own countdown.
- **Changes during a close** (`_closing`: its host sliding away, for any reason: the parts' time up, its own countdown, a higher popout): anything coming in waits (`_show` → `_pending`, the changes themselves, in order, `force` if any one opens the OSD) and, once the OSD is gone, each comes in as it would to a shut OSD (`_showCard` / `_showTile` / `_showLevel`), so every verdict is the open path's (`_againstCard`, the ring's `keep`): Airplane then Wi-Fi rings Airplane, a headset's level after its Bluetooth card is held under it. A quiet batch is dropped; a forced one reopens the OSD (its host reopens only after closing). A change whose system is taken off the list meanwhile is dropped (`on_SystemsKeyChanged`). The Show button during a close only reopens it, which brings the bars and the icons out (`preview` does nothing while closing).
- **What gives way to what** (`OSDEngine.arbitrate`, Engine › Arbitration): a card replaces the card out unless it's the same change (a headset's output and input, one app's camera and microphone, a still card after its key's still card); a change without a card shows nothing when it's the card's own knock-on (a mute or a level just after a device switch; the other half of a VPN switch; a capture stopping as it starts), folds the card back when it would say what no longer holds (a VPN, Wi-Fi, the charger or Bluetooth turned off), and else shows beside the card; Wi-Fi or Bluetooth switching just after airplane mode leaves its ring. All within `OSDEngine.quietWindow` (2 s), but the fold-back.
- **Its size:** each part's own as far as it's out, gaps between (`gap`: the host's padding inside its stroke, `contentPadding` less the border, so parts are as far apart as the outer ones are from the outline, and the nearest from the screen edge, which `EdgePopout.attachExtra` keeps the same; measured between what shows: a part's own empty margin, `_inset` (a card's round its picture, `OSDCard.inset`; not a bar's, whose margin holds its muted highlight: run on into the gap it sat cramped), runs on into the gap or the padding instead of adding to it); the host keeps room for every part out at once across its edge (`maxDepth`: the bars, the icons at their largest (`OSDTileRow.maxDepth`: a tile), the deeper card it may show at its largest (`OSDCard.maxShown`: beside a side edge its widest, else its faint line wrapped to three lines, so its text changing never resizes the window), and the gaps; → `EdgePopout.maxContentDepth`), so its window isn't resized as parts come and go: the host sizes its window from `AttachedSurface.depthFor(maxContentDepth + padding)`, the surface's depth at its largest (or the surface's own, should it be deeper), never from the surface's depth less the content's (two bindings a pass apart as a part eases: they wobbled a few pixels a frame, each wobble resizing the layer window, a stutter on a 240 Hz monitor). Along the edge it's the longest part's, as far as it's out (`_lengthNow`). The hover strip's `triggerLength` is the open parts' full length (`_lengthTarget`), not the eased one, so its window resizes once per part, not every frame. **Whole pixels:** each part's depth, its gap and `_lengthNow` are rounded (`_layout`), and the host's window depth is ceil'd: a fraction left the content a pixel off its outline, and a bottom or right OSD's window flipping a pixel taller and back moved everything in it.

### Surface (`qml/shell/OSD`)
- One `EdgePopout` per enabled OSD (`OSDConfig.shownIds`), on each screen its `screen` puts it on (`General.screensFor`).
- It is keyed by id, so editing an OSD's settings updates it in place instead of rebuilding every OSD.
- Placed at its `edge` / `position`. With `detached` it is held off the edge, `distance` across the free screen, sliding or fading in (`animation`), as a dock is (see [Held off an edge](../popouts/held-off-edge.md)).
- **Popout claim:** it uses `overNamespace: "axiom-osd"` and claims as kind `osd` (`claimKey` `osd:<id>:<screen>`), so it closes under a higher popout and won't open under one (see [Popout registry](../popouts/registry.md)).
- `keepLoaded: true`: the systems report their own changes, so their watchers must exist while the OSD is closed.
- Hiding: the parts' own times (`OSDHost`'s `collapse` → `hide()`, see What shows › Times); the host's own countdown (`timeout`) only runs while nothing is out (opened from its hover strip with nothing to show).

### What opens it (`OSDTriggers`)
- A change opens every OSD listing its system, on the target screen (the focused one), or on all of them in "all" mode. The same system in two OSDs opens both. `OSDTriggers.poke(force)` opens or keeps open, restarting the countdown; `OSDHost` pokes it for each change it shows.
- **Changes made on screen don't open it** (unless `OSD.onScreenChanges`): the UI marks a change right before it calls the setter (`ShellManager.onScreen(kind)`, most through `ActionsManager.run(id, {fromScreen: true})` and its `osdKind` ([Actions](../core/actions.md)): the Volume and Microphone widgets, the Bluetooth, Notifications, Vpn, IdleInhibitor, KeyboardLayout, ScreenRecord and Button widgets, the AudioMixer, VolumeDials, the OSD's own bars (every drag, scroll and mute: each marks its entry's `mark`, as `OSDEngine.markOf` gives it), Brightness, QuickActions, NightLightControls, Caffeine, WifiNetworks and BluetoothDevices modules (its radio switch, and a device connected, disconnected, paired or forgotten from its rows, so that device's card updates an open OSD but opens none), `VpnRow`, `NotificationHeader`, the night light settings card, the shared prompt's card for a request with `marks` (a Bluetooth pairing accepted)). A watcher asks `OSDEngine.byUser(def, key, ShellManager.markAge(mark))` (the key's `mark`, judged by its system's window: 2 s, 8 s for Wi-Fi, Bluetooth and airplane mode, 15 s for a VPN), and a change that's the mark's (`byUser`) updates an open OSD, never opens a shut one (`OSDEngine.opens`), unless it's an alert (a headset's battery low). Never a service: keys come in through IPC and automation (idle, schedules) calls the setters too, and both must still open it. Launcher commands aren't marked (typed, and the launcher closes).
- The settings page's Show button (and `axiom ipc osd show <id>`) goes through `ShellManager.showOsd(id)`: the OSD opens on its bars and its status icons as they are (every one when none would show, `_previewAll`, until they close), else its preview card (`OSDHost.preview`).
- `axiom message [--detail <text>] [--osd <id>] <icon> <text>` (`backend/internal/cli/message.go`) calls the `osd` target's `message(id, icon, text, detail)` with all four, `""` for a flag not given (IPC functions take no optional arguments; the CLI is the documented way in, the IPC function its plumbing): `ShellManager.osdMessage`, shown as a message card on `OSDConfig.messageOsd`'s OSD (Systems › Message).
- `_message` files it in the notification history's Quiet section with `OSD.cardsToHistory` (a refusal isn't filed), and sends a notification instead where no OSD picks Messages (`messageOsd` ""); `ShellManager.confirm(icon, title, detail)` is an answer to something just done (the calendar's "Added …"), never filed, a toast that isn't kept where no OSD picks Messages; `ShellManager.refuse(icon, title, detail)` sends it as a refusal (`tone: "warning"`: the card's picture on the warning colour, the icon the base one of what was refused, the title what, the detail why: "Night light" / "Not available here"). An IPC action that can't run here says why with it (screen recording without wf-recorder, no VPN to toggle, night light unavailable, no other audio output), since a bind or hot corner has no button to grey out.
- When an OSD opens, each of its watchers' `opened()` runs (`OSDHost.open`): Brightness refreshes the monitors its bar shows.

### Editing
- On the section's `x-card` `views/Settings/OSDListCard` (an `EntryListCard`):
  - tabs, one per OSD (named by `labelOf`);
  - the screen picker every placed surface has (its nine spots and a drag);
  - a Show button;
  - its systems (`views/Settings/OSDSystemsEditor`, the card's `entryContent`; `ownKeys: ["systems"]`), folding under the `systems` setting's title: a row per system in order (its icon and label from the `OSDSystem` kind, `OSDConfig.systemTypes`; a quiet one marked `notifications_off`), dragged to reorder (`EntryListTarget` / `EntryListRow` on an `InlineDragLayer`), clicked to select, X to remove. **Add** opens a `TypePickerPopup` of the systems not in the list, exactly as wide as the Add button (`matchWidth`, long labels elided), under their `x-libraryGroup` headings (the schema's `x-libraryGroups` order: Keys & input, Audio, Connections, Power, Privacy, Capture, Events), with its search; the one added is filled with its schema's defaults (`SchemaValidation.applyDefaults`) and selected. The selected system's form is under the list (a `SchemaPropertiesForm` of its item's schema less `type`, built anew per system through a `KeyedLoader`): its parts' switches (`tile`, `card`) and `quiet` first, then its own settings in the schema's order; a setting only its tile or bars use carries `x-showIf: {tile: true}` (Audio's `bars`, Brightness's, LockKeys' `keys`; Audio's `tiles` also pick its device cards, so they show while either part is on). The selection is by type (each system is in the list once), so a move keeps it, and it clears on another OSD's tab.
  - the other settings ("Place and timing": `row`, `cardsEnabled`, `cardTimeout`, place and timing), then the bars' layout (`barLayout`, `lastSections`).
  - Every edit replaces the OSD's whole `systems` list through the settings draft (`EntryListCard.edit`), so it shows live and waits for Save.
- The App field's chips come from `x-suggestions: "audioApps"` (`SettingsManager.suggestionsFor`).
- The settings page lists each system from its `schema.yaml` (generated: [config/OSDSystems](../config/OSDSystems.md)).

## Engine
The OSD runs on **systems** (one folder per feature) and one engine that judges every change alike: `OSDHost` builds an `OSDSystemHost` per item of an OSD's `systems` and shows what they report. This section is the contract the pieces follow (the [recipe](../../recipes/osd-system.md) walks a new system through it); the sections above describe what they make of it.

### A system's folder
`qml/components/surfaces/osd/systems/<Type>/` (`check_structure` holds each to it):
- `<Type>.qml`, the **definition**: an `OSDSystem` (`engine/OSDSystem.qml`), pure. It imports only `QtQuick`, `qs.components.methods` and `qs.components.surfaces.osd.engine`, so `tst_OSDSystems` loads it.
- `<Type>Watch.qml`, the **watcher**: an `OSDWatch` (`engine/OSDWatch.qml`), the only file of the system that reads services (with `design/`).
- `schema.yaml`: its item in an OSD's `systems` list, a type of the schema kind `OSDSystem` (`index.yaml` › `kinds`, base `definitions/kinds/OSDSystemBase.yaml`, `x-settingsAt: /properties`): `label`, `icon`, `group` (an `x-libraryGroups` name, checked as a bar widget's), its own `settings`, and the parts it has: `tile: standard` adds the switch `tile` (its icons in the row, default on, labelled "Icon"; a system with bars names it, `tile: {variant: standard, tile: {title: Bar, description: …}}`, as Brightness and Audio do), `card: standard` the switch `card` (its cards, default on). Every item has `type` and `quiet` (its changes don't open the OSD).
- `design/` (optional): visuals only it uses, loaded by URL (`Paths.osdDesignUrl(type, "<File>")`).
- **No file of the folder names another** (`check_structure`): each is loaded by its URL (`Paths.osdSystemUrl(type)`, `Paths.osdWatchUrl(type)`; a name with a slash names another file of the folder), and `OSDSystemHost` hands the watcher its definition as a property. So qs never has to scan the folder as a module (qml-pitfalls › URL-loaded files): what the files import is what must be reached from `qml/shell.qml`, `qs.components.surfaces.osd.engine` (the host that builds `OSDSystemHost` imports it) and the services and helpers, which are. A system's view of its own (a design file) is loaded by URL the same way; anything two systems share goes in `surfaces/osd/design/`, imported by the host.

### The definition (`OSDSystem`)
A definition is mostly declarations: the engine does the hard parts (gaps, settling, reloads, focus-follow, owners across keys, the cards' memory) from them, and `judge()` is a last resort for something truly one-off. Properties (each policy and `model`, `updateFields`, `userWindow`, the declarations below but `groups`, `takesIn`, `ownerField`, `retractsCardWhenOff`, `yieldsCard` and `knockOnOf` may also be set on one `exposes` entry, overriding the system's for that key: `OSDEngine.policy(def, key, name)`):
- `type` (its folder's name; set by its loader), `options` (its item: `{ type, tile, card, quiet, …own settings }`).
- `exposes`: `[{ key, part: "bar" | "tile" | "card", icon, label, mark?, opens?, action?, call?, design?, preview?, roles?, …overrides }]`, a binding over `options` where the item's settings pick what it shows. Keys keep the old type names (`audio`, `microphone`, `capsLock`, `camera`, `master`, `other`, …), unique in `exposes`: the microphone's bar is `micLevel` (mark `"microphone"`; its tile keeps `microphone`), an App bar `app:<its index in bars>` (mark `"audio"`). `opens: false`: a change of that key never opens a shut OSD (an Audio bar's `showOsd` off; `OSDEngine.opens`). `mark` is the on-screen mark a change of it is judged by (`ShellManager.onScreen`'s kind; default the key: Audio's bars say `"audio"`, the microphone's `"microphone"`). `action` / `call`: what a click on the tile runs (`ActionsManager.run(id, { call })`, call `"toggle"` by default). `design`: a file of the system's own drawing that key (`Paths.osdDesignUrl(type, design)`: a file of its `design/` by name, `"VolumeBar"`): a bar's is kept handed its `system`, `entry`, `orientation` and `showPercent` (Audio's `VolumeBar`, which reads and sets its service itself, a stream bar's streams matched by its watcher's `streamsOf`, the one rule its state reads too); a card's is an `OSDCard` (`design/`) kept handed `card`, which sets its own `title`, `subtitle`, `status` and `picture` (Now playing's `MediaCard`). `preview: true` on a card key: the card an OSD with no bars or icons opens on (its hover strip, the Show button: Now playing's). `roles` (a set's key): `{ add, still, stopped }`, the engine makes its card (`OSDEngine.cardOf`, below).
- `model`: `"scalar"` (state `{ value, … }`), `"set"` (`{ members: [{ id, … }], … }`) or `"event"` (`{ event, seq }`). A bar's state is `{ level, muted }` whatever the model.
- Policies, each `"card"`, `"icon"` or `"none"`: `onAdd` (default `"icon"`), `onChange` (`"icon"`), `onUpdate` (`"icon"`), `onRemove` (`"icon"`; also `"still"` and `"last"`), `onUnexpectedRemove` (`""`: onRemove's; also `"still"` and `"last"`), `onEvent` (`"card"`; `carriesEvents`).
- `updateFields` (`["icon", "label"]`): besides `on` and `slash`, which always count, the tile fields whose change with the value the same is an `update`. Audio's is `[]`: a Bluetooth profile switch changes the device's icon, which isn't a change of its own.
- `anyone` (false): count changes the watcher calls unsettled (`settled()` false) too.
- `settledKinds` (null: every kind): the change kinds that count only while the watcher calls them settled. Audio's `["update", "level"]`: a device switch counts as its new node binds (never settled), a mute or a level only once it has. `anyone` makes it none.
- `resetBy` (`[]`): state fields whose change makes a change of the key nobody's, so nothing shows (a reload, not a switch: KeyboardLayout's `ids`, Audio's stream bars' `streams`).
- `countsWithin` (null): `{ after, ms }`, a state field holding a time (`Date.now()` ms, 0 for never): a change counts only within `ms` after it, the user's own set (Brightness's `{ after: "setAt", ms: 500 }`: a refresh or idle dimming is nothing; a set at its limit, the level unchanged, is a level, its time having moved). Such a key gates itself, so the watcher's settle window doesn't hold it (`OSDEngine.showsWhileSettling`).
- `ignoreWithin` (null): `{ after, ms, unlessAfter }`, state fields holding times (`Date.now()` ms, 0 for never): a change within `ms` after `after` shows nothing, unless within `ms` after `unlessAfter` too. KeyboardLayout's focus-follow: `{ after: "focusedAt", ms: 1000, unlessAfter: "switchedAt" }` (a window's own input method coming back on focus, unless axiom switched then).
- `carriesEvents` (false; scalar): its state carries events too (`{ value, event, seq }`): a new `seq` with an event is an `event` change, shown by `onEvent`, before the value's own. Bluetooth: the radio's on and off and its devices' events on one key, so its card folds back as the radio turns off and the radio coming on under it is its own knock-on.
- `alertKinds` (`[]`): event kinds (`after.event.kind`) whose change is an `alert` (it opens the OSD even just after an on-screen mark): Bluetooth's `["low", "critical"]`.
- `memberState` (null; set): `{ field, on, off }`, a set judged by one member field (Vpn's `{ field: "state", on: "on", off: "off" }`): the set is the members whose field is `on`, and only a member known before (settled `on` or `off`) and still there counts. Any other value is a member in transit (connecting), judged as it last settled (`OSDEngine.remember` keeps that reading; one never settled is left out); one appearing (Tailscale's first status) or going isn't a change.
- `keepThroughGap` (false; scalar): a value going empty is a gap, not a removal, and the watcher judges the next value against the one before the gap (`OSDEngine.remember`). Audio's devices: a Bluetooth headset's profile switch replaces its node, often with none between; the device it comes back as isn't a switch.
- `takesIn` (`"key"`): what changes without a card its card out takes in within the quiet window (`sameChange`'s default): `"key"` its own key's (a capture stopping as it starts), `"system"` any of its keys' (Audio: a new device's mute, its level arriving late).
- `ownerField` (`""`; set): the member field naming who a member belongs to (Privacy's `"app"`): what a set's card names and what `groups` match by (a member without it, its id).
- `groups` (`[]`): `[{ keys, role }]`, keys whose changes of one owner make one card. A key's owners are a set's members' `ownerField`, once each, or a scalar's value (`OSDEngine.ownersOf`); a grouped key's tile carries them (`owners`). Three things follow:
  - a card of one key coming within the quiet window of another's card out, an owner in common, is kept (Arbitration rule 4);
  - the card of an arrival (`add`, `change`, not `still`) whose owner another listed key of the group holds says the group's `role` (Audio's "Output and input", Privacy's "Using the camera and microphone"), re-read as the state changes;
  - under `onRemove: "still"`, a set's last member leaving one key (none left there) while its owner stays on another listed key of the group is a still card (`kept` that key): Privacy's "Vesktop / Still using the microphone" as a call app drops its camera.
- `userWindow` (2000): ms after its mark a change is the pointer's (8000 Wi-Fi, Bluetooth, airplane mode; 15000 a VPN).
- `retractsCardWhenOff` (false), `yieldsCard` (false), `knockOnOf` (`[]`, system names): see Arbitration.
- Functions, each overridden by a definition declaring its own (the base calls them through `root`, so its own `actionOf` sees an override):
  - `tile(key, state)` → any of `{ icon, label, on, slash, notable, hidden, name, nameOnly, … }` (`name` a device's, a VPN's or the apps': the tooltip's value; `nameOnly` a tile whose on and off say nothing, named alone in its tooltip: the power profile) (`state` is that key's; `OSDEngine.tileOf` fills the rest, the icon from `exposes`); default a toggle's, `on` and `notable` while `value` is true, `hidden` while `available` is false (Caffeine, Dnd, NightLight, Airplane, LockKeys, Recording declare none).
  - `card(change, state)` → `{ icon, image, title, role, detail, tone, clickable }` or null (`state` is the system's, by key; English, translated by the view, its strings declared in a comment as `I18n.tr("…")` calls; `OSDEngine.cardOf` fills the rest, the icon from the tile).
  - `judge(before, after, ctx)` → `undefined` (leave it to the engine), `null` (nothing), or `{ kind, show, … }` (its extra fields kept). `ctx`: `{ key, part, model, at, byUser, settled, before, after }` (`before` / `after` the whole states). It's asked only past the first reading and `available` (rule 2 and 3 below), and reads `ctx.settled` itself. It may set `alert: true` (else `alertKinds` says). A last resort, for what no declaration says, its reason written above it: no shipped system declares one (lock keys' availability is their `available`). It runs before the engine's own guards and declarations.
  - `sameChange(shown, incoming)` → bool; default `incoming.card !== true && (takesIn === "system" || shown.key === incoming.key)`.
  - `absorbs(own, other)` → bool; default false.
  - `actionOf(key, state)` → `{ id, call }` or null; default from `exposes`.

### The judgement (`OSDEngine.judge(def, key, before, after, ctx)`)
- Returns null (nothing shows) or `{ key, part, model, kind, show, card, still, unexpected, alert, added, removed, left, at, byUser }`. `alert` (an event of a kind `alertKinds` lists, or the definition's `judge()` sets it): it opens the OSD even when made on screen (`OSDEngine.opens`). `kind`: `"add"`, `"remove"`, `"change"`, `"update"`, `"event"`, `"level"`. `show`: `"card"`, `"tile"`, `"level"` (`card` is `show === "card"`).
- `members` (a set's change): the members as the change saw them, those after an arrival, those before a departure. It's the card's memory: a host keeps the change of its card out, so the card still names who came once they're gone (a picker's preview stream stopping under its card: "Stopped sharing the screen"). `kept`: a group's still card's key the owner stays on.
- `ctx`: `{ at, byUser, settled, before, after }`.
- In order:
  1. **The same state** (`OSDEngine.same(model, before, after)`: an event's by the event object and its `seq`, any other by value): null.
  2. **The first reading** (`before` missing): null.
  3. **Not available**: `before.available` or `after.available` is `false`: null (the LEDs appearing, Wi-Fi or Bluetooth with no service).
  4. **The definition's own** `judge()`, when it doesn't return `undefined` (it sees `ctx.settled`; nothing below applies to it).
  5. **The declarations:** a field of `resetBy` changed with it, it came outside `countsWithin`, or within `ignoreWithin`: null.
  6. **The model** (each kind it finds counts unsettled only if `settledKinds` leaves it out, or with `anyone`):
     - A bar: `level`.
     - `event`: a non-null `after.event` is `event`, shown by `onAdd`; where the state counts its events (`seq`), only with a `seq` other than before's (the same event read again with the rest of the state, a drive's count changing, isn't one).
     - `set`, by member id (with `memberState`, the ids `on` among those known before and still there): any added is `add` (`onAdd`; `added`); else any removed is `remove` (`removed`, `left` the ids still there (`on`); `kept` when the set's last member leaves (none left) and a group's key keeps its owner).
     - `scalar`: with `carriesEvents`, a new `seq` with a non-null `after.event` is `event` (`onEvent`), before the rest. `value` empty → not is `add` (`onAdd`), not → empty is `remove` (a gap with `keepThroughGap`: null), one → another is `change` (`onChange`). Empty is `undefined`, `null`, `""`, `false` or `[]`. The tile's look changing (its `on`, `slash` and `updateFields`; not its name or a signal) is `update` (`onUpdate`). When both happen, the stronger show wins (card, then tile): Wi-Fi turned off loses its network (`remove`, none) and its look (`update`, the icon). But a look's card never outranks the value going: the card would describe what's gone (Now playing's only player quitting while it plays, with `onPlayPause` on).
  7. **A removal:** `unexpected` is `!ctx.byUser`. Its policy is `onUnexpectedRemove` when unexpected and set, else `onRemove`. `"still"` shows a card while some are left, or a group's key keeps the owner (`still: true`), the icon for the last; `"last"` the reverse: the icon while some are left (here or on a group's key), a card for the last (a VPN dropping with none left up: "Disconnected"; the other half of a switch: the icon).
  8. **A policy of `"none"`**: null.
- **Who made it** (`byUser`): the watcher asks `OSDEngine.byUser(def, key, ShellManager.markAge(mark))`. `markAge(kind)`: ms since the mark (`ShellManager.onScreen(kind)`), -1 for never; `byUser(def, key, elapsed)`: less than the key's `userWindow` ago, never from the future (negative) nor never; `ActionsManager._osdKinds` gives each action's mark. `OSD.onScreenChanges` stays the host's (an on-screen change still opens it with the switch on). A click on the OSD's own tile marks its kind (`OSDHost.toggle`; the OSD is open, so it still shows), so a VPN taken down there is expected.

### The watcher (`OSDWatch`)
A `QtObject` (an Item's `state` is taken); what it declares inside (Connections, Timers) goes in its default `data`.
- `definition` (set by `OSDSystemHost`), `options`, `screen` (the OSD's screen, a ShellScreen: Brightness reads its monitor, with `allMonitors` all of them), `osdId` (the OSD's id: Message takes only its own OSD's `ShellManager.osdMessage`).
- `holds`: services acquired (`acquire(watch)`) on completion and released on destruction.
- `state`: by exposed key, bound to its services; the definition's model's shape. `available: false` holds judgement.
- `settled(key, before, after)`: false while its service is still settling (Audio: `AudioManager.sinkSettled()` / `sourceSettled()`); a change then only moves the state on.
- `events` and `pulse(key, event)`: an event model's state (`"drive": watch.events.drive ?? ({ event: null })`), `seq` counting each one, so one like the last still counts.
- `activate(change)`: a click on a `clickable` card.
- `opened()`: its OSD opened on this screen (`OSDHost.open`): picks up what nothing pushes (Brightness `refresh`es the monitors its bar shows).
- `setLevel(key, level)`: a bar with no `design` (`OSDLevelBar`'s plain `StyledVolumeBar`) dragged or scrolled.
- `tiles` (readonly): `OSDEngine.tileOf` of each tile key.
- `change(what)` (signal): each judged change, `OSDEngine.judge`'s with `{ system }`, in `exposes` order.
- How it runs:
  - A state change is judged once it's all in (`Qt.callLater`), every key against the state last judged (`OSDEngine.remember(def, before, after)`: a `keepThroughGap` value kept through a gap; `state`, `snapshot` and the tiles stay as they are).
  - For its first 1.5 s (the settle window, from its building: a shell start, a list edit that rebuilds it) a change only moves the state on, while services settle; but an event of an `event`-model key shows at once (`OSDEngine.showsWhileSettling`): its watcher pulses it as it happens, so it's never a first reading (an `axiom message` sent just after a start isn't lost). So does a key declaring `countsWithin`, which gates itself (only the user's own set counts: a brightness key just after a start). A `carriesEvents` scalar's event waits like the rest: it's read from its service's state, which may answer with its last one as it starts.
  - A watcher for a toggle is a few lines: `state: ({ "caffeine": { "value": IdleManager.caffeine } })`.

### The host of one system (`OSDSystemHost`)
- **Inputs:** `type`, `options`, `screen`, `osdId` (the last two handed to the watcher; neither changes in a host's life, its OSD keyed by both). It loads the definition (`Paths.osdSystemUrl(type)`, given `type` and `options`), then the watcher (`Paths.osdWatchUrl(type)`, given `definition` and `options`). Both load once, as it's built (a type change rebuilds the host); `options` reaches both in place.
- **Exposes:**
  - `definition`, `watch`;
  - `snapshot` (the watcher's `state`), `tiles`;
  - `change(what)` (relayed);
  - `card(what)` (`OSDEngine.cardOf` over `snapshot`), `actionOf(key)`;
  - `opens(what)` (`OSDEngine.opens` with the item and `OSD.onScreenChanges`: whether the change opens a shut OSD);
  - `activate(what)` (hands a card's click to the watcher).
- **The card out is re-read from the live state:** the host keeps the change that brought the card out and shows `card(change)`, bound to `snapshot`, so it says what holds now (the apps left after another stops, a network's name filling in, "Stopped …" as a capture stops under its card), never a copy taken as it came.
- **Opening:** `OSDEngine.opens(item, def, change, onScreenChanges)`: never with the item `quiet` or the key's `opens: false`; else unless made on screen (`byUser`), which `OSD.onScreenChanges` or the change's `alert` overrides. A change that doesn't open the OSD still shows on an open one.

### The OSD's host (`OSDHost`)
- **Systems:** a Repeater over the `systems` items' types as a string (an edit of an item's own settings reaches its `OSDSystemHost` in place; a type added, removed or moved rebuilds them), each given its item, the OSD's `screen` and `osdId`. No system is named in the host.
- **Parts from the systems:** the bars are each shown system's `exposes` bars (`OSDLevelBar`, by count), the row its tiles by id `"<type>/<key>"` (`OSDTileRow` / `OSDTile`, named by each entry's `label`), the card `OSDSystemHost.card(change)` of the change it keeps (`OSDCard`, or the key's `design`). A system's bars and tiles show only with its item's `tile` on.
- **A change** (`OSDSystemHost.change`): `OSDEngine.shownAs` says what it shows on this OSD (a level only with the item's `tile` on); it's made whole (`system`, `tile` now (`OSDEngine.contextTile`: a tile's or a card's own; a bar's its `mark`'s tile, so the System volume carries its output device and its Bluetooth address; none for a bar marked by itself), `card`), `OSDSystemHost.opens` says whether it opens the OSD shut, and it's asked in the order below (Arbitration): a card against the card out, a bar against the card out (the late level's fix), a tile against the card out then the ring.
- **Opening:** `open` (the host's `isOpen`) calls each watcher's `opened()`; `OSDTriggers` only pokes the host and answers the Show button.

### Arbitration (`OSDEngine.arbitrate(shown, incoming, elapsed, defs)`)
`shown` / `incoming`: whole judged changes (`judge()`'s: `key`, `part`, `kind`, `card` (bool), `still`, `unexpected`, `alert`, `added`, `removed`, `left`, `at`, `byUser`), each with its `system` and `tile` (that key's tile as the change came); `sameChange` and `absorbs` read any of it. A host keeps the whole change of its card and of its ring for this; `elapsed` ms since `shown` came; `defs` the definitions by system. Returns:
- **Against a card out** (`shown.card`):
  - a card: `"replace"` (it swaps in) or `"keep"` (the same change: the first card says it);
  - a change without one (a tile or a bar): `"retract"` (the card folds back, the change shows), `"suppress"` (nothing shows) or `"beside"` (it shows beside the card).
- **Against the ringed tile** (`shown.card` false; only a tile change without a card asks): `"replace"` (it takes the ring) or `"keep"` (nothing shows).

The rules, in order:
1. **Retract:** against a card, a change of the same system and key without a card, with the system's `retractsCardWhenOff` and its tile not `on`, is `"retract"`, at any age.
2. **Yields:** a card of a system with `yieldsCard` (Now playing) against another system's card is `"keep"`, at any age: the lowest card never covers another (a device switch pausing the music leaves the device's card out). Its own cards still replace each other, and any other card replaces it.
3. **Past the quiet window** (`elapsed >= OSDEngine.quietWindow`, 2000): no knock-on.
4. **A knock-on**, within the window: `incoming`'s system lists `shown`'s in `knockOnOf`; or another system that `shown`'s `absorbs(shown, incoming)`; or (against a card only) the same system, whose `sameChange(shown, incoming)` says so, or with a card of its own: a still card against its own key's still card (several leaving one after another: the card out, re-read, names those left), or a card of another key of `shown`'s group, an owner in common (the tiles' `owners`). It makes a card `"keep"`, a change without one `"suppress"`, and the ring `"keep"`.
5. **Else** a card `"replace"`s, a change without one shows `"beside"`, and a tile takes the ring.

A host asks in this order (`tst_OSDSystems` simulates it):
- **A card:** with no card out it opens; else arbitrate against the card.
- **A bar:** against a card out (`"suppress"` or `"beside"`), else it opens.
- **A tile:**
  - against a card out first (`"suppress"` ends it, `"retract"` folds it back);
  - then against the ring (`"keep"` ends it);
  - else it takes the ring.
- **No ring** for a key without a tile part (a message).

**How each old branch maps** (the old OSD's `OSDItems.replaces` / `besideCard` and `OSDContent.showStatus`, the files the engine replaced):

| Old branch | Declaration |
|---|---|
| `elapsed >= quietWindow` → replaces | rule 3 |
| `shown === "message"` card: gives way only to a card | default: the Message system's `sameChange` is the default (same key, no card), and a message never comes without its card, so a card replaces it and anything else shows beside; no tile, so no ring |
| airplane ringed, `wifi` / `bluetooth` within the window → keep the ring | Wifi and Bluetooth `knockOnOf: ["Airplane"]` |
| `shownCard` false → replaces (the ring) | rule 5 |
| same type, no card, `vpn` / `wifi` / `charger` off → retract (`besideCard`, any age) | `retractsCardWhenOff: true` on Bluetooth, Vpn, Wifi and Battery (Battery's `battery` key never comes without its card) |
| same type, no card, still on → suppress (the other half of a VPN switch, a capture stopping as it starts, Wi-Fi still on) | default `sameChange` (same key, no card) |
| camera ↔ micUse cards from one app → keep (one card says both) | Privacy's `groups: [{ keys: ["camera", "micUse"] }]` by `ownerField: "app"` (rule 4) |
| a capture stopping beside another capture's card → beside | the default `sameChange`: the same key only |
| (new) a still card just after its key's still card → keep | rule 4 |
| audio ↔ microphone cards, same device → keep (a headset) | Audio's `groups: [{ keys: ["audio", "microphone"] }]`, matched by value (rule 4) |
| audio ↔ microphone card, another device, or the same key again → replace | no owner in common |
| audio / microphone no card (a mute) after a device card → suppress | Audio's `takesIn: "system"`: any of its keys |
| (new) a device's level arriving late after its card → no bars beside it | the same: a bar is one of Audio's keys, and bars now arbitrate too (the late level's fix) |
| (new) a Bluetooth headset's card takes in Audio's switch to it, and its late level | Bluetooth's `absorbs(own, other)`: Audio's card or bar for its address (a bar's tile its mark's: `OSDEngine.contextTile`) |
| a card replaces any ring (`showStatus`' card branch never asks the ring) | a host asks a card only against a card out |

### Routing (`OSDEngine.opensCard` / `cardRoute` / `shownAs`)
Over the new OSD entry shape `{ enabled, cardsEnabled, systems: [{ type, tile, card, quiet, … }] }` (`OSDEngine.itemOf(osd, type)` finds an item):
- `opensCard(osd, type, key)`: an enabled OSD with its cards on, listing the system with its `card` not false and not `quiet`; with `key` (the event's), an item whose `tiles` setting picks the keys it shows (Audio's, Battery's) must pick it (a low battery's card only where Battery shows `battery`).
- `cardRoute(osds, type, notify, key)`: `"osd"` when one opens it, else `"notification"` with `notify`, else `""`.
- `shownAs(osd, change, hasTile)`: what a change shows on that OSD.
  - A card stays a card while the OSD's and the item's cards are on.
  - Else it shows as its tile, when the key has one and the item's `tile` isn't false; else nothing.
  - A tile shows only under the same tile condition.
  - A level shows as a level while the item's `tile` isn't false.

### Timelines (`tests/tst_OSDSystems.qml`, `tests/osd/`)
The spec of every system's behaviour.
- **Files:** `tests/osd/index.js` lists the row files by name (`files: { "<System>": <its rows> }`, each `.import`ed), one `.pragma library` file per system (`tests/osd/<System>.js`, `var rows = [...]`) and `Cross.js` for rows across systems.
- **What it runs:** the pure definition (loaded from its path by `Qt.createComponent`) and `OSDEngine`, with no watcher and no settle window; each step judged against the state the watcher would keep (`OSDEngine.remember`). A row of a system with no folder, or whose definition doesn't load, fails.
- **A row:**
  - `name`;
  - `systems` (default: the file's name);
  - `options` (the item's settings, by system or for the only one);
  - `host` (what's out at the start: `{ card: { system, key, at }, ring: { system, key, at } }`; once a change comes out the simulated host keeps it whole, and arbitrates with it);
  - `onScreenChanges` (`OSD.onScreenChanges` for `opens`; default false);
  - `steps`.
- **A step:**
  - `system` (default: the row's first);
  - `at` (ms; default 3000 after the last, past the quiet window);
  - `state`: by key, laid over that system's state (a key given replaces it; `null` deletes it; one not given keeps the very same object, so an event isn't seen anew);
  - `byUser` (default false);
  - `settled` (default true; or by key);
  - `tiles`: by key, a subset of each one's tile after the step, changed or not (`hidden` too; the first reading's included);
  - `expect`.
- **The first step** of a system is its first reading: nothing shows.
- **`expect`:**
  - Omitted or `"none"`: nothing shows.
  - An object: exactly one change. An array: those, in `exposes` order.
  - Each may hold:
    - `key`, `show` (both checked first, as a list);
    - any field of the change (`kind`, `still`, `unexpected`, `alert`, `added`, `removed`, `left`, `byUser`);
    - `opens`: whether the change opens a shut OSD (`OSDEngine.opens` with the row's item `options`, its `quiet`, the key's `opens`, `byUser`, `alert` and the row's `onScreenChanges`);
    - `action`: a subset of the definition's `actionOf(key, state)` (`null`: none);
    - `tile` (a subset of `OSDEngine.tileOf` for the key after the step) and `card` (a subset of `OSDEngine.cardOf`; `null`: none);
    - `host`: the simulated host's decision. For a card it's `"open"`, `"replace"` or `"keep"`. For a tile it's `"ring"`, `"keep"`, `"beside"`, `"suppress"` or `"retract"`. For a bar it's `"open"`, `"beside"` or `"suppress"`.
- A subset compares objects field by field, anything else exactly.
- **Example:**
  ```js
  { "name": "turned on: its icon, lit and unusual",
    "steps": [
      { "at": 0, "state": { "caffeine": { "value": false } } },
      { "at": 3000, "state": { "caffeine": { "value": true } },
        "expect": { "key": "caffeine", "show": "tile", "kind": "add", "tile": { "on": true, "notable": true }, "host": "ring" } } ] }
  ```
