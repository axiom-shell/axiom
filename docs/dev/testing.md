# Testing and debugging the running shell

> **Files:** `scripts/dev/verify.sh`, `scripts/dev/shot.sh`, `scripts/dev/bench_overlay.sh`, `scripts/dev/mem.sh`, `scripts/log.sh`, `backend/internal/buginfo/buginfo.go`, `backend/internal/cli/buginfo.go`, `scripts/check_all.sh`, `scripts/run_tests.sh`
> **Config:** none
> **Related:** [Developer docs](README.md), [Packaging](packaging.md), [Memory](core/memory.md)

How to check a change, look at the running shell and debug it without disturbing your own session, plus where every feature's own testing notes live. Several things are unsafe to do against the session you are using (locking it, switching its compositor config, touching Bluetooth or the machine's clock, …): [Unsafe against your live session](#unsafe-against-your-live-session) lists them with the safe alternative.

### The loop
- `scripts/dev/verify.sh` after every change: formats the changed QML in place (keeping the inode), runs `check_structure`, `check_sizes`, `check_icons`, `check_docs` and `check_packages` on every change, lints changed QML, checks changed JSON files parse, runs the affected unit tests (a changed `methods/<Name>` runs `tst_<Name>`, a schema change runs `Config`, a changed script its `tests/scripts/test_scripts.py` classes, mapped in verify.sh), shellchecks changed scripts (and `.githooks/`), counts a deleted file (a rename's old path too) and a changed check script as changes to what they cover, builds the generated files first (`scripts/generate.sh`: the schema from `qml/config/schema/` and the reference docs in `docs/dev/config/` and `docs/dev/generated/`), through the Go checks (`scripts/check_go.sh --fix`, which add the shared fixtures) when `backend/`, a file it embeds, the schema or what the fixtures are recorded from changed, checks and replays the shared fixtures, and prints the shell's log since the reload (waiting for one only when it formatted a file: a save's reload came before it started). `--all` runs `check_all.sh`.
- Each check script has a `tests/scripts/test_scripts.py` class asserting it fails on what it catches, so a pattern that stops matching fails: `CheckStructure`, `CheckI18n`, `CheckPackages` and `CheckDocs` break a copy of the tree (`fixture_root`) once per rule and assert each message; `CheckQmllint` (its baseline's `against()`), `CheckSizes` and `ConfigUsage` test their functions on small inputs. A new check rule gets its case there.
- `scripts/dev/bench_overlay.sh [-w SECONDS] [-n CYCLES] [-p PID] [--mem] [PAGE…]` times the overlay: how long opening and each page switch blocked, and how long each page and its modules took to build (see [pages-and-grid.md › Loading](overlay/pages-and-grid.md)).
- `scripts/dev/mem.sh PID` reads a qs's memory (RSS, Private_Dirty, AnonHugePages, the JS heap, render threads), and `bench_overlay.sh -p PID --mem -n CYCLES` reads it after each overlay cycle of a nested shell: [memory.md](core/memory.md).
- `scripts/dev/shot.sh` takes a screenshot of a surface and closes it again, printing the PNG's path: `page <ViewType>`, `launcher [text]`, `ipc <target> <open> [close]`, `screen`; `-m MONITOR` (default the focused one), `-w SECONDS`.

### The checks
All run in CI; `scripts/dev/verify.sh --all` (= `scripts/check_all.sh`) runs every one. None runs the shell, so still read its log.
- `scripts/check_structure.py`: folders, imports, layering gates, the Quickshell.Io allowlist, and the conventions a pattern can hold (live Repeater models, `duration:` literals, `Qt.formatDateTime`, `Quickshell.screens`) and the bar widget template (T1-T8, exceptions in `scripts/bar-widget-exceptions.json`: [widget style](bar/widget-style.md#the-widget-template)). Run it after adding, renaming or moving QML files. It fails a singleton over 800 lines (bar `qml/components/methods/` and the compositor backends).
- `scripts/run_tests.sh [Name…]` runs `tests/tst_<Name>.qml` (schema defaults are `tst_Config`); a migration step's tests are Go (`scripts/check_go.sh`).
- The bar tests share `tests/barstyle/Bars.js` (an enriched bar through the real `BarEnrich`); `tst_BarWidgetStyle` is the colour invariant sweep and `tst_BarStyleMatrix` only geometry (looks, cell shapes, outlines).
- `scripts/check_qmllint.py` fails on warnings not in `scripts/qmllint-baseline.json`, and on baselined ones gone. `--update-baseline` is for Quickshell type-info gaps or baselined warnings that are gone; every baseline only shrinks.
- `scripts/check_i18n.py`: the pre-commit hook (`git config core.hooksPath .githooks`; verify.sh warns if it isn't set up) adds new keys empty (shown in English) to every `qml/config/i18n/<code>.json` and drops unused ones ([i18n](core/i18n.md)). Edit i18n files only in the checker's format (2-space JSON; `--format` fixes it).
- `scripts/check_docs.py` fails on a hand-written doc citing a path or `Singleton.member` that's gone, and on an `x-*` annotation missing from [schema-annotations](core/schema-annotations.md).
- `scripts/check_go.sh`: the Go checks for `backend/` (`--fix` regenerates and formats).
- `scripts/check_packages.py`: a dependency has to be in install.sh's table, `Packages.packages` and the AUR PKGBUILDs ([packaging](packaging.md)).
- `scripts/check_sizes.py`: literal pixel sizes outside the bars ([shared-ui-pieces](core/shared-ui-pieces.md) › Sizes).
- `scripts/check_icons.py`: an icon name the bundled font doesn't have, in the schema or a QML literal ([icons](core/icons.md) › The check).
- **Built, never committed** (`.gitignore`; `scripts/generate.sh` builds them when stale, and verify.sh, check_all.sh, check_go.sh and CI run it first; a fresh clone runs it once): `qml/config/json/config.schema.json` (from `qml/config/schema/`), the binary's embedded copies `backend/internal/assets/data/`, the reference docs `docs/dev/config/` and `docs/dev/generated/` (`scripts/gen_docs.py`, which also fails when the shell calls a daemon method the daemon doesn't define, on a setting nobody reads or a reader member nobody uses, and on a read of a reader member that doesn't exist), and with `--fixtures` the shared fixtures `tests/fixtures/shared/` (recorded from the JS helpers; needs qmltestrunner and the whole git history).
- Generated but committed, never edited by hand: `qml/config/themes/template/theme.json` (`scripts/gen_theme_template.py`; the pre-commit hook rebuilds it), `qml/config/i18n/template/language.json`, and the wallpaper shaders' `qml/components/surfaces/wallpaper/shaders/*.frag.qsb` with their `stamps.txt` (`scripts/check_shaders.py --build`, which needs qsb from qt6-shadertools; the check itself, in verify.sh and CI's checks job, only compares the stamps, so it fails on a source changed without a rebuild).
- `scripts/check_doc_drift.py` (warnings) lists docs whose `Files:` changed in 5+ commits since the doc did: reread one against the code before relying on it, and touch it to reset the count.
- Formatting: verify.sh formats changed QML in place with Qt 6's qmlformat (`.qmlformat.ini`), keeping the inode; the `qmlformat` on PATH is Qt 5's and fails silently. A `// reads: Section.path, …` comment's `*` matches any part; `// rpc:` comments: [protocol](backend/protocol.md) › Changing the protocol.

### Reloads and logs
- The shell runs under `axiom run` (the daemon, which owns config.json) and hot-reloads QML files it has loaded. Starting, stopping or restarting the shell or the daemon is yours to do by hand, in your own session; a second axiom only runs nested (`scripts/dev/nested.sh <sway|niri|hyprland>`) or on scratch folders, never on the live ones.
- A scratch environment in zsh: `E="XDG_RUNTIME_DIR=/x XDG_CONFIG_HOME=/y"; env $E …` passes one argument, so the command falls back to the live folders (two test writes once landed in the real config.json this way). Put the assignments inline, use `env ${=E}`, or source a file in `bash -c`, and check `axiom config path` resolves to the scratch folder before any write.
- `~/.config/axiom/config.json` belongs to the settings UI but may be edited to test. Edit it in an editor that goes through the daemon's checks, not with a blind `cp`, `sed -i` or redirect: the daemon holds `x-takeover` settings (the compositor mode, …) as they are, and a raw overwrite skips that. An invalid file never replaces the running config (`savesBlocked` refuses saves until it's fixed).
- `console.log` is for tracing (`scripts/log.sh --debug` shows it), `console.warn` only for real problems.
- **A schema change and the live shell.** The daemon builds the schema from the tree's YAML (`qml/config/schema/`) when it starts, and a QML reload does not rebuild it. `scripts/generate.sh` (run by verify.sh) only rebuilds the generated files on disk (`qml/config/json/config.schema.json`, the binary's embedded copy, the reference docs). So outside dev mode the live shell keeps the old schema until axiom is restarted on a binary rebuilt with the new one (`scripts/generate.sh`, then `go -C backend build -o ~/.local/bin/axiom ./cmd/axiom` or wherever yours lives); a tree whose schema isn't its binary's runs read-only. In dev mode (below) the daemon watches the dev tree's YAML and rebuilds the schema itself. Either way, test a schema change in `scripts/dev/nested.sh` or with `axiom config validate` first.
- **Which tree runs** (`axiom dev status`): the live shell runs the install tree (`~/.local/share/axiom-shell`, never edited by hand), or, while dev mode runs it, the dev tree (`axiom dev set <clone>`) on the dev config (`~/.config/axiom/dev/config.json`). A QML edit reaches the live shell only in the tree it runs: an edit in another worktree is checked by verify.sh and seen in a nested shell, not the live one.
- **Dev mode** (`axiom dev on|off|rebuild|set|options` and `dev config copy|pull` change the live daemon's image, tree and config, so they are for you to run deliberately, never from a script or test; `dev status` and `dev config diff` only read it): while the dev image runs, a YAML edit in the dev tree rebuilds the live schema, and saving a Go file under its `backend/` builds axiom and re-execs the live daemon by itself (the shell keeps running): that's expected, not something to avoid. A failed build shows in `axiom dev status` and the daemon log (`axiom daemon logs`).
- **Testing dev mode itself**: in a nested session (`scripts/dev/nested.sh`, which runs this tree with `--dev --tree`), drive the nested daemon by its socket: `<scratch>/axiom --socket $XDG_RUNTIME_DIR/axiom/<nested display>/axiom.sock dev set <another worktree>` (then `dev status`, `dev rebuild`, `dev config diff`, `dev off`, …; a socket that isn't the live display's reaches only the nested daemon). Its dev build, `dev.json`, `build.json` and dev config land in the scratch folders, and `<scratch>/axiom --socket <it> log` reads the nested shell's log.
- `scripts/log.sh` (a wrapper of `axiom log`, which reads the log of the shell the daemon runs, whichever tree that is) shows warnings and errors since the last reload. `--debug` adds `console.log`, `--all` covers earlier reloads, `-f` follows, `-g PATTERN` filters. A clean reload is just `Reloading configuration...` + `Configuration Loaded`.
- `axiom bug-info` (`--json` for one object) prints the block the bug report form asks for: axiom's version (the tree's `.packaged` marker, else a clone's `git describe` and branch), the binary's and whether it runs, Quickshell's, the running compositor's version (asked over its socket, `compositor/ipc`'s `Version`) and how many monitors are on, the distribution, and the config's format, version and `Compositor.mode` with whether it loads (`ok`, `blocked`). The binary, the tree and the config come from the running daemon (`daemon.hello`, `config.get`), else (none runs, or one that won't answer: an older binary after an update) from this binary, the installed tree and the file (`backend/internal/buginfo`, `cli/buginfo.go`). No names or paths. It's not a check.
- **qs watches files by inode.** `sed -i`, `/usr/lib/qt6/bin/qmlformat -i`, `git checkout <file>` and `git stash push/pop` all replace the inode. Later edits to that file may then not reload, and the shell silently keeps old code.
  - To force a reload, make a real in-place content change to a file that's still watched (append `// x` with Python's `open(p, 'w')`, then remove it). Rewriting identical content doesn't count.
  - Count `Reloading` lines in `scripts/log.sh --all` before and after to confirm.
  - Nothing reloads while the built-in lock screen is up (`Quickshell.watchFiles` is off, [lockscreen](features/lockscreen.md) › No reload under the lock): edits made meanwhile load at the first save after unlocking.
  - Revert temporary edits in place, not with `git checkout`, for the same reason.
- A failed reload leaves the old generation running. Force a clean reload before editing config.json.
- To wait for a reload: `timeout 8 bash -c 'until scripts/log.sh | grep -q "Configuration Loaded"; do :; done'`.
- Raw logs: `axiom log --debug -f` (or `axiom log -- -t 50`: `qs log` of the QML folder the daemon's shell runs from); each instance also writes `/run/user/$UID/quickshell/by-id/<instance>/log.log` (plain text; `pgrep -af "qs -p .*/qml"` finds the instance). stdout and journalctl show nothing.
- If config.json was lost (it falls back to defaults), restore it from a snapshot in `~/.config/axiom/saved/`.
- **Renaming or deleting a singleton** can leave a reload failing with `Type <Old> unavailable … File not found`: one fired between the edits and kept the old file in its module listing. Force one more reload (above); it rescans and loads. Add the old name to `RETIRED` in `scripts/check_docs.py` so docs still citing it fail.

### Seeing a page or surface
- Overlay pages: `scripts/dev/shot.sh page <ViewType>` does all of this. By hand: `axiom ipc overlay page <ViewType>`, then `grim -o <monitor>` (or `grim -g "X,Y WxH"`), crop with `magick`, read the PNG, then `axiom ipc overlay close`.
- The overlay only instantiates the current page and its neighbours, so a page's QML errors only reach `scripts/log.sh` once it's been opened like this.
- A temporary `IpcTarget` (for a settings category, calling `SettingsManager.openCategory(name)`; a lockscreen preview; a screenshot hook) goes in `qml/shell.qml`, called with `axiom ipc`. Revert it in place afterwards.
- Simulated cursor movement is unreliable for checking UI (hover, drags and popouts depend on real pointer events): read the logs and reason through the bindings, and look at anything interactive yourself.
- Per-feature recipes:
  - Launcher: [launcher.md › Testing](features/launcher.md) (`appLauncher search`, focus stealing).
  - Lock screen: [lockscreen.md › Testing](features/lockscreen.md) (`LockManager.editor.startPreview()`, draft-only demo layouts).
  - Greeter: [greeter-runtime.md › Testing](features/greeter-runtime.md) (windowed greeter) and [greeter-install.md › Testing](features/greeter-install.md) (scratch root).
  - Onboarding: [onboarding.md › Testing](features/onboarding.md) (`axiom ipc onboarding goTo <n>`).
  - Another compositor: [sway-backend.md › Running it](compositor/sway-backend.md) (`scripts/dev/nested.sh <sway|niri|hyprland>`: a nested compositor with a second axiom on scratch folders and its own D-Bus; kill only the nested compositor you started, never the live one). Nested niri: [niri-backend.md › Running it](compositor/niri-backend.md). Keep its window visible: hidden (another workspace), niri's winit backend stops, and the axiom in it, and any `axiom ipc` call into it, hangs until it's shown again.

### Unsafe against your live session
These act on the session you are using, or on the machine, and a reload doesn't undo them. Use the alternative instead.

| Don't, on the live session | Why | Instead |
|---|---|---|
| Lock the built-in lock screen | only you can type the password to get back in | test `LockSurface` in a hidden window ([lockscreen](features/lockscreen.md) › Testing) |
| Switch `Compositor.mode` into or out of `managed`, or out of `included`; press a takeover card's Allow; `axiom compositor claim|release` or `binds remove`; pass `--takeover` to a daemon on the live config | it takes over or releases your compositor config | a nested session (`scripts/dev/nested.sh <compositor> [--managed]`) or scratch folders ([config modes](compositor/config-modes.md)) |
| Keep a monitor layout, or enable `Idle` | Keep confirms it on real monitors; `Idle` replaces your own idle daemon (hypridle) | a nested session; make the choice yourself |
| Quit, reload another config or change outputs on the live niri (`niri msg action quit`, `load-config-file`, `output`) | it ends or rewires your session | the nested niri's own `NIRI_SOCKET` ([niri backend](compositor/niri-backend.md)) |
| Write config.json with `cp`, `sed -i`, a redirect or `axiom config set` on the live config; delete it | it skips the `x-takeover` hold (a hand edit can release a managed compositor config), or loses your settings | edit it through an editor, restore from `~/.config/axiom/saved/` (`SavedConfigsManager.restore`, never a raw copy), or use `axiom ipc onboarding goTo <n>` to see the onboarding |
| Write the live input method's settings (fcitx5's `Controller1` `Set*`/`Save`/`Restart`/`Exit`, `gsettings set org.freedesktop.ibus.*`, the daemon's `inputMethod.push|options|framework`) | it rewrites your profile | a scratch bus (`dbus-run-session`) or daemon |
| Apply a theme integration's hookup (`hookup.apply`) | it edits your real app configs | a scratch daemon, or the Go tests' scratch home |
| Restart or stop `xdg-desktop-portal` or its backends, or write the screen-share portal configs | it ends running shares | the Screen sharing card's Apply and Restart, on your click ([screen-sharing](features/screen-sharing.md) › Testing) |
| Change the clock, time zone, hostname, password, picture, real name or default apps | system-wide and permanent | [Machine settings](#machine-settings) below |
| Forget, unpair, block or disconnect a real Bluetooth device; turn the live adapter off (`bluetoothctl`, `rfkill`, `axiom bluetooth off|toggle`, `axiom ipc airplane enable|toggle`, BlueZ's `RemoveDevice`/`Disconnect`/`Pair`/`RegisterAgent`/`Powered`/`Blocked`); register a second Bluetooth agent | your mouse or keyboard could drop out | the fake BlueZ (`go test ./internal/bluez`), or a scratch daemon on a scratch system bus (`DBUS_SYSTEM_BUS_ADDRESS`, `AXIOM_BLUETOOTH_AGENT=off`) |
| Install, update or remove the greeter, or restart greetd | it is root-owned, and restarting greetd ends the session | `axiom greeter-install` with a scratch `AXIOM_GREETER_ROOT`, the greeter only windowed on scratch folders ([greeter-runtime](features/greeter-runtime.md) › Testing) |
| Run, quit, restart or re-exec the live daemon (`axiom run|quit|restart`, `axiom daemon stop|restart|reexec`), switch its dev mode or tree, `axiom lock`, `axiom ipc lockscreen …` | it runs your shell and owns the config | a scratch instance: `XDG_RUNTIME_DIR=<scratch>`, `--socket`, `--config-dir`; a test lock screen's fallback is never `loginctl lock-session` |
| Update the live repo (`selfupdate.apply`) | it rewrites your clone | the Go tests' scratch clones ([self-update](features/self-update.md) › Testing) |

### Popout and layering checks
- **Fullscreen must cover bars and the border.** This is a recurring regression. After changing layer rules (`render.LayerRulesLua`), `WlrLayershell.layer` or `aboveWindows`, test a fullscreen window on a normal and on a special workspace.
  - Hyprland hides Top layers over fullscreen by fading them (`m_aboveFullscreen`), not by draw order. A Top layer that *maps* while a fullscreen window is up draws over it, so never map a Top window in response to fullscreen. Keep it mapped and hide its contents.
  - Known Hyprland 0.56.2 bug: on scrolling-layout (strip) monitors, a fullscreen window on a special workspace goes under the bars.

### Config and schema
- Renaming or reshaping a config key is the schema change first (or both in one edit), then its format-2 step ([migration recipe](../recipes/migration.md)).
- Adding a module to a live config: [writing-modules.md › Testing](overlay/writing-modules.md). Make sure the running daemon has the new schema first (see "A schema change and the live shell" above), keep a copy of config.json to restore, add one module at a time and watch qs's RSS.

### Machine settings
Settings › General's Account and Default apps and System's System info and Date & time change the machine itself: its clock, time zone and hostname (timedated, hostnamed), the user's password, picture and real name (AccountsService, `passwd`) and their default apps (`mimeapps.list`, `xdg-terminals.list`). None of it is undone by a reload, so it is only exercised away from the live system:
- **Go:** each service's package tests it against a fake on a `dbustest` bus (`backend/internal/sysinfo` and the packages beside it), `passwd` against a scripted fake in a pty, and `mimeapps` in `t.TempDir()` folders. They check the calls carry `FlagAllowInteractiveAuthorization` (polkit asks the user through axiom's agent, `PolkitManager`).
- **A scratch daemon:** `XDG_RUNTIME_DIR=<scratch> XDG_CONFIG_HOME=<scratch>/config DBUS_SYSTEM_BUS_ADDRESS=<a dbus-run-session's>`, where the setters reach nothing real. Reading (`system.info`, `datetime.get`, `account.get`, `apps.roles`, `apps.handlers`) is fine against the live one.
- **What only the user can check** (a real time zone change, a password change, a picture showing on the lock screen) goes in the pull request description for the reviewer to try.

### JS and QML experiments
- Engine gaps (`flatMap`, `Object.fromEntries`, `Intl`) and the inline-component trap are in [qml-pitfalls](core/qml-pitfalls.md). `toLocaleString(..., { timeZone })` is ignored too: see [clock-timezones](features/clock-timezones.md).
- For quick JS checks, run a scratch `tst_x.qml` with `QT_QPA_PLATFORM=offscreen /usr/lib/qt6/bin/qmltestrunner -input <dir>`. The dev scripts find Qt 6's tools through `scripts/lib/qt_paths.sh` (`$QT_BIN`, else `qmake6 -query`, else `/usr/lib/qt6/bin`; Fedora's are in `/usr/lib64/qt6/bin`). The plain `qml` tool prints nothing.

### CI
- `.github/workflows/checks.yml` runs on pull requests (a PR's run checks the merge commit that lands; merges are serial), weekly on main for the `go` job alone (govulncheck, for advisories published since the last Go PR), and by hand (`gh workflow run checks.yml --ref <branch>`) for a full run. Each of its four jobs runs its part of `scripts/check_all.sh` (`--ci <job>`), the one list of checks. A new push cancels the PR's older run, and the `go` job skips itself when the PR touches nothing the binary is built or tested from (its first step lists the paths). CI confirms; `scripts/dev/verify.sh --all` before the first push is what finds failures.

### CI locally
- To dry-run the CI `qt` job in a clean container:
  1. Copy the tracked and new files (`git ls-files -co --exclude-standard -z | tar --null --ignore-failed-read -T - -c`; a tracked file deleted in the work tree would otherwise fail the archive) into a scratch dir and `git init` + commit there.
  2. Mount it read-only into `docker run --rm -e CI=true archlinux:latest`.
  3. Run the workflow's pacman line, then copy to a writable dir and run the steps.
- This catches dependencies only the dev machine has (e.g. `Qt5Compat.GraphicalEffects`).

### Container tests
- `scripts/dev/container-test.sh [--rebuild] [--keep] [--shell] [-run REGEX]` runs the tests in `backend/internal/containertest` in a docker container (image `scripts/dev/container/Dockerfile`, tagged by its hash; the tree is snapshotted as in CI locally, read-only, built and tested by `scripts/dev/container/inside.sh`). Logs are kept in `<snapshot>.out/<TestName>/` (printed at the end). It refuses to run inside a container or without docker; the exit code is the tests'.
- The tests are built with `-tags container`, call `Require(t)` first (skips unless `AXIOM_CONTAINER=1`, which the image sets, and refuses without `/.dockerenv`), and never run on the host: never `go test -tags container` outside the script.
- `NewSession(t)` is one scratch desktop: its own `HOME` and XDG dirs, runtime dir and session bus, an environment built from scratch (no `SWAYSOCK`, `NIRI_SOCKET`, `WAYLAND_DISPLAY`, `HYPRLAND_INSTANCE_SIGNATURE` of the host's). `StartSway(config)` (headless), `StartNiriNested(config)` (inside that sway; skips when niri doesn't start), `StartAxiom(kind)` (`axiom run` with the test binary as its shell: it says hello and sends `backend/internal/compositor/manager/testdata/facts.json` as the inputs), `Swaymsg`, `NiriMsg`, `Axiom` (the CLI), `LogSince`, `WaitLog` and `WriteFile`; each process stops when the test ends.
- The daemon drops `AXIOM_*` variables from its shell's environment, so the fake shell's own are `CTR_*`. The fake shell relays calls (`ShellCall(method, params)`: shell-only RPCs such as `polkit.stopOthers`, through `$XDG_RUNTIME_DIR/ctr-shell.sock`), and exits when the daemon's connection is gone for good (a SIGKILLed daemon), waiting out a re-exec's gap.
- More of the harness (reused by later tests): `NewSessionWith(t, env…)` (more environment, the bus's too), `StartAxiomWith(kind, env, args)`, `AxiomTry`/`SwaymsgTry`, `FakeProgram(name, script)` (into `~/bin`, on `PATH`; `Sleeper` is a script whose argv[0] is its own path), `StartProgram(env, name, args…)`, `SecondDisplayEnv()` (an out-of-scope environment), `StartSecondBus()`, `OwnBusName(name)` (a fake `org.freedesktop.systemd1` held by the test process), `StartFakePortal(bus, name)` (a process owning a name, which records its SIGTERM), `PingPortal()` (starts the real xdg-desktop-portal and returns its pid), `StartHyprlandNested(config)` and `Hyprctl` (skips when Hyprland doesn't start nested, which it doesn't in this image: see [Hyprland config modes](hyprland/config-modes.md) HY1), `Record()`/`Guard()`/`GuardLog()` (the session record and the guard), `Procs`/`Alive`/`WaitGone`.
- The footprint tests (`footprint_test.go`): `s.SeedHome(dir)` copies `testdata/home-seed/` into the scratch home keeping links and modes (`dotfiles/` is made read-only so Apply wraps the gtk-4.0 link), `s.Snapshot()` is the home's `{path → type, mode, sha256 | link target}` without axiom's own folders, glib's keyfile, sway's config and `bin`, plus `gsettings list-recursively org.gnome.desktop.interface`, and `Diff(a, b)` compares two. Every command runs with `GSETTINGS_BACKEND=keyfile` (a keyfile in the scratch home, never dconf). `TestContainerFootprintRoundTrip` applies every integration and hookup, a cursor theme and a default app, undoes everything and expects the home as it was but for the kept `.axiom-bak-*` files; the image has `xcursor-themes` and `fcitx5` (the fcitx5 test skips when it doesn't start) ([Footprint ledger](backend/footprint.md)).

### Mutation runs
- A sampled mutation run used a throwaway mutator kept outside the repo (about 200 lines of Go on `go/ast`, `go/parser`, `go/format`, no dependencies, plus a shell driver). To rebuild it: for each function of a file (optionally filtered by a name regexp) it lists every site of these mutations, applies one at a time to a copy, and runs `go test -overlay <json> -count=1 -timeout 90s ./internal/<pkg>` (the overlay swaps the mutated copy in, so the tree is never touched), six at a time: `==`↔`!=`, `<`→`<=`, `<=`→`<`, `>`→`>=`, `>=`→`>`, `&&`↔`||`, an `if` condition negated, a `!` dropped from an `&&`/`||` operand, `true`↔`false`, a returned error (`err`, an `*Err*` name, or `fmt.Errorf`/`errors.New`/`axerr.New`/`axerr.Wrap*`) replaced by `nil`, and a call statement removed. A passing run is a survivor; a build or vet failure counts as killed. Survivors that only drop a log line are equivalent.
- A mutant can undo a test's stub (`greeterinstall.New`'s default `pkexec` reached the real one and waited on its prompt): put refusing stand-ins for `pkexec`, `sudo`, `su`, `doas` and `run0` first on `PATH` for the run, and the root-only branches go through `unshare -rm`, never real root.
