# Recipe: a new theme integration (theming another app)

> **Use when:** making another app follow axiom's theme: a `scripts/theme_<key>.sh` writing that app's own `axiom.*` file, plus the hookup that makes the app load it.
> **Copy from:** `scripts/theme_alacritty.sh` + `scripts/templates/alacritty_template.toml` (template render), `scripts/theme_zathura.sh` (live reload); schema → `properties.ThemeIntegrations.properties.alacritty` (switch + `x-hookup` + `x-hookupNote`)
> **Docs:** [theme-integrations](../dev/theming/theme-integrations.md), `scripts/AGENTS.md`

## Files to touch
1. `scripts/theme_<key>.sh` (executable): renders the app's theme file.
2. `scripts/templates/<key>_template.<ext>`: `envsubst` template, if the script renders one.
3. `config/schema/sections/ThemeIntegrations.yaml` → `properties.<key>`: a boolean (`default: false`) with `title`, `description`, `x-hookup` (optionally `x-hookupNote`). `ThemeManager.integrations` is derived from these boolean keys, in schema order.
4. `config/ThemeIntegrations.qml`: `readonly property bool <key>: _c.<key>` (`ThemeManager` reads `ThemeIntegrations[key]`).
5. `services/core/ThemeManager.qml` → `_integrationCommands`: only if the app's binary isn't named `<key>` (the list is what "installed" is checked by).
6. `tests/scripts/test_scripts.py`:
   - `FORMATS[<key>]` (toml/yaml/json/ini/css/plist) so the output is parse-checked;
   - the binary in `STUBS` if the script `require_cmds` it;
   - a branch in `integration_args` (`tests/scripts/test_scripts.py`) only if its arguments aren't `[theme, target/axiom.out]`.

## Skeleton
```bash
#!/usr/bin/env bash
#
# Quickshell theme -> Foo colors (templates/foo_template.toml).
#
# Usage: theme_foo.sh <theme.json> [output]
#   output: ~/.config/foo/axiom.toml
#   hookup: `include = "axiom.toml"` in foo.toml
#   reload: Foo watches its config (or: how it's reloaded)
#
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/lib/theme_env.sh"
usage_or_help 3 8 "$@"
require_cmds jq envsubst foo

OUTPUT_FILE="${2:-${XDG_CONFIG_HOME:-$HOME/.config}/foo/axiom.toml}"
load_theme "$1"
export_theme_colors
render_template "$SCRIPT_DIR/templates/foo_template.toml" "$OUTPUT_FILE"
```
Template variables: `${BACKGROUND}`, `${FOREGROUND}`, `${ACCENT}`, `${ANSI_0}`…`${ANSI_15}`, `${BASE00}`…, `${THEME_NAME}` (see `export_theme_colors` / `load_theme` in `scripts/lib/theme_env.sh`). Start the template with a "Generated by axiom … edit the template instead" comment.
```json
"foo": {
  "type": "boolean",
  "title": "Foo",
  "default": false,
  "description": "Writes foo/axiom.toml. Foo reloads it by itself.",
  "x-hookup": [
    {
      "file": "{config}/foo/foo.toml",
      "place": "…",
      "text": "include = \"{config}/foo/axiom.toml\"",
      "accept": "regex matching an existing equivalent line"
    }
  ]
}
```

## Steps
1. Write the template and the script. The header comment's lines 3–8 are the usage text (`usage_or_help 3 8`), so keep the shape.
2. `chmod +x scripts/theme_<key>.sh`.
3. Add the schema switch with its `x-hookup`:
   - The `place`/`section`/`replace` options are described in [theme-integrations](../dev/theming/theme-integrations.md) and implemented in `scripts/integration_hookup.py`.
   - Copy the closest existing entry for the file format.
4. Add the reader property and, if needed, the `_integrationCommands` entry.
5. Add the test entries (`FORMATS`, `STUBS`, and an args branch only if needed).

## Gotchas
- **Only the hookup touches the user's config.** The script writes only its own `axiom.*` file. Only `integration_hookup.py` edits the user's app config, on the user's Apply click, after a backup. ncspot is the one exception (no include support; it rewrites only between its markers).
- **Live reload** (signal, socket, CLI) runs only when no output argument was given, as in `theme_zathura.sh`. Tests pass an output path and must not poke running apps.
- **Warnings:** anything printing `Warning:` on stderr fails `run_script` in the tests. Use `warn` only for real problems.
- **Color forms:** colors must stay 6- or 8-digit hex (`assert_parses` checks it). Convert formats with the helpers in `theme_env.sh` (`hex`, `quote_color`, `map_theme_colors`) rather than by hand.
- **Never on the live configs:** don't run a hookup against your real configs. Use a scratch `HOME`/`XDG_CONFIG_HOME`.

## Verify
- `shellcheck -x -S warning scripts/theme_<key>.sh`
- `python3 tests/scripts/test_scripts.py ThemeIntegrations HookupScript`: renders every shipped theme through every script, and applies every hookup to empty configs, in a scratch home (about 10 s).
- `scripts/dev/verify.sh` (schema, reader, generated docs)
- `scripts/check_i18n.py`
