# Recipe: a new theme integration (theming another app)

> **Use when:** making another app follow axiom's theme: an entry in the daemon's integrations table writing that app's own `axiom.*` file, plus the hookup that makes the app load it.
> **Copy from:** `alacritty` in `backend/internal/theme/integrations/table.go` + `templates/alacritty.toml` (a template render), `zathura` in `backend/internal/theme/effects.go` (a live reload); schema → `ThemeIntegrations.alacritty` in `config/schema/sections/ThemeIntegrations.yaml` (switch + `x-hookup` + `x-hookupNote`)
> **Docs:** [theme-integrations](../dev/theming/theme-integrations.md), `backend/AGENTS.md`

## Files to touch
1. `backend/internal/theme/integrations/templates/<key>.<ext>`: the app's file with `${NAME}`s, if it renders one.
2. `backend/internal/theme/integrations/table.go` → `Table["<key>"]`: its files and where they go.
3. `backend/internal/theme/effects.go` → `effects["<key>"]`: only if the app needs telling (a signal, socket, D-Bus call) or a file reshaped for its version.
4. `config/schema/sections/ThemeIntegrations.yaml` → `properties.<key>`: a boolean (`default: false`) with `title`, `description`, `x-hookup` (optionally `x-hookupNote`). `ThemeManager.integrations` is derived from these boolean keys, in schema order.
5. `config/ThemeIntegrations.qml`: `readonly property bool <key>: _c.<key>` (`ThemeManager` reads `ThemeIntegrations[key]`).
6. `services/core/ThemeManager.qml` → `_integrationCommands`: only if the app's binary isn't named `<key>` (the list is what "installed" is checked by).
7. The goldens: `go -C backend test ./internal/theme/integrations -update`.

## Skeleton
```go
// table.go
"foo": one("{config}/foo/axiom.toml", tmpl{name: "foo.toml", text: true}),
```
```toml
# templates/foo.toml
# Generated by axiom from the "${THEME_NAME}" theme.
# Rewritten on every theme change: edit the template instead.
background = "${BACKGROUND}"
foreground = "${FOREGROUND}"
cursor = "${ACCENT}"
color0 = "${ANSI_0}"
```
Template values: `${THEME_NAME}`, `${THEME_AUTHOR}`, `${THEME_VARIANT}`, `${COLOR_SCHEME}` (light/dark), `${BASE00}`…`${BASE0F}`, every semantic color as UPPER_SNAKE (`${BACKGROUND_ALT}`), `${ANSI_0}`…`${ANSI_15}` (the package doc of `backend/internal/theme/integrations`). Options on `tmpl`: `text` (the red…info text colors made readable, for terminal-drawn apps), `format` (`hex`, `quoted`, `kdeRGB`, or your own), `extra` (values of its own). Paths start with `{config}`, `{state}` or `{data}`; an app with several config folders uses `Each`, a browser `Profiles`.
```yaml
foo:
  type: boolean
  title: Foo
  default: false
  description: Writes foo/axiom.toml. Foo reloads it by itself.
  x-hookup:
    - file: '{config}/foo/foo.toml'
      place: …
      text: include = "{config}/foo/axiom.toml"
      accept: regex matching an existing equivalent line
```

## Steps
1. Write the template and the table entry.
2. Add the schema switch with its `x-hookup`:
   - The `place`/`section`/`replace` options are described in [theme-integrations](../dev/theming/theme-integrations.md) and implemented in `scripts/integration_hookup.py`.
   - Copy the closest existing entry for the file format.
3. Add the reader property and, if needed, the `_integrationCommands` entry.
4. A reload, if the app has one: an `effects` entry wrapped in `live(…)`, so only the daemon's integrator runs it, never a test.
5. Write the goldens (`-update`) and read them.

## Gotchas
- **Only the hookup touches the user's config.** The integration writes only its own `axiom.*` file (`TestOnlyAxiomFiles` checks every path has an `axiom` part). Only `integration_hookup.py` edits the user's app config, on the user's Apply click, after a backup. ncspot and kdeglobals are the exceptions (theme-integrations.md).
- **Version-gated signals:** some apps die of a signal they don't handle yet (Helix before 23.10): use `signalFrom` with the first version that reloads.
- **Warnings** (`r.warn`) are logged by the shell as warnings: only for real problems.
- **Color forms:** colors stay 6- or 8-digit hex (`TestEveryThemeRenders` checks it): convert them with a `format`, not in the template.
- **Never on the live configs:** tests use a scratch home (`scratch` in `integrate_test.go`); never run an integration against your real home.

## Verify
- `go -C backend test ./internal/theme/...` (goldens, every shipped theme through every integration, the writer in a scratch home; the table against the schema)
- `python3 tests/scripts/test_scripts.py HookupScript`: applies every hookup to empty configs, in a scratch home.
- `scripts/dev/verify.sh` (schema, reader, generated docs, the Go checks)
